# 🔁 待复习队列

> 每次面试后，把**被问倒的题目**记录到这里，并链接到对应的知识库笔记。
> 这是整套知识库**最高效的查漏方式** —— 比从头复习有效十倍。

## 使用方法

```text
1. 每场面试后 30 分钟内复盘，把没答好/答不上的题记入本表
2. 每条记录链接到对应的知识笔记
3. 每周清空一次"待处理"，用 ✅ 标记已补齐
4. 面试前一周只看本表
```

## 高频薄弱点统计

> 用 `grep` 或 Obsidian 的 Dataview 统计哪些笔记被标记的次数最多 —— 那通常就是你的系统性短板。

```dataview
TABLE length(rows) as "被问倒次数"
FROM #android AND -"Templates"
GROUP BY part
SORT length(rows) DESC
```

## 定期自测清单

> 建议每两周做一次。**关掉笔记，口述 3 分钟**，能讲出来才算过。

### 第一梯队（不问会怀疑你只是 API 调用者）

- [ ] Handler 消息机制 + **同步屏障**原理
- [ ] Binder 一次拷贝原理 + ServiceManager 链路
- [ ] View 绘制流程 measure/layout/draw + `requestLayout` vs `invalidate`
- [ ] 事件分发三方法 + `ACTION_CANCEL` 产生时机
- [ ] Vsync → Choreographer → doFrame 三阶段 + 掉帧排查
