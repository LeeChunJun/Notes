# 文件存储

## 一句话定义

文件存储是 Android 上**唯一能承载任意大小、任意格式二进制数据**的持久化手段：从内部私有目录（`filesDir`/`cacheDir`）到外部公共目录（Android 10+ 受分区存储限制），配合 **FileProvider** 把私有文件安全地暴露给其他应用，是下载、缓存、图片、大 JSON 落地的标准方案。

## 核心原理

### 1. 内部存储 vs 外部存储

```
        应用沙箱（/data/data/<package>/ 或 /data/user/0/<package>/）
        ┌────────────────────────────────────────────────┐
        │  files/      ← getFilesDir()   私有文件，不主动清理 │
        │  cache/      ← getCacheDir()   私有缓存，系统可清理   │
        │  shared_prefs/                                 │
        │  databases/                                    │
        │  no_backup/  ← 备份时排除（放密钥/token）        │
        └────────────────────────────────────────────────┘

        共享存储（/storage/emulated/0）
        ┌────────────────────────────────────────────────┐
        │  Android/          ← getExternalFilesDir() 私有 │
        │    data/<pkg>/files/                            │
        │    cache/<pkg>/                                 │
        │  DCIM/, Pictures/, Movies/, Music/, Download/   │
        │  Android/data/<pkg>/  ← 卸载时自动删除           │
        └────────────────────────────────────────────────┘
```

| 维度 | 内部存储 | 外部存储 |
| --- | --- | --- |
| 路径 | `/data/user/0/<pkg>/`（`/data/data/` 是软链） | `/storage/emulated/0`（共享） |
| 访问权限 | **仅本应用 UID**（Linux DAC 保护） | **所有应用可读**（部分可写，取决于分区存储） |
| 其他应用可见 | ❌ | ✅ |
| 卸载时 | 随应用一起删除 | `Android/data/<pkg>/` 会删；公共目录（DCIM 等）**不会** |
| 是否加密 | 文件系统级加密（FBE） | 同样受 FBE 保护，但**换机迁移 / 跨用户更敏感** |
| 存储位置 | 应用私有分区（`/data`） | **共享用户分区**（与内部共享同一个物理卷） |
| 分区存储影响 | 无（本来私有） | **Android 10+ 受限**，见下文 |
| 适合 | 配置、加密数据、DB、缓存 | 大文件、用户可见的图片/视频、下载内容 |

> 关键区别：**外部存储与内部存储在物理上可能是同一块存储**（emulated 外部存储本质上是 `/data/media` 的 FUSE 挂载）。区别在于**访问控制模型**：内部靠 **Linux 文件权限（UID）**，外部靠**Android 的 scoped storage / FUSE 层**。

### 2. 分区存储（Scoped Storage，Android 10 / API 29 起）

```
   Android 9 及以前                        Android 10+（Scoped Storage）
   ┌───────────────────────┐               ┌───────────────────────────┐
   │ 需要 READ/WRITE_EXTERNAL│               │ 只读：MediaStore 里的媒体  │
   │ _STORAGE 权限           │               │ 写：MediaStore.insert()   │
   │ 可直接读写任意路径        │               │ 私有：Android/data/<pkg>/  │
   │ /storage/emulated/0/xxx │               │ 无法直接访问其他 App 的    │
   │                        │               │ Android/data/ 或公共目录   │
   └───────────────────────┘               └───────────────────────────┘
```

**Android 10 (API 29) 的核心变化**：
- 应用**不再能读写其他应用在共享存储中的私有目录**。
- 应用**不能直接访问公共目录中的任意文件路径**，必须通过 **MediaStore**（媒体）或 **SAF（Storage Access Framework）**。
- 应用**仍可自由读写自己的** `Android/data/<pkg>/` 与 `Android/obb/<pkg>/`（无需任何权限）。
- `requestLegacyExternalStorage` 可让 `targetSdk=29` 的 App 暂时沿用旧行为（**Android 11 已失效**）。

**Android 11 (API 30) 强化**：
- `requestLegacyExternalStorage` **不再生效**。
- 文件访问框架（SAF）**不能请求 `MANAGE_EXTERNAL_STORAGE`** 来"一键授权全盘"（该权限只对**文件管理器/备份类**App 开放，且 Play 商店有严格政策）。

**Android 13 (API 33) 分区媒体权限**：
| 权限 | 覆盖内容 |
| --- | --- |
| `READ_MEDIA_IMAGES` | 图片 |
| `READ_MEDIA_VIDEO` | 视频 |
| `READ_MEDIA_AUDIO` | 音频（不含非媒体） |
| `READ_MEDIA_VISUAL_USER_SELECTED` | 用户**部分授权**（照片选择器部分选中） |

`READ_EXTERNAL_STORAGE` 在 Android 13 已被**废弃/替换**，用 `READ_MEDIA_*` 代替。

### 3. 常用目录 API

```kotlin
// ---- 内部存储 ----
val filesDir: File = context.filesDir          // /data/user/0/pkg/files —— 私有持久
val cacheDir: File = context.cacheDir          // /data/user/0/pkg/cache —— 私有缓存
val codeCacheDir: File = context.codeCacheDir  // 私有，存放编译后的代码
val noBackupFilesDir: File = context.noBackupFilesDir // 备份时排除

// ---- 外部存储（Android 10+ 只能访问自己的目录）----
val extFiles: File = context.getExternalFilesDir(null)      // Android/data/pkg/files
val extCache: File = context.getExternalCacheDir()          // Android/data/pkg/cache
val extFilesType: File? = context.getExternalFilesDir(Environment.DIRECTORY_PICTURES)
val extDirs: Array<File> = context.getExternalMediaDirs()   // 外部媒体专用目录（卸载即删）

// ---- 公共目录（Android 10+ 写需经 MediaStore/SAF）----
val dcim: File = Environment.getExternalStoragePublicDirectory(Environment.DIRECTORY_DCIM)
```

| 目录 | 是否需权限 | 卸载时 | 典型用途 |
| --- | --- | --- | --- |
| `filesDir` | ❌ | 删除 | 用户数据、离线包、加密文件 |
| `cacheDir` | ❌ | 删除 | 图片缓存、临时下载（**系统空间不足时会清理**） |
| `getExternalFilesDir()` | ❌ | **删除** | 大文件（用户不可见） |
| `getExternalCacheDir()` | ❌ | **删除** | 外部缓存 |
| `getExternalMediaDirs()` | ❌ | **删除** | 媒体专用（如编辑后的图片） |
| `Environment.DIRECTORY_PICTURES` | 写需 MediaStore | **不删除** | 用户可见的图片 |
| `DCIM` / `Movies` / `Download` | 写需 MediaStore | **不删除** | 相机、下载内容 |

> **面试点**：`cacheDir` 的文件**系统空间不足时会被系统清理**，所以**不能把"用户数据"放 cacheDir**；同理 `getExternalFilesDir` 虽然卸载会删，但**用户卸载即丢**。

### 4. FileProvider：为什么不能用绝对路径传文件

**问题**：Android 7.0（API 24）起，跨应用传文件**不再允许 `file://` URI**（`FileUriExposedException`），因为 `file://` 暴露了文件系统路径，接收方可以访问**任意路径**（越权读取）。

**解决**：用 **FileProvider** 把内部私有文件包装成 **content:// URI**，通过 `FLAG_GRANT_READ_URI_PERMISSION` 临时授权给接收方。

```
   发送方 App                                  接收方 App
   ┌────────────────────┐                    ┌────────────────────┐
   │ FileProvider       │                    │                    │
   │  ┌──────────────┐  │   content://      │  openInputStream() │
   │  │ 你的私有文件   │  │ ───────────────▶ │  ← 只拿到这一个文件 │
   │  │ /data/user/0/ │  │  + 临时读权限      │     的读权限        │
   │  │   pkg/files/  │  │                    │                    │
   │  │   a.png       │  │                    │                    │
   │  └──────────────┘  │                    │                    │
   └────────────────────┘                    └────────────────────┘
        ↑                                      ↑
   路径不出沙箱                          只能访问被授权的 URI
```

**Manifest 声明**：

```xml
<provider
    android:name="androidx.core.content.FileProvider"
    android:authorities="${applicationId}.fileprovider"
    android:exported="false"
    android:grantUriPermissions="true">
    <meta-data
        android:name="android.support.FILE_PROVIDER_PATHS"
        android:resource="@xml/file_paths" />
</provider>
```

**`res/xml/file_paths.xml`**：

```xml
<?xml version="1.0" encoding="utf-8"?>
<paths>
    <!-- 内部 files 目录：path 对应 filesDir 下的相对子路径 -->
    <files-path name="internal_files" path="files/" />
    <!-- 内部 cache 目录 -->
    <cache-path name="internal_cache" path="cache/" />
    <!-- 外部私有目录 -->
    <external-files-path name="external_files" path="." />
    <external-cache-path name="external_cache" path="." />
    <!-- 根目录（⚠️ 谨慎使用，等价于把整个外部存储暴露出去）-->
    <!-- <root-path name="root" path="/" /> -->
    <!-- 外部存储公共目录（仅在 API < 29 或特定场景有意义）-->
    <!-- <external-path name="external" path="." /> -->
</paths>
```

**生成 URI**：

```kotlin
val authority = "${context.packageName}.fileprovider"
val file = File(context.filesDir, "shared/report.pdf")

val uri: Uri = FileProvider.getUriForFile(context, authority, file)
```

**分享**：

```kotlin
val intent = Intent(Intent.ACTION_SEND).apply {
    type = "application/pdf"
    putExtra(Intent.EXTRA_STREAM, uri)
    addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)
}
startActivity(Intent.createChooser(intent, "分享"))
```

**踩坑清单**：
1. **`path` 写错** → 运行时报 `IllegalArgumentException: Failed to find configured root`。`files-path` 的 `path` 是**相对于 `filesDir` 的子路径**，写 `path="."` 表示整个 `filesDir`。
2. **忘了 `FLAG_GRANT_READ_URI_PERMISSION`** → 接收方 `SecurityException`。
3. **`intent.setData()` vs `putExtra(EXTRA_STREAM)`**：图片用 `EXTRA_STREAM`，自定义 URI 用 `setData`。
4. **接收方也要读权限**：`Intent.FLAG_GRANT_READ_URI_PERMISSION` 是一次性授权，进程被杀后失效；接收方若要长期访问，需要自己在 `onReceive` 里 `takePersistableUriPermission`（`FLAG_GRANT_PERSISTABLE_URI_PERMISSION`，用于 `ACTION_OPEN_DOCUMENT`）。
5. **`file://` 仍可用的情况**：只有当 `Intent` 只发给自己（`setPackage` / 相同应用）时，系统才不抛异常。

### 5. 流式读写：为什么不能一次性读进内存

```kotlin
// ❌ 大文件直接读：OOM 风险
val bytes = file.readBytes()   // 1GB 文件 → 直接 OOM

// ✅ 流式读：内存占用恒定
file.inputStream().use { input ->
    val buffer = ByteArray(8 * 1024)
    while (true) {
        val read = input.read(buffer)
        if (read <= 0) break
        // process(buffer, 0, read)
    }
}

// ✅ 流式写
file.outputStream().use { out ->
    val buffer = ByteArray(8 * 1024)
    // ...
    out.write(buffer, 0, n)
}

// ✅ 更简洁：Okio / Kotlin 扩展
file.bufferedReader().useLines { lines -> lines.forEach { println(it) } }
```

| API | 用途 | 特点 |
| --- | --- | --- |
| `InputStream` / `OutputStream` | 通用流 | 手动管理 buffer |
| `BufferedInputStream` | 带缓冲 | 减少 syscall |
| `RandomAccessFile` | **随机读写** | `seek()` + `read/write`，断点续传的基础 |
| `FileChannel` + `MappedByteBuffer` | **内存映射** | 大文件随机访问，零拷贝 |
| Okio `source`/`sink` | Kotlin 流 | 与 Retrofit/OkHttp 生态一致 |
| `ParcelFileDescriptor` | **跨进程文件通道** | 配合 `ContentProvider.openFile()` |

### 6. 大文件下载与断点续传

```
   断点续传原理
   ┌────────────┐                    ┌────────────┐
   │ 客户端      │  HEAD/Range 请求    │  服务器    │
   │ 已有 5MB   │ ─────────────────▶ │            │
   │            │ ◀─ 206 Partial     │ 支持 Range │
   │ 追加写入    │   Content-Range    │            │
   │ offset=5MB │                    │            │
   └────────────┘                    └────────────┘
```

**关键点**：
- **请求头**：`Range: bytes=<start>-`；**响应**：`206 Partial Content` + `Content-Range: bytes <start>-<end>/<total>`。
- **本地必须用 `RandomAccessFile` 的 `seek(offset)` 追加写**，而不是 `FileOutputStream`（后者会**覆盖**）。
- **服务端要支持 `Accept-Ranges: bytes`**，否则只能整包重下。
- **校验**：下载完成后用 `MD5/SHA-1` 与服务端给的校验和比对（URL 里带 `?hash=xxx`）。

```kotlin
/**
 * 断点续传下载：支持暂停/续传、校验、协程取消
 */
class ResumableDownloader(
    private val context: Context,
    private val okHttpClient: OkHttpClient = OkHttpClient()
) {
    // 断点信息：临时文件名固定，".tmp" 后缀表示未完成
    private fun tempFileOf(url: String): File =
        File(context.cacheDir, "downloads/${url.hashCode().toUInt()}.tmp")

    private fun metaFileOf(url: String): File =
        File(context.cacheDir, "downloads/${url.hashCode().toUInt()}.meta")

    suspend fun download(
        url: String,
        target: File,
        expectedMd5: String? = null
    ): File = withContext(Dispatchers.IO) {
        val tmp = tempFileOf(url)
        tmp.parentFile?.mkdirs()

        val existing = if (tmp.exists()) tmp.length() else 0L
        val total = queryContentLength(url)

        // 请求：从断点处继续
        val request = Request.Builder()
            .url(url)
            .apply { if (existing > 0) header("Range", "bytes=$existing-") }
            .build()

        okHttpClient.newCall(request).execute().use { response ->
            // 206 = 部分内容（续传成功）；200 = 服务端不支持 Range，需要从头下载
            val append = response.code == 206 && existing > 0
            if (!append) {
                existing = 0L
                tmp.delete()
            }
            val expected = total ?: response.body!!.contentLength() + existing

            // ⚠️ 关键：RandomAccessFile.seek() 定位到断点处追加写
            RandomAccessFile(tmp, "rw").use { raf ->
                raf.seek(existing)
                val buffer = ByteArray(64 * 1024)
                var downloaded = existing
                response.body!!.source().use { source ->
                    while (true) {
                        val read = source.read(buffer)
                        if (read == -1) break
                        raf.write(buffer, 0, read)
                        downloaded += read
                        // 进度回调
                        withContext(Dispatchers.Main) {
                            onProgress(downloaded, expected)
                        }
                    }
                }
            }
        }

        // 校验
        if (expectedMd5 != null) {
            val actual = tmp.md5()
            check(actual.equals(expectedMd5, ignoreCase = true)) {
                "MD5 mismatch: expect=$expectedMd5 actual=$actual"
            }
        }

        // 原子替换：先写目标再删临时
        if (target.exists()) target.delete()
        check(tmp.renameTo(target)) { "rename failed" }
        target
    }

    private var onProgress: (downloaded: Long, total: Long?) -> Unit = { _, _ -> }

    private fun queryContentLength(url: String): Long? = runCatching {
        val head = Request.Builder().url(url).head().build()
        okHttpClient.newCall(head).execute().use { it.body?.contentLength() }
    }.getOrNull()

    private fun File.md5(): String {
        val md = java.security.MessageDigest.getInstance("MD5")
        inputStream().use { input ->
            val buffer = ByteArray(8 * 1024)
            while (true) {
                val read = input.read(buffer)
                if (read <= 0) break
                md.update(buffer, 0, read)
            }
        }
        return md.digest().joinToString("") { "%02x".format(it) }
    }
}
```

### 7. 文件加密：密钥放 Keystore

```
   ┌────────────────────────────────────────────┐
   │           Android Keystore (TEE/StrongBox) │
   │  · 不可导出的 AES 密钥                     │
   │  · 硬件隔离，应用沙箱之外                  │
   └────────────────────────────────────────────┘
            │ 只提供加解密操作，密钥永不出 TEE
            ▼
   ┌────────────────────────────────────────────┐
   │  App 进程                                │
   │  1. 生成随机 DEK（数据密钥）               │
   │  2. 用 Keystore 主密钥加密 DEK → 存文件    │
   │  3. 文件内容用 DEK 加密（AES/GCM）         │
   └────────────────────────────────────────────┘
```

```kotlin
/**
 * 文件加密：Keystore 主密钥 + 随机 DEK
 *  - 主密钥存于 TEE，不可导出
 *  - DEK 用主密钥加密后存到私有目录
 *  - 数据文件用 DEK 做 AES/GCM 加密（含完整性校验）
 */
class EncryptedFileStore(private val context: Context) {

    private val keyStore = KeyStore.getInstance("AndroidKeyStore").apply { load(null) }

    private fun getOrCreateMasterKey(): SecretKey {
        (keyStore.getKey(MASTER_ALIAS, null) as? SecretKey)?.let { return it }
        val generator = KeyGenerator.getInstance(KeyProperties.KEY_ALGORITHM_AES, "AndroidKeyStore")
        generator.init(
            KeyGenParameterSpec.Builder(
                MASTER_ALIAS,
                KeyProperties.PURPOSE_ENCRYPT or KeyProperties.PURPOSE_DECRYPT
            )
                .setBlockModes(KeyProperties.BLOCK_MODE_GCM)
                .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_NONE)
                .setKeySize(256)
                .build()
        )
        return generator.generateKey()
    }

    /** 用主密钥加密 DEK，DEK 的密文存到文件里 */
    private fun storeDek(wrapped: ByteArray) {
        File(context.filesDir, "dek.bin").writeBytes(wrapped)
    }

    private fun loadDek(): ByteArray {
        val wrapped = File(context.filesDir, "dek.bin").readBytes()
        val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        cipher.init(Cipher.DECRYPT_MODE, getOrCreateMasterKey())
        return cipher.doFinal(wrapped)
    }

    /** 加密写入：文件格式 = [IV(12B)][ciphertext+tag] */
    fun writeEncrypted(target: File, content: ByteArray) {
        val dek = ByteArray(32).also { java.security.SecureRandom().nextBytes(it) }
        // DEK 用主密钥保护后落盘
        val wrapCipher = Cipher.getInstance("AES/GCM/NoPadding")
        wrapCipher.init(Cipher.ENCRYPT_MODE, getOrCreateMasterKey())
        storeDek(wrapCipher.doFinal(dek))

        val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        cipher.init(Cipher.ENCRYPT_MODE, SecretKeySpec(dek, "AES"))
        val encrypted = cipher.doFinal(content)
        target.writeBytes(cipher.iv + encrypted)   // IV 存前面，解密时要用
    }

    /** 解密读取 */
    fun readEncrypted(source: File): ByteArray {
        val all = source.readBytes()
        val iv = all.copyOfRange(0, 12)
        val body = all.copyOfRange(12, all.size)
        val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        cipher.init(Cipher.DECRYPT_MODE, SecretKeySpec(loadDek(), "AES"), GCMParameterSpec(128, iv))
        return cipher.doFinal(body)
    }

    companion object {
        private const val MASTER_ALIAS = "file_master_key"
    }
}
```

> **面试点**：**AES-GCM 比 AES-CBC 好**，因为 GCM 是 **AEAD（认证加密）**，自带完整性校验，能防止"密文被篡改"（padding oracle 类攻击）。MMKV 用的是 **AES-CFB**（流模式，无完整性保护，靠 CRC 兜底）。

## 代码示例

### 1. 内部/外部存储读写封装

```kotlin
class FileRepository(private val context: Context) {

    private val appContext = context.applicationContext

    /** 内部私有目录：用户数据，加密存储的敏感文件放这里 */
    fun userDataFile(name: String): File =
        File(appContext.filesDir, name).apply { parentFile?.mkdirs() }

    /** 内部缓存：可被系统清理，只放可重建的数据 */
    fun cacheFile(name: String): File =
        File(appContext.cacheDir, name).apply { parentFile?.mkdirs() }

    /** 外部私有目录：大文件（用户不可见），卸载即删 */
    fun externalFile(name: String): File =
        File(appContext.getExternalFilesDir(null), name).apply { parentFile?.mkdirs() }

    /** 文本读写（UTF-8） */
    fun writeText(file: File, content: String) {
        file.writeText(content, Charsets.UTF_8)
    }

    fun readText(file: File): String =
        if (file.exists()) file.readText(Charsets.UTF_8) else ""

    /** 流式写大文件（避免 OOM） */
    fun writeStream(file: File, write: (OutputStream) -> Unit) {
        file.outputStream().use { out -> write(out) }
    }

    /** 流式读大文件 */
    fun forEachLine(file: File, action: (String) -> Unit) {
        if (!file.exists()) return
        file.bufferedReader(Charsets.UTF_8).useLines { lines ->
            lines.forEach(action)
        }
    }
}
```

### 2. 内存映射读写大文件

```kotlin
/**
 * 用 FileChannel + MappedByteBuffer 读写大文件：
 *  - 映射整段文件到内存，随机访问零拷贝
 *  - 写入时：写入映射页 → force() 刷盘
 */
class MappedFile(private val file: File) {

    fun write(bytes: ByteArray) {
        val channel = FileChannel.open(file.toPath(), StandardOpenOption.CREATE,
            StandardOpenOption.READ, StandardOpenOption.WRITE)
        channel.use { ch ->
            val size = ch.size()
            // 不足则扩容
            if (size < bytes.size) {
                ch.position(size)
                ch.write(ByteBuffer.wrap(ByteArray(bytes.size - size.toInt())))
            }
            val buffer = ch.map(FileChannel.MapMode.READ_WRITE, 0, bytes.size.toLong())
            buffer.put(bytes)
            buffer.force()   // 刷盘（可选，性能换持久性）
        }
    }

    fun read(offset: Long, length: Int): ByteArray {
        FileChannel.open(file.toPath(), StandardOpenOption.READ).use { ch ->
            val buffer = ch.map(FileChannel.MapMode.READ_ONLY, offset, length.toLong())
            val out = ByteArray(length)
            buffer.get(out)
            return out
        }
    }
}
```

### 3. FileProvider 完整配置与分享

```kotlin
/** 生成可分享的 content URI */
object ShareHelper {

    fun uriFor(context: Context, file: File): Uri {
        val authority = "${context.packageName}.fileprovider"
        return FileProvider.getUriForFile(context, authority, file)
    }

    /** 分享文件（自动处理权限 flag） */
    fun shareFile(context: Context, file: File, mimeType: String, title: String = "分享") {
        val uri = uriFor(context, file)
        val intent = Intent(Intent.ACTION_SEND).apply {
            type = mimeType
            putExtra(Intent.EXTRA_STREAM, uri)
            addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)
        }
        context.startActivity(Intent.createChooser(intent, title).addFlags(
            Intent.FLAG_ACTIVITY_NEW_TASK
        ))
    }

    /** 分享文本 + 文件（例如带说明的图片） */
    fun shareImageWithText(context: Context, file: File, text: String) {
        val uri = uriFor(context, file)
        val intent = Intent(Intent.ACTION_SEND).apply {
            type = "image/*"
            putExtra(Intent.EXTRA_STREAM, uri)
            putExtra(Intent.EXTRA_TEXT, text)
            addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)
        }
        context.startActivity(Intent.createChooser(intent, "分享").addFlags(
            Intent.FLAG_ACTIVITY_NEW_TASK
        ))
    }
```

### 4. SAF：让用户选择文件（替代直接的外部存储读写）

```kotlin
/**
 * SAF：ACTION_OPEN_DOCUMENT 让用户选文件，拿到的是 content URI（可持久化授权）
 * 这是 Android 10+ 访问"用户已有文件"的正确姿势。
 */
class SafPicker(private val activity: Activity) {

    private val openDocLauncher = activity.registerForActivityResult(
        ActivityResultContracts.OpenDocument()
    ) { uri: Uri? ->
        if (uri == null) return@registerForActivityResult
        // 持久化授权（进程被杀后依然有效）
        activity.contentResolver.takePersistableUriPermission(
            uri, Intent.FLAG_GRANT_READ_URI_PERMISSION
        )
        readText(uri)
    }

    fun pick() {
        // mimeType: "*/*" 任意文件；"image/*" 图片
        openDocLauncher.launch(arrayOf("image/*"))
    }

    fun readText(uri: Uri): String? = runCatching {
        activity.contentResolver.openInputStream(uri)?.use { input ->
            input.bufferedReader().readText()
        }
    }.getOrNull()

    /** 创建新文件（写） */
    fun createFile(mimeType: String, displayName: String): Uri? {
        val uri = activity.contentResolver.insert(
            MediaStore.Files.getContentUri("external"),
            android.content.ContentValues().apply {
                put(MediaStore.MediaColumns.DISPLAY_NAME, displayName)
                put(MediaStore.MediaColumns.MIME_TYPE, mimeType)
                put(MediaStore.MediaColumns.RELATIVE_PATH, Environment.DIRECTORY_DOWNLOADS)
            }
        )
        return uri
    }
}
```

## 常见问题 / 面试要点

**读者问：内部存储和外部存储有什么区别？Android 10 之后有什么变化？**

**AI答：**

1. **本质区别**：
   - **内部存储** = `/data/user/0/<pkg>/`，**靠 Linux 文件权限（UID）保护**，只有本应用能访问；**卸载时全部删除**。
   - **外部存储** = `/storage/emulated/0/`，**所有应用可见**（历史上）；卸载时 `Android/data/<pkg>/` 会删，公共目录不会删。
2. **外部存储的"emulated"含义**：它**不是真正的物理 SD 卡**，而是 `/data/media` 的 **FUSE 挂载**（PC 上的位置是 `内部存储/media/0`），所以**外部存储和内部存储在物理上是同一块盘**，只是访问控制模型不同。
3. **Android 10（API 29）分区存储**：
   - 应用**不能再直接读写共享存储中的任意路径**。
   - 媒体文件 → 走 **MediaStore**（`insert`/`query`）。
   - 非媒体文件 → 走 **SAF**（`ACTION_OPEN_DOCUMENT` / `ACTION_CREATE_DOCUMENT`）。
   - **自己的** `Android/data/<pkg>/` 与 `Android/obb/<pkg>/` **仍可自由读写，无需权限**。
   - `requestLegacyExternalStorage` 让 `targetSdk=29` 短暂沿用旧行为，**Android 11 起失效**。
4. **Android 13（API 33）**：把 `READ_EXTERNAL_STORAGE` 拆成 `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` / `READ_MEDIA_AUDIO`，并新增 `READ_MEDIA_VISUAL_USER_SELECTED`（**部分授权**，配合系统照片选择器）。
5. **面试话术**："Android 10 之后的核心变化是**从'路径访问'变成'URI 访问'**。以前是 `File(Environment.getExternalStorageDirectory(), "a.jpg")`，现在必须用 `ContentResolver` + `MediaStore`/`SAF` 拿 URI。我们项目里所有图片读写都走 MediaStore，私有大文件走 `getExternalFilesDir()`。"

**读者问：FileProvider 到底怎么用？为什么不能直接传文件绝对路径？**

**AI答：**

1. **为什么不能传绝对路径**：
   - Android 7.0（API 24）起，跨应用传 `file://` URI 会抛 **`FileUriExposedException`**（`StrictMode` 的 `FileUriExposure`）。
   - **根因是安全**：`file://` 暴露的是**文件系统路径**，接收方拿到后可以访问**该路径下的任意文件**（甚至通过 `../` 遍历），构成**越权访问**。FileProvider 的**动态授权**精确限定了"只能读这一个文件"。
2. **FileProvider 的工作原理**：
   - 它是一个 **ContentProvider 的子类**，自己**不持有数据**，而是通过 `file_paths.xml` 把"**允许暴露的根目录**"声明出来。
   - `getUriForFile(context, authority, file)` 会**校验** `file` 是否在某个声明的根目录下 → 越界直接抛 `IllegalArgumentException`。
   - 生成的 URI 形如 `content://com.example.fileprovider/internal_files/my_file.png`，其中 `internal_files` 是 `<files-path name="...">` 的 `name`。
   - 接收方通过 `ContentResolver.openInputStream(uri)` 读取，FileProvider 在 `openFile()` 里打开真实文件。
3. **完整三步**：
   - **Manifest**：声明 `<provider>`，加 `androidx.core.content.FileProvider`。
   - **`res/xml/file_paths.xml`**：声明允许暴露的根目录。
   - **代码**：`FileProvider.getUriForFile(...)` + Intent 加 `FLAG_GRANT_READ_URI_PERMISSION`。
4. **常见坑**：
   - `path` 写错 → `Failed to find configured root`。**`files-path` 的 `path` 是相对 `filesDir` 的子目录**，如 `path="images/"`。
   - 忘记 `FLAG_GRANT_READ_URI_PERMISSION` → 接收方 `SecurityException`。
   - `<root-path>` 权限太大（等于把整个外部存储暴露），**生产环境慎用**。
   - **`external-path` 在 Android 10+ 基本没用了**（你已无法访问公共目录路径）。
5. **进阶**：如果接收方需要**长期**访问，用 `ACTION_OPEN_DOCUMENT` + `takePersistableUriPermission`（SAF 路线）；如果是**自己发给自己**，可以不带 flag。

**读者问：大文件怎么存？下载怎么实现断点续传？**

**AI答：**

1. **存放位置选择**：
   - **用户数据（不能丢）** → `filesDir` 或 `getExternalFilesDir()`（后者卸载即删，慎用于用户数据）。
   - **可重建的缓存** → `cacheDir` / `getExternalCacheDir()`（**系统空间紧张时会清理**）。
   - **用户可见的图片/视频** → `MediaStore`（见 [[../数据共享/MediaStore与数据共享]]）。
   - **超大文件（>1GB）** → 考虑 `getExternalFilesDir()` 或 `getExternalMediaDirs()`，**绝不能放 `cacheDir`**（会被清理）。
2. **读写方式**：
   - **流式读写**（`InputStream`/`OutputStream` + buffer），内存占用恒定 → **绝不能 `readBytes()`** 大文件（OOM）。
   - **随机读写** → `RandomAccessFile`（`seek` + `read/write`）。
   - **内存映射** → `FileChannel.map(READ_WRITE, ...)` → `MappedByteBuffer`，**零拷贝随机访问**，适合大文件分块处理。
   - **跨进程文件通道** → `ParcelFileDescriptor`（`ContentProvider.openFile()` 返回）。
3. **断点续传原理**：
   - 本地保留**未完成的临时文件**（`.tmp`）和**已下载字节数**（可以用临时文件长度作为断点）。
   - 请求时带 `Range: bytes=<offset>-`；服务端返回 `206 Partial Content` + `Content-Range`。
   - **必须用 `RandomAccessFile.seek(offset)` 追加写**；用 `FileOutputStream` 会**覆盖**已有内容。
   - 服务端必须支持 `Accept-Ranges: bytes`，否则只能整包重来（收到 `200` 时要**清空临时文件从头下**）。
   - 下载完成后 **MD5/SHA 校验**，再 **rename** 到正式文件名（保证"要么完整要么不存在"）。
4. **常见坑**：
   - **中途 App 被杀** → 临时文件与断点信息要**一起持久化**（用文件长度当断点最简单可靠）。
   - **文件变化（服务端资源更新）** → 记录 `ETag`/`Last-Modified`，续传时带上，变化则**重新下载**。
   - **并发下载同一文件** → 需要**文件锁**避免互相写坏。

**读者问：文件加密怎么做？密钥放哪里？**

**AI答：**

1. **目标**：文件落盘时**密文**，攻击者拿到文件也读不出内容（防止设备丢失/root/备份泄露）。
2. **分层密钥方案**：
   ```
   Android Keystore (TEE/StrongBox，密钥不可导出)
        │  加密
        ▼
   DEK（随机数据密钥，密文存在私有目录）
        │  加密
        ▼
   业务数据文件（密文）
   ```
   - **主密钥（KEK）**：在 Keystore 里生成，**硬件隔离**、**不可导出**、可设置 `setUserAuthenticationRequired`（需解锁才能用）。
   - **数据密钥（DEK）**：随机生成，用主密钥加密后落盘。
   - **数据文件**：用 DEK 加密。
3. **算法选择**：
   - **AES-GCM**（**推荐**）：**AEAD**，同时提供**机密性 + 完整性 + 认证**，能检测篡改；**每次加密用新 IV**，IV 存文件头。
   - **AES-CBC**：需要 PKCS7 padding，**易受 padding oracle 攻击**，不推荐。
   - **AES-CFB**：流模式，MMKV 使用；**无完整性保护**，需另配 CRC/HMAC。
   - **ChaCha20-Poly1305**：软件实现下常比 AES 快（无 AES 硬件加速时）。
4. **性能**：加密会**降低读写速度**（通常 30%~50%），且**不能直接 mmap 随机写**（因为需要解密整块）→ 加密文件不适合大文件的随机访问。
5. **与 AndroidX Security 的关系**：`androidx.security:security-crypto` 提供了 `EncryptedFile` / `EncryptedSharedPreferences`（封装了 Keystore + Tink），适合简单场景；**自定义**方案则用 `KeyStore` + `Cipher` 直接实现。
6. **别忘了**：`noBackupFilesDir` —— 存放**密钥、token** 等**不应参与云备份**的数据。

---

**读者问：`cacheDir` 里的文件会被系统删除吗？什么时候删？**

**AI答：**

1. **会**。`cacheDir`（`/data/user/0/<pkg>/cache`）与 `getExternalCacheDir()` 都是**缓存目录**：
   - **系统空间不足时，系统会主动清理**（LRU 策略，删除最久未访问的）。
   - **卸载应用时删除**。
   - **不会**在应用运行期间被随意删除（正常使用不受影响）。
2. **所以**：
   - **不能把"用户数据"放 cacheDir**（如草稿、离线下载的正文）。
   - **适合放**：图片/视频缩略图缓存、可重新下载的临时文件、解压中间产物。
3. **最佳实践**：
   - 启动时**主动清理过期缓存**（按时间戳 / LRU）。
   - 缓存文件加**过期策略**（如 7 天），避免无限膨胀。
   - **重要数据**同时写一份到 `filesDir` 或数据库，cache 只是加速层。
4. **面试话术**："`cacheDir` 的语义是'**丢了也能重建**'。我们只在这里放缩略图和临时下载；真正的数据在 Room 和 filesDir。"

**读者问：Android 10+ 想读取用户相册里的图片，怎么做？**

**AI答：**

1. **必须用 MediaStore，不能用绝对路径**：
   ```kotlin
   val uri = MediaStore.Images.Media.EXTERNAL_CONTENT_URI
   val projection = arrayOf(MediaStore.Images.Media._ID, MediaStore.Images.Media.DISPLAY_NAME)
   contentResolver.query(uri, projection, null, null, null)?.use { cursor ->
       val idCol = cursor.getColumnIndexOrThrow(MediaStore.Images.Media._ID)
       while (cursor.moveToNext()) {
           val id = cursor.getLong(idCol)
           val contentUri = ContentUris.withAppendedId(uri, id)
           // contentUri 即 content://media/external/images/media/<id>
       }
   }
   ```
2. **权限**：
   - **Android 13+**：需要 `READ_MEDIA_IMAGES`（或 `READ_MEDIA_VISUAL_USER_SELECTED` 部分授权）。
   - **Android 12 及以下**：`READ_EXTERNAL_STORAGE`。
3. **推荐做法：系统照片选择器（Photo Picker）**：
   ```kotlin
   val picker = ActivityResultContracts.PickVisualMedia()
   picker.launch(PickVisualMediaRequest(ImageOnly))
   ```
   - **Android 13+（API 33+）**：`ACTION_PICK_IMAGES`，**无需任何存储权限**。
   - **Android 11~12L**：通过 `MediaStore.getMediaUriFor` 兼容。
   - 这是**官方推荐**方案：用户明确选择，权限最小化。
4. **老 API（Android 10）**：有 `READ_EXTERNAL_STORAGE` 时可以用 `MediaStore` 查询得到 `content://` URI；**targetSdk=30+ 且无权限**时**无法查询媒体表**。
5. **不要做的事**：
   - 不要用 `Environment.getExternalStoragePublicDirectory(DIRECTORY_DCIM)` + 遍历文件（Android 10+ 直接读不到）。
   - 不要把 `content://media/...` 硬编码成路径字符串再转回 URI（`MediaStore.Images.Media.insertImage` 在 API 29+ 已废弃）。
6. **写入图片到相册**：用 `MediaStore.Images.Media.EXTERNAL_CONTENT_URI` 的 `insert()`（详见 [[../数据共享/MediaStore与数据共享]]）。

**读者问：文件存储和数据库、SharedPreferences 怎么选？**

**AI答：**

1. **三者的定位**：
   | | SharedPreferences / DataStore | 数据库（Room） | 文件 |
   | --- | --- | --- | --- |
   | 适合 | **少量配置项** | **结构化、可查询** | **任意二进制、大对象** |
   | 访问方式 | key-value | SQL | 字节流 |
   | 查询 | ❌ | ✅（SQL/索引） | ❌ |
   | 事务 | ❌ | ✅ | ❌ |
   | 大小 | KB 级 | MB~GB | 无上限 |
2. **判断流程**：
   ```
   数据是"开关/主题/token"吗？
     → DataStore（类型安全 + Flow）
   数据有"结构、需要筛选排序关联"吗？
     → Room（见 [[SQLite与Room]]）
   数据是"图片/视频/大 JSON/下载包/二进制"吗？
     → 文件 + 流式读写
   ```
3. **典型工程组合**：
   - **Room**：业务实体（订单、消息、用户）。
   - **DataStore**：用户偏好（主题、语言、是否已看过引导页）。
   - **文件**：图片缓存、下载的离线包、加密的密钥材料、日志文件。
   - 三层组合 → **Repository** 统一对外（见第 7 部分 [[../..//07-架构、工具与生态/README]]）。
4. **面试话术**："数据存储选型的本质是**访问模式**决定存储结构**：按 key 取 → KV；按条件查 → 关系型；按字节流读写 → 文件。"
