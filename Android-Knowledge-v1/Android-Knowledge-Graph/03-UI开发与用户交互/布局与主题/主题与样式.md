# 主题与样式

## 一句话定义

**Theme（主题）** 是作用于**整个 Activity / Application** 的外观定义；**Style（样式）** 是作用于**单个 View** 的外观定义。两者本质都是"属性的键值集合"，通过 `parent` 继承、通过 `?attr/` 引用，形成 Android 资源体系里最重要的作用域机制。

## 核心原理

### 1. Style 与 Theme 的本质区别

```text
两者都是 <style> 标签定义的资源，编译后都是 bag（键值包）。
区别只在于「应用范围」：

Style：  style="@style/MyButtonStyle"     → 作用于一个 View
Theme：  <application android:theme="@style/AppTheme">  → 作用于整个 App/Activity
```

| 维度 | Style | Theme |
| --- | --- | --- |
| 应用对象 | 单个 View（`style` 属性） | Activity / Application / Dialog |
| 定义位置 | `res/values/styles.xml` | `res/values/themes.xml`（或同文件） |
| 典型用途 | 统一按钮外观、文本样式 | 定义颜色、字体、组件默认样式、系统栏 |
| 能否互相引用 | ✅ 可以 `parent="@style/xxx"` | ✅ 可以 |

**关键**：**Theme 本身也是一个 Style**。`Theme.Material3.DayNight` 就是一个定义了 `colorPrimary`、`materialButtonStyle` 等属性的 style。所以一个 Theme 可以被当作 Style 用。

### 2. 继承机制

```text
style 继承的三种写法：

1. 显式 parent
   <style name="MyTheme" parent="Theme.Material3.DayNight"> ... </style>

2. 隐式 parent（点号命名约定）
   <style name="MyTheme" parent="Base.Theme">...</style>
   <style name="Base.Theme">...</style>      ← Base.Theme 隐式 parent = Base
   注意：命名中的点是层级分隔符，最后一段之前的部分会作为隐式 parent

3. parent 省略（表示没有 parent，继承系统默认）
   <style name="MyButton">...</style>
```

**隐式继承的例子**：

```xml
<style name="Button" parent="Widget.AppCompat.Button">
    <item name="android:textAllCaps">false</item>
</style>

<!-- 隐式：parent = "Button"（因为点号前是 "Button"） -->
<style name="Button.Primary">
    <item name="backgroundTint">@color/primary</item>
</style>
```

> ⚠️ **隐式继承的坑**：命名必须严格遵守约定，一旦写成 `<style name="MyApp.Button.Primary">`，隐式 parent 会变成 `MyApp.Button`（而不是 `Button`），容易出错。**推荐始终显式写 `parent`**。

**`ThemeOverlay` 的作用**：

```xml
<!-- 只覆盖少量属性，用于局部（Dialog / BottomSheet / 特定 Activity） -->
<style name="ThemeOverlay.MyApp.Dialog" parent="ThemeOverlay.Material3.MaterialAlertDialog">
    <item name="colorSurface">@color/dialog_surface</item>
</style>
```

- `ThemeOverlay.*` 是**"基于某个主题的差异集"**，只覆盖列出的属性，其余继承。
- 典型用途：全局深色，但某个 Dialog 强制浅色。

### 3. 自定义属性与 `?attr/` 引用

**两步走**：

```xml
<!-- 1. 在 res/values/attrs.xml 声明自定义属性 -->
<resources>
    <attr name="brandPrimaryColor" format="color" />
    <attr name="brandCornerRadius" format="dimension" />
    <attr name="brandIcon" format="reference" />
</resources>
```

```xml
<!-- 2. 在主题中赋值，在布局中用 ?attr/ 引用 -->
<style name="Theme.MyApp" parent="Theme.Material3.DayNight">
    <item name="brandPrimaryColor">@color/brand_primary</item>
    <item name="brandCornerRadius">16dp</item>
</style>
```

```xml
<!-- 3. 布局中引用 -->
<com.google.android.material.card.MaterialCardView
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    app:cardBackgroundColor="?attr/brandPrimaryColor"
    app:cardCornerRadius="?attr/brandCornerRadius" />
```

**`?attr/` 的解析机制**：

```text
运行时：
  Theme (当前 Activity 的主题)
    └─ attr "brandPrimaryColor" → @color/brand_primary (资源 ID)
         └─ 解析该资源 → 具体值（可能是 color，可能是 color-night 限定符下的另一个值）
```

**关键点**：`?attr/` 的值在**运行时**从当前主题解析，所以**换主题就换外观，无需改布局**。这正是"一套布局，多套品牌"的基础。

**`?attr/` vs `@color/` vs `?android:attr/`**：

| 写法 | 含义 |
| --- | --- |
| `@color/brand_primary` | 直接引用一个颜色资源（写死） |
| `?attr/brandPrimaryColor` | 从当前主题解析（可换肤） |
| `?android:attr/colorAccent` | 从**系统**主题解析（系统级属性） |
| `?attr/colorPrimary` | Material 库定义的属性（需 Material 主题） |
| `@style/MyTextAppearance` | 引用一个 style（外观集合） |

> ⚠️ **常见崩溃**：`?attr/xxx` 指向的属性**当前主题没有定义** → 运行时 `Resources.NotFoundException`。解决：在所有使用该主题的 Context 上用 `ThemeOverlay` 补上，或用 `?attr/xxx, fallback` 语法（`?attr/colorPrimary` 无 fallback，但 `?android:attr/textColorPrimary` 有内置默认）。

### 4. 资源限定符（Qualifier）与配置匹配

Android 资源目录名的格式：

```text
res/<base_name>-<qualifier1>-<qualifier2>-.../<resource>
```

**限定符的优先级顺序（重要）**：

```text
1. MCC / MNC        移动国家码 / 运营商
2. Locale            语言_国家（values-zh-rCN）
3. LayoutDirection   布局方向（ldrtl）
4. smallestWidth     sw<N>dp
5. Available width   available width / height
6. Screen size       small/normal/large/xlarge
7. Screen aspect     long/notlong
8. Round             round/notround
9. Wide color gamut  widecg
10. HDR               highdr
11. Screen orientation  port/land
12. UI mode           car/desk/television/appliance/watch/vrheadset
13. Night mode       night/notnight
14. Screen pixel density  hdpi/xhdpi/...
15. Touchscreen type   notouch/stylus/finger
16. Keyboard availability  keyssoft/keysexposed/keyshidden
17. Primary text input method  nokeys/qwerty/12key
18. Navigation key availability  navhidden/navexposed
19. Screen size        （旧版）
```

**规则**：
1. **限定符按表格顺序匹配**，前面的优先级更高。
2. **只声明一个限定符时，其余视为"任意"**。
3. 多个限定符时，**顺序必须与表格一致**（否则 AAPT 报错）。
4. **资源选择算法**（简化）：
   ```text
   1. 排除不匹配的限定符
   2. 按优先级逐个比较，第一个不同的限定符决定胜负
   3. 都没有 → 用默认（无限定符）目录
   ```

**常用限定符详解**：

| 限定符 | 含义 | 例子 |
| --- | --- | --- |
| `values-zh-rCN` | 简体中文（中国） | `values-zh-rCN/strings.xml` |
| `values-b+zh` | 中文（BCP 47 语言标签） | `values-b+zh+Hant+TW/strings.xml` |
| `values-night` | 深色模式 | `values-night/colors.xml` |
| `values-v21` | API 21+ | `values-v21/styles.xml` |
| `values-v26` | API 26+ | `values-v26/styles.xml` |
| `values-sw600dp` | 最小宽度 ≥ 600dp（平板） | `values-sw600dp/dimens.xml` |
| `values-w820dp` | 可用宽度 ≥ 820dp | |
| `values-h720dp` | 可用高度 ≥ 720dp | |
| `values-land` | 横屏 | `values-land/strings.xml` |
| `values-port` | 竖屏 | |
| `values-hdpi` | 密度 240dpi | `drawable-hdpi/` |
| `values-ldrtl` | RTL 布局 | |
| `values-notnight` | 强制浅色 | |
| `values-w820dp-h720dp` | 多限定符（顺序敏感） | |

**`values-night` 的工作原理**：

```text
系统切换深色模式
   → Configuration.uiMode 的 UI_MODE_NIGHT_MASK 变化
   → Resources 重新解析资源表
   → 查找匹配 night 限定符的配置
   → 若存在 values-night/colors.xml → 用其中的同名资源
   → 否则回退到 values/colors.xml
```

> **注意**：`values-night` 中的资源**只需写"要覆盖的项"**，其余自动继承 `values/` 中的定义。因为资源是**按 name 覆盖**的，不是整目录替换。

**`values-v21` / `values-v26` 的工作原理**：

```text
系统版本 API 21+
   → Configuration.sdkVersion >= 21
   → 优先匹配 values-v21/，没有则回退 values/
```

常用于：
- `values-v21/styles.xml`：定义 `android:windowDrawsSystemBarBackgrounds` 等 API 21 才有的属性。
- `values-v23/styles.xml`：定义 API 23+ 才有的属性。
- `values-v26/styles.xml`：定义 `android:windowLightStatusBar`（API 23+）或 `windowLightNavigationBar`（API 27+）。

> **版本限定符必须按 API 降序排列**：`values-v27` > `values-v26` > `values-v23` > `values-v21` > `values`。

### 5. `ContextThemeWrapper` 与 `applyStyle`

**问题**：如何给一个已创建的 Context（或 View）**局部套一层主题**？

```java
// 1. ContextThemeWrapper：创建一个带新主题的 Context 包装器
Context themedContext = new ContextThemeWrapper(baseContext, R.style.Theme_MyApp_Dialog);
View view = new MyView(themedContext);
```

**典型用途**：
- `AlertDialog.Builder(Context, int themeResId)` 的内部实现；
- `PopupWindow` 的 `setBackgroundDrawable` 关联主题；
- `ContextThemeWrapper` 用于 `LayoutInflater` 的 `cloneInContext`；
- `LayoutInflater.from(context)` 实际上就是 `new ContextThemeWrapper(context, themeResId)`。

**`applyStyle` 的两种用法**：

```java
// 1. 在 Context 上应用（一次性）
Context ctx = new ContextThemeWrapper(context, R.style.Theme_MyApp);
ctx.applyStyle(R.style.MyTextAppearance, true);   // true = 合并到现有主题

// 2. 在 View 上应用（影响该 View 及其子 View）
TextView tv = new TextView(context);
tv.getContext().applyStyle(styleResId, true);
```

**`applyStyle(resId, theme)` 的语义**：
- `theme = true`：把 style 的属性**合并**到当前主题（已存在的同名属性会被覆盖）。
- `theme = false`：只应用到 View 自身（用于 View 的属性解析）。

**`LayoutInflater` 的主题处理**：

```java
// inflate 时用带主题的 Context
LayoutInflater inflater = LayoutInflater.from(themedContext);
View v = inflater.inflate(R.layout.item, parent, false);
```

**自定义 View 中读取主题属性**：

```java
TypedArray a = context.obtainStyledAttributes(attrs, R.styleable.MyView, defStyleAttr, 0);
// defStyleAttr = R.attr.myViewStyle  → 从当前主题解析 MyView 的默认样式
```

### 6. 主题的应用范围

```text
Application 级：  <application android:theme="@style/AppTheme">
Activity 级：     <activity android:theme="@style/ActivityTheme">   ← 覆盖 Application
Fragment/View：  LayoutInflater 的 Context 主题
Dialog：         new AlertDialog.Builder(context, R.style.DialogTheme)
PopupWindow：     popup.setBackgroundDrawable(...) / 主题化布局
Service：        无 UI，但可通过 context.getTheme()
```

**Activity 主题覆盖 Application 主题**：`Activity.getTheme()` 返回 Activity 自己的主题；`Application.getTheme()` 返回 App 级主题。

```kotlin
// 检查当前主题
val isMaterial3 = context.theme.obtainStyledAttributes(
    R.styleable.MaterialTheme
).use { it.getBoolean(R.styleable.MaterialTheme_isMaterial3, false) }
```

### 7. Compose 的 MaterialTheme 与 CompositionLocal

**Compose 的对应物**：

| View 体系 | Compose |
| --- | --- |
| `Theme`（`colorPrimary` 等） | `MaterialTheme.colorScheme` |
| `TextAppearance` | `MaterialTheme.typography` |
| `ShapeAppearance` | `MaterialTheme.shapes` |
| `?attr/` 引用 | `MaterialTheme.colorScheme.primary` |
| `ContextThemeWrapper` | `CompositionLocalProvider` |

**`CompositionLocal` 是 Compose 的"主题作用域"**：

```kotlin
// 1. 定义
val LocalAppConfig = compositionLocalOf { AppConfig() }

// 2. 提供
CompositionLocalProvider(LocalAppConfig provides AppConfig(darkMode = true)) {
    MyScreen()
}

// 3. 消费
@Composable
fun MyScreen() {
    val config = LocalAppConfig.current
}
```

**`staticCompositionLocalOf` vs `compositionLocalOf`**：

| | `compositionLocalOf` | `staticCompositionLocalOf` |
| --- | --- | --- |
| 变更时 | **只重组**读取它的 composable | **整个提供子树**重组 |
| 性能 | 更好 | 差，但读取更高效 |
| 适用 | 主题、配置等高频变更 | 极少变更的（如 `LocalContext` 替代品） |

**Compose 中的主题桥接**：

```kotlin
@Composable
fun MyAppTheme(content: @Composable () -> Unit) {
    val isDark = isSystemInDarkTheme()
    MaterialTheme(
        colorScheme = if (isDark) DarkColors else LightColors,
        typography = MyTypography,
        shapes = MyShapes,
        content = content
    )
}
```

**读取 XML 主题属性**（用于混用场景）：

```kotlin
@Composable
fun Context.themeColor(@AttrRes attr: Int, default: Color): Color {
    val typedValue = TypedValue()
    theme.resolveAttribute(attr, typedValue, true)
    return if (typedValue.resourceId != 0) {
        Color(ContextCompat.getColor(this, typedValue.resourceId))
    } else Color(typedValue.data)
}
```

### 8. 资源作用域与样式化编程

**`values` 目录的资源都是"编译期常量"**：

```xml
<!-- values/dimens.xml -->
<dimen name="spacing_medium">16dp</dimen>
```

```kotlin
// 通过资源 ID 获取
val spacing = resources.getDimensionPixelSize(R.dimen.spacing_medium)
// 或用 ContextCompat
val spacing = ContextCompat.getDimensionPixelSize(context, R.dimen.spacing_medium)
```

**样式化编程（Styled Resources）**：Android 提供 `TypedArray` 一次读取一组同前缀的属性。

```kotlin
// 定义
<declare-styleable name="MyView">
    <attr name="myColor" format="color" />
    <attr name="mySize" format="dimension" />
</declare-styleable>

// 读取
val a = context.obtainStyledAttributes(attrs, R.styleable.MyView, defStyleAttr, 0)
val color = a.getColor(R.styleable.MyView_myColor, Color.BLACK)
val size = a.getDimensionPixelSize(R.styleable.MyView_mySize, 0)
a.recycle()
```

```kotlin
class ThemeAwareViewHolder(
```

### 4. 自定义 View 读取主题属性

```java
public class BrandCardView extends FrameLayout {

    private final Paint paint = new Paint(Paint.ANTI_ALIAS_FLAG);

    public BrandCardView(Context context) {
        this(context, null);
    }

    public BrandCardView(Context context, AttributeSet attrs) {
        this(context, attrs, R.attr.brandCardViewStyle);   // ← defStyleAttr 让它跟随主题
    }

    public BrandCardView(Context context, AttributeSet attrs, int defStyleAttr) {
        super(context, attrs, defStyleAttr);

        TypedArray a = context.obtainStyledAttributes(attrs, R.styleable.BrandCardView, defStyleAttr, 0);
        try {
            int color = a.getColor(R.styleable.BrandCardView_brandColor,
                    resolveThemeColor(context, R.attr.brandPrimaryColor, Color.BLUE));
            float radius = a.getDimension(R.styleable.BrandCardView_brandRadius,
                    resolveThemeDimension(context, R.attr.brandCornerRadius, 16f));
            paint.setColor(color);
            paint.setStyle(Paint.Style.STROKE);
            paint.setStrokeWidth(2f);
        } finally {
            a.recycle();
        }
    }

    /** 从当前主题解析 ?attr/ 属性 */
    private int resolveThemeColor(Context context, int attr, int fallback) {
        TypedValue tv = new TypedValue();
        if (context.getTheme().resolveAttribute(attr, tv, true)) {
            if (tv.resourceId != 0) return ContextCompat.getColor(context, tv.resourceId);
            return tv.data;
        }
        return fallback;
    }

    private float resolveThemeDimension(Context context, int attr, float fallbackDp) {
        TypedValue tv = new TypedValue();
        if (context.getTheme().resolveAttribute(attr, tv, true) && tv.resourceId != 0) {
            return TypedValue.complexToDimension(tv.data, context.getResources().getDisplayMetrics());
        }
        return fallbackDp * context.getResources().getDisplayMetrics().density;
    }
}
```

### 5. Compose 主题与 CompositionLocal

```kotlin
/** 1. 定义一个应用级配置 */
data class AppConfig(
    val userName: String = "",
    val isVip: Boolean = false
)

val LocalAppConfig = compositionLocalOf { AppConfig() }

/** 2. 在根部提供 */
@Composable
fun MyApp(viewModel: AppViewModel = hiltViewModel()) {
    val config by viewModel.config.collectAsStateWithLifecycle()

    CompositionLocalProvider(LocalAppConfig provides config) {
        MyAppTheme {
            MainScreen()
        }
    }
}

/** 3. 在任意深层消费 */
@Composable
fun ProfileBadge() {
    val config = LocalAppConfig.current
    if (config.isVip) {
        Badge(label = "VIP")
    }
}

/** 4. 自定义主题 */
private val LightScheme = lightColorScheme(primary = Color(0xFF6750A4))
private val DarkScheme = darkColorScheme(primary = Color(0xFFD0BCFF))

@Composable
fun MyAppTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    content: @Composable () -> Unit
) {
    MaterialTheme(
        colorScheme = if (darkTheme) DarkScheme else LightScheme,
        typography = Typography(),
        shapes = Shapes(),
        content = content
    )
}
```

### 6. 运行时切换主题（品牌换肤）

```kotlin
/** 运行时切换 Application 主题 */
class ThemeManager(private val context: Context) {

    fun applyTheme(themeResId: Int) {
        AppCompatDelegate.setDefaultNightMode(
            if (themeResId == R.style.Theme_MyApp_Dark) {
                AppCompatDelegate.MODE_NIGHT_YES
            } else {
                AppCompatDelegate.MODE_NIGHT_NO
            }
        )
    }

    /** 只覆盖 Activity 的主题（不影响全局） */
    fun overrideActivityTheme(activity: Activity, themeResId: Int) {
        activity.setTheme(themeResId)
    }
}

/** 局部主题：给 RecyclerView 的 item 换一套主题 */
class ThemedAdapter(
    private val baseContext: Context,
    private val themeResId: Int

    inner class VH(view: View) : RecyclerView.ViewHolder(view) {
        init {
            val themed = ContextThemeWrapper(baseContext, themeResId)
            LayoutInflater.from(themed).inflate(R.layout.item, view as ViewGroup, false)
        }
    }
```

## 常见问题 / 面试要点

**读者问：Style 和 Theme 有什么区别？它们的关系是什么？**

**AI答：**

1. **本质相同**：两者都是 `<style>` 定义的**属性集合**（编译后是 `bag` 资源），语法完全一样。
2. **区别在应用范围**：
   - **Style**：作用在**单个 View** 上（`style="@style/MyButtonStyle"`）。
   - **Theme**：作用在**整个 Activity / Application** 上（`android:theme`），本质上是"**一组默认属性 + 颜色角色 + 组件默认样式**"。
3. **关键关系**：**Theme 也是一个 Style**。你可以在 `layout.xml` 中写 `style="@style/Theme.MyApp"`（技术上可行，只是不推荐）；反过来，一个 Style 不能直接当 Theme 用（缺少 `windowBackground` 等系统必需属性时 Activity 会崩）。
4. **实践区分**：
   - `res/values/themes.xml` 放 Theme，`res/values/styles.xml` 放 Style（**约定**，不是强制）。
   - Theme 里定义**颜色、字体、组件默认样式**；Style 里定义**某个控件的具体外观**。
5. **`ThemeOverlay`**：介于两者之间——**基于某个主题的差异集**，用于局部覆盖（Dialog、BottomSheet、单个 Activity）。
6. **面试话术**："**Style 是『控件长什么样』，Theme 是『App 什么调性』。Theme 本质上是一个范围更大的 Style。**"

---

**读者问：`?attr/` 是什么？它和 `@color/` 有什么区别？为什么 `?attr/` 能实现换肤？**

**AI答：**

1. **`?attr/` 是"运行时主题属性引用"**：`?attr/xxx` 表示"从**当前 Context 的主题**中查找名为 `xxx` 的属性并取其值"。
2. **与 `@color/` 的区别**：
   | | `@color/brand_primary` | `?attr/brandPrimaryColor` |
   | --- | --- | --- |
   | 解析时机 | 编译期（资源 ID 固定） | **运行时**（查当前主题） |
   | 换主题 | ❌ 不变 | ✅ **自动变化** |
   | 依赖 | 无 | 主题必须定义该属性 |
3. **换肤原理**：
   ```text
   布局：app:cardBackgroundColor="?attr/brandPrimaryColor"   ← 只写"角色名"
   主题 A：<item name="brandPrimaryColor">@color/red</item>
   主题 B：<item name="brandPrimaryColor">@color/blue</item>

   → 换主题 B，布局代码一行不改，外观全变
   ```
4. **`?android:attr/`** 与 `?attr/` 的区别：前者查**系统主题**属性（如 `?android:attr/textColorPrimary`），后者查**应用（或 Material 库）主题**属性。
5. **自定义属性必须先在 `attrs.xml` 声明**，否则 AAPT 编译报错。
6. **坑**：
   - 当前主题**没有定义**该属性 → 运行时 `NotFoundException`。解决：用 `ThemeOverlay` 补齐，或统一在基础主题里定义。
   - `?attr/` 不能用在 `android:` 命名空间的属性上（那些只能用 `@android:` 或 `?android:attr/`）。
   - 在 **Compose** 中没有 `?attr/`，对应物是 `MaterialTheme.colorScheme.xxx`。
7. **面试话术**："**`?attr/` 是运行时查主题的间接引用，是『一套布局多套品牌』和 Material 组件自动跟随主题的技术基础。**"

---

**读者问：`values-night` 是怎么工作的？哪些资源需要做 night 版本？**

**AI答：**

1. **工作原理**：
   ```text
   系统切换深色模式
     → Configuration.uiMode 的 UI_MODE_NIGHT_MASK 改变
     → Resources 重新解析资源表
     → 优先匹配 values-night/ 中的同名资源
     → 未定义的项自动回退到 values/
   ```
2. **关键点：按 name 覆盖，不是整目录替换**。`values-night/colors.xml` 里只写要改的颜色即可。
3. **需要做 night 版本的资源**：
   - **颜色**（最核心）：背景、前景、品牌色、分割线。
   - **主题**（如果深浅差异大，如需要反转某些自定义属性）。
   - **图片/图标**：深色下需要用浅色版本的图标（如深色背景上的黑色图标看不清）。
   - **矢量图**：可以用 `values-night` 中的 `color` 引用，让矢量图自动变色（推荐做法）。
   - **布局**：极少需要（深浅模式通常布局相同）。
4. **推荐的"主题驱动"做法**（避免为每个颜色写两份）：
   ```xml
   <!-- values/themes.xml -->
   <style name="Theme.MyApp" parent="Theme.Material3.DayNight">
       <item name="android:colorBackground">@color/brand_surface</item>
   </style>

   <!-- values/colors.xml -->
   <color name="brand_surface">#FFFBFE</color>
   <!-- values-night/colors.xml -->
   <color name="brand_surface">#1C1B1F</color>
   ```
   → 布局和组件代码完全不用改。
5. **系统强制深色**：`forceDarkAllowed`（API 29+）——系统会自动把浅色主题反色。若你的 App 已支持深色模式，应设为 `false` 避免二次反色：
   ```xml
   <item name="android:forceDarkAllowed" tools:targetApi="q">false</item>
   ```
6. **Compose 侧**：`isSystemInDarkTheme()` + `darkColorScheme()`（详见 [[../资源与适配/深色模式]]）。
7. **面试话术**："**深色模式的核心是『资源按 night 限定符覆盖同名项』，配合 `Theme.Material3.DayNight` 自动切换；关键是只覆盖颜色，布局和逻辑不动。**"

**读者问：主题的继承机制是怎样的？`parent` 和隐式继承有什么区别？`ThemeOverlay` 什么时候用？**

**AI答：**

1. **三种继承写法**：
   - **显式 `parent`**：`parent="Theme.Material3.DayNight"` —— **推荐**。
   - **隐式 parent**：`<style name="Base.Theme.MyApp">` 会隐式继承名为 `Base` 的 style（点号前部分）。
   - **无 parent**：`<style name="Foo">` 没有隐式 parent 时，继承系统默认（实际上 AAPT 会警告）。
2. **隐式继承的坑**：
   ```xml
   <style name="Button" parent="Widget.AppCompat.Button">...</style>
   <style name="Button.Primary">...</style>        ← 隐式 parent = "Button" ✓
   <style name="MyApp.Button.Primary">...</style>  ← 隐式 parent = "MyApp.Button" ✗（易误解）
   ```
   **最佳实践：始终显式写 `parent`**。
3. **`ThemeOverlay` 的语义**：
   - 它是**"基于某个主题的差异集"**，只覆盖列出的属性，其余继承 parent。
   - 命名约定：`ThemeOverlay.XXX`，parent 通常是 `ThemeOverlay.Material3.*`。
   - **用途**：
     - Dialog / BottomSheet / PopupWindow 的局部主题；
     - 某个 Activity 单独换肤；
     - 全局深色但某个页面强制浅色；
     - **给 View 局部套主题**（`ContextThemeWrapper`）。
4. **对比 `Theme`**：
   | | `Theme` | `ThemeOverlay` |
   | --- | --- | --- |
   | 替换 | **完全替换**当前主题（除非自己继承原主题） | **叠加**在当前主题之上 |
   | 用途 | Activity / Application 级别 | 局部（Dialog / View / 部分页面） |
5. **面试话术**："**Theme 是替换，ThemeOverlay 是叠加。`ThemeOverlay` 是 Compose 之前实现『局部换肤』的标准手段。**"

---

**读者问：`ContextThemeWrapper` 是什么？什么时候需要用？`applyStyle` 的两个参数是什么意思？**

**AI答：**

1. **`ContextThemeWrapper` 的作用**：创建一个**包装了主题的 Context**，让用这个 Context 创建的 View / LayoutInflater 能解析到新的主题属性。
   ```java
   Context themed = new ContextThemeWrapper(base, R.style.Theme_MyApp_Dialog);
   View v = new MyView(themed);   // 这个 View 的 ?attr/ 走 themed 的主题
   ```
2. **典型使用场景**：
   - `LayoutInflater.from(context)` 内部就是 `ContextThemeWrapper`。
   - Dialog：`new AlertDialog.Builder(context, themeResId)`。
   - RecyclerView / ListView 的 item 需要不同主题 → 给 ViewHolder 用 `ContextThemeWrapper`。
   - 自定义 View 需要在某个局部主题下绘制。
3. **`applyStyle(resId, theme)`**：
   - `theme = true`：**合并到当前主题**（同名属性被覆盖），作用于后续从这个 Context 创建的资源解析。
   - `theme = false`：只应用到**这个 View 自身**的属性解析（不污染 Context）。
4. **注意**：`applyStyle` 只能**覆盖/新增**属性，**不能删除**已有属性。
5. **Compose 的对应物**：`CompositionLocalProvider`（Compose 的"局部主题"就是它）。
6. **面试话术**："**`ContextThemeWrapper` 是 View 时代的『局部主题作用域』，Compose 的对应物是 `CompositionLocalProvider`。**"

**读者问：资源限定符的优先级规则是什么？多个限定符怎么组合？**

**AI答：**

1. **优先级顺序（从高到低，节选）**：
   ```text
   Locale > LayoutDirection > smallestWidth > 可用宽高 > 屏幕尺寸 >
   屏幕长宽比 > 圆形屏 > 色域 > HDR > 屏幕方向 > UI 模式 >
   夜间模式 > 屏幕密度 > 触摸类型 > 键盘 > 导航键 > ...
   ```
2. **组合规则**：
   - **顺序必须与官方表格一致**，否则 AAPT 编译报错。例如 `values-v21-sw600dp` ✅，`values-sw600dp-v21` ❌。
   - **每种限定符最多出现一次**。
   - **只声明一个限定符时，其余视为"任意匹配"**。
3. **资源选择算法**：
   ```text
   1. 过滤掉不匹配的限定符组合
   2. 按优先级逐个比较，第一个有差异的限定符决定胜负
   3. 完全相同则用该配置
   4. 都没匹配上 → 用默认（无限定符）目录
   ```
4. **例子**（系统是 `zh-CN`、`night`、`sw720dp`、`xhdpi`）：
   ```text
   values-zh-rCN-night-sw720dp-xhdpi   ← 最匹配（全部命中）
   values-zh-rCN-night-xhdpi
   values-night-sw720dp
   values-night
   values                                  ← 兜底
   ```
5. **常见错误**：
   - `values-zh-rCN` 写成了 `values-zh-CN`（**大写 `r` 才是 region**）→ AAPT 报错 "Invalid resource directory name"。
   - 目录名大小写不匹配（`values-Night`）→ 不生效。
   - `values-v21` 里用了 API 30 才有的属性 → 运行时 `NoSuchFieldError`。
   - **密度限定符应放在 `drawable-` 而不是 `values-`**（`values-xhdpi` 只影响数值资源）。
6. **面试话术**："**限定符匹配 = 过滤 + 按优先级表逐项比较，第一个差异决定胜负，最后回退到无限定符目录。**"

**读者问：Compose 里怎么实现主题？和 View 的 `?attr/` 怎么对应？**

**AI答：**

1. **Compose 的主题三件套**：
   ```kotlin
   MaterialTheme(
       colorScheme = lightColorScheme(...),   // 对应 View 的 colorPrimary 等
       typography = Typography(...),           // 对应 TextAppearance
       shapes = Shapes(...),                   // 对应 ShapeAppearance
       content = content
   )
   ```
2. **与 `?attr/` 的对应**：
   ```text
   ?attr/colorPrimary       ↔  MaterialTheme.colorScheme.primary
   ?attr/colorOnPrimary     ↔  MaterialTheme.colorScheme.onPrimary
   ?attr/colorSurface       ↔  MaterialTheme.colorScheme.surface
   ?attr/textAppearanceBody1↔  MaterialTheme.typography.bodyLarge
   ?attr/shapeAppearanceCornerMedium ↔ MaterialTheme.shapes.medium
   ```
3. **作用域机制**：Compose 用 **`CompositionLocal`** 实现"局部主题"：
   ```kotlin
   val LocalAppConfig = compositionLocalOf { AppConfig() }

   CompositionLocalProvider(LocalAppConfig provides config) {
       DeepChild()   // 这里面 LocalAppConfig.current 就是 config
   }
   ```
   - `compositionLocalOf`：值变化时**只重组读取它的 composable**（性能好）。
   - `staticCompositionLocalOf`：值变化时**整个子树重组**（读取更快，但影响大）。
4. **与 View 的 `ContextThemeWrapper` 对应**：`CompositionLocalProvider` ≈ `ContextThemeWrapper`。
5. **混用时的桥接**：
   ```kotlin
   // Compose → View
   val primary = MaterialTheme.colorScheme.primary
   AndroidView(factory = { ctx -> MyView(ctx).apply { setColor(primary.toArgb()) } })

   // View → Compose（读 XML 主题）
   val primary = context.theme.resolveThemeColor(R.attr.colorPrimary)
   ```
6. **面试话术**："**Compose 把『主题』做成了 `MaterialTheme` 这个组合局部（CompositionLocal），`?attr/` 换成了 `MaterialTheme.colorScheme.xxx`；`ContextThemeWrapper` 换成了 `CompositionLocalProvider`。**"
