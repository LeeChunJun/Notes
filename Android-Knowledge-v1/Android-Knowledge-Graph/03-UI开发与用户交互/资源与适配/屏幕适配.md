# 屏幕适配

## 一句话定义

屏幕适配的本质是**用与设备无关的抽象单位（dp / sp）表达尺寸**，再通过**资源限定符**为不同尺寸、密度、方向的设备提供差异化资源。目标不是"一套布局在所有设备上像素相同"，而是"**同一套代码在不同设备上都呈现合理、可读、可点击的界面**"。

## 核心原理

### 1. 尺寸单位体系

| 单位 | 全称 | 含义 | 使用场景 |
| --- | --- | --- | --- |
| **px** | pixel | 物理像素点 | ❌ 几乎不用（不同设备像素数不同） |
| **dp**（dip） | density-independent pixel | 密度无关像素 | **所有尺寸**（间距、宽高、圆角） |
| **sp** | scale-independent pixel | 缩放无关像素 | **所有字号**（会跟随用户字体缩放） |
| **in** | inch | 英寸 | 极少用（打印、地图比例尺） |
| **mm** | millimeter | 毫米 | 极少用（地图、打印） |
| **pt** | point | 1/72 英寸 | 极少用（印刷） |

**dp 与 px 的换算**：

```text
1 dp = (densityDpi / 160) px

densityDpi 桶（Bucket）      density    换算
─────────────────────────────────────────────
ldpi    120    0.75
mdpi    160    1.00    ← 基准
hdpi    240    1.50
xhdpi   320    2.00
xxhdpi  480    3.00
xxxhdpi 640    4.00
```

**sp 与 dp 的关系**：

```text
1 sp = 1 dp × fontScale

fontScale 来源：
  1. 系统"字体大小"设置（1.0 ~ 2.0+）
  2. 系统"显示大小"设置（部分厂商 ROM 会同时影响）
  3. 无障碍设置（超大字体）

→ 用 dp 写字号，用户放大字体时**不会变大** → 无障碍问题
→ 用 sp 写字号，用户放大字体时**会变大** → ✅ 正确
```

**Android 的换算 API**：

```kotlin
val dp = TypedValue.applyDimension(
    TypedValue.COMPLEX_UNIT_DIP, 16f, resources.displayMetrics
)
val sp = TypedValue.applyDimension(
    TypedValue.COMPLEX_UNIT_SP, 16f, resources.displayMetrics
)
val px = resources.displayMetrics.density * 16
```

**实际显示像素**：

```text
实际字号(px) = sp × fontScale × density
例：16sp，fontScale=1.3，density=2.75（xxhdpi）
     = 16 × 1.3 × 2.75 = 57.2px
```

> **面试点**：为什么字号用 `sp` 而不是 `dp`？因为 `sp` 会乘上 `fontScale`，尊重用户的无障碍偏好；`dp` 不会。这是个**高频陷阱**——用 `dp` 写字号在用户放大字体时无效，属于无障碍缺陷。

### 2. 密度与资源目录

```text
密度限定符（drawable 目录）：
  ldpi    120dpi
  mdpi    160dpi   ← 基准
  hdpi    240dpi
  xhdpi   320dpi
  xxhdpi  480dpi
  xxxhdpi 640dpi
  nodpi    不随密度缩放（用于特定像素尺寸的资源）
  anydpi   任意密度（矢量图，API 21+）
```

**图片资源的密度目录策略**：

```text
方案 A：按密度提供多份位图
  drawable-hdpi/  icon.png   (1.5x)
  drawable-xhdpi/ icon.png   (2x)
  drawable-xxhdpi/icon.png   (3x)
  → 内存占用是密度的平方关系，xxhdpi 的 3x 图 = 9x 像素

方案 B：只提供一份 + 放到 drawable/（默认 mdpi）
  → 系统会自动放大，模糊但省空间

方案 C：使用矢量图（VectorDrawable）✅✅
  drawable/icon.xml
  → 任意密度无损缩放，体积小

方案 D：使用 WebP / AVIF
  → 体积比 PNG 小 25%~35%（AVIF 更多）
```

**Bitmap 的内存计算**：

```text
内存 = 宽(px) × 高(px) × 每像素字节数

每像素字节数：
  ARGB_8888 = 4 字节
  RGB_565   = 2 字节
  ARGB_4444 = 2 字节

一张 1920×1080 的 ARGB_8888 图 = 1920 × 1080 × 4 = 8.3 MB！
```

**`drawable-nodpi` vs `drawable-xxxhdpi`**：
- 放在 `drawable/`（默认 mdpi）的图会按 `density` 缩放；
- 放在 `drawable-nodpi/` 的图**不缩放**，1px 就是 1px（用于背景平铺、像素级资源）；
- 放在 `drawable-xxxhdpi/` 的图在 xxxhdpi 设备上 1:1，其他设备按比例缩放。

**启动图 / 背景图的正确做法**：

```xml
<!-- res/drawable/launch_background.xml -->
<layer-list>
    <item android:drawable="@color/splash_background" />
    <item>
        <bitmap android:gravity="center" android:src="@drawable/logo" />
    </item>
</layer-list>
```

### 3. 尺寸限定符（sw / w / h）

| 限定符 | 含义 | 典型设备 |
| --- | --- | --- |
| **`sw<N>dp`** | **smallestWidth**（屏幕**最短边**的 dp 值） | `sw600dp` = 7" 平板 |
| **`w<N>dp`** | available **width**（当前可用宽度） | `w840dp` = 横屏平板 |
| **`h<N>dp`** | available **height**（当前可用高度） | `h720dp` = 横屏 |
| `small` / `normal` / `large` / `xlarge` | 屏幕尺寸（旧版，已废弃） | 早期 |
| `long` / `notlong` | 屏幕长宽比 | |

**`smallestWidth` 的关键特性**：
- 它是**屏幕最短边**的 dp 值，**与横竖屏无关**（旋转屏幕时 `sw` 不变）。
- 因此 `sw600dp` 是判断"是不是平板"的标准做法。
- 它是**设备无关**的：同一台设备无论横屏竖屏，`sw` 都一样。

**`w` / `h` 会随旋转和分屏变化**：
- 竖屏手机：`w = 360dp`, `h = 720dp`
- 横屏手机：`w = 720dp`, `h = 360dp`
- 分屏（半屏）：`w = 360dp`（一半）

**典型配置**：

```text
res/values/            默认（手机竖屏）
res/values-sw600dp/    平板（7" 及以上）
res/values-sw720dp/    大平板（10"）
res/layout-sw600dp/    平板专用布局（双栏）
res/layout-land/       横屏布局
res/layout-w600dp/     宽度 ≥ 600dp 时使用
```

**Google 官方推荐的断点**：

```text
手机：     < 600dp   （compact）
平板：     600dp ~ 840dp（medium）
大平板：   > 840dp  （expanded）
```

### 4. 屏幕方向与宽高比

```text
res/layout/         默认
res/layout-land/    横屏
res/layout-port/    竖屏
res/layout-square/  方形（少见）
res/layout-long/    长屏
res/layout-notlong/ 非长屏
```

**方向处理的三种方式**：

| 方式 | 做法 | 评价 |
| --- | --- | --- |
| **资源限定符** | `layout-land/` | 简单直接，但资源膨胀 |
| **`configChanges`** | `android:configChanges="orientation\|screenSize"` | **不重建 Activity**，但需手动处理 |
| **响应式布局** | 同一布局用 ConstraintLayout / 权重自适应 | ✅ **推荐** |

```xml
<!-- 声明 configChanges 避免旋转重建 -->
<activity
    android:name=".MainActivity"
    android:configChanges="orientation|screenSize|smallestScreenSize|screenLayout|keyboardHidden"
    android:windowSoftInputMode="adjustResize" />
```

```kotlin
override fun onConfigurationChanged(newConfig: Configuration) {
    super.onConfigurationChanged(newConfig)
    // 手动重新布局
    binding.root.requestLayout()
}
```

> ⚠️ **坑**：`configChanges` 会让 Activity **不重建**，意味着 `onCreate` 不会重新执行 → 依赖"重建时刷新"的逻辑会失效（布局不会自动切换到 `layout-land/`）。除非确实需要，否则**推荐让系统重建**，用资源限定符自动处理。

**多窗口/分屏**：

```text
res/layout/          默认（手机）
res/layout-w600dp/   分屏时宽度 ≥ 600dp
```

**Android 12L+ 的新特性**：

```text
窗口尺寸类（Window Size Classes，Material 3）：
  Compact   < 600dp   手机竖屏
  Medium    600~840dp 手机横屏 / 小平板
  Expanded  > 840dp   平板 / 桌面

官方依赖：
  implementation("androidx.compose.material3:material3-window-size-class")
```

```kotlin
@Composable
fun AdaptiveScreen() {
    val windowSizeClass = calculateWindowSizeClass(activity)
```

### 5. 资源选择的优先级（完整）

```text
给定设备配置，系统按以下顺序匹配：

1. MCC/MNC           移动国家码/运营商
2. Locale            语言_国家
3. LayoutDirection   ldrtl
4. smallestWidth     sw<N>dp      ← 决定"手机还是平板"
5. Available width   w<N>dp
6. Available height  h<N>dp
7. Screen size       small/normal/large/xlarge
8. Screen aspect     long/notlong
9. Round             round/notround
10. Wide color gamut widecg
11. HDR              highdr
12. Screen orientation port/land
13. UI mode          car/desk/television/...
14. Night mode       night/notnight
15. Screen density   ldpi/mdpi/hdpi/xhdpi/...
16. Touchscreen      notouch/stylus/finger
17. Keyboard         keyssoft/keysexposed/keyshidden
18. Primary text input method  nokeys/qwerty/12key
19. Navigation key availability navhidden/navexposed
```

**匹配算法**：

```text
1. 过滤掉不匹配的限定符
2. 从优先级最高的限定符开始逐个比较
3. 第一个有差异的限定符决定胜负（配置中更具体的赢）
4. 全部相同 → 使用该配置
5. 没有完全匹配 → 逐级降级：
   去掉 night → 去掉方向 → 去掉 sw → ... → 默认目录
```

**具体例子**（设备：`zh-CN`、`night`、`sw720dp`、`land`、`xhdpi`）：

```text
候选（按优先级从高到低尝试）：
  values-zh-rCN-night-sw720dp-land-xhdpi    ← 完全匹配（如果存在）
  values-zh-rCN-night-sw720dp-xhdpi
  values-zh-rCN-night-land-xhdpi
  values-zh-rCN-night-xhdpi
  values-night-xhdpi
  values-night
  values
```

### 6. 折叠屏（Foldable）与窗口尺寸变化

**Android 的窗口变化回调**：

```kotlin
// Activity 中
override fun onMultiWindowModeChanged(isInMultiWindowMode: Boolean, newConfig: Configuration) {
    super.onMultiWindowModeChanged(isInMultiWindowMode, newConfig)
    // 分屏/自由窗口切换
}

override fun onConfigurationChanged(newConfig: Configuration) {
    super.onConfigurationChanged(newConfig)
    // 折叠状态变化也会走这里
}
```

**Jetpack WindowManager（官方折叠屏适配库）**：

```kotlin
// 依赖
// implementation("androidx.window:window:1.3.0")

class MyActivity : AppCompatActivity() {

    private lateinit var windowInfoTracker: WindowInfoTracker

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        windowInfoTracker = WindowInfoTracker.getOrCreate(this)

        lifecycleScope.launch {
            lifecycle.repeatOnLifecycle(Lifecycle.State.STARTED) {
                windowInfoTracker.windowLayoutInfo(this@MyActivity)
                    .collect { layoutInfo ->
                        // 1. 判断是否处于折叠状态
                        val foldingFeature = layoutInfo.displayFeatures
                            .filterIsInstance<FoldingFeature>()
                            .firstOrNull()

                        val isSeparating = foldingFeature?.isSeparating == true
                        val isHalfOpened = foldingFeature?.state == FoldingFeature.State.HALF_OPENED
                        val isFlat = foldingFeature?.state == FoldingFeature.State.FLAT

                        // 2. 不同的布局策略
                        when {
                            isSeparating -> {
                                // 铰链处有间隔 → 双栏布局，中间留出铰链空间
                                binding.container.setPadding(0, 0, hingeWidth, 0)
                            }
                            isHalfOpened -> {
                                // 半折状态（类似笔记本）→ 上半屏内容，下半屏控件
                                binding.topHalf.visibility = View.VISIBLE
                                binding.bottomHalf.visibility = View.VISIBLE
                            }
                            else -> {
                                // 完全展开 → 常规单栏
                                binding.topHalf.visibility = View.GONE
                            }
                        }
                    }
            }
        }
    }
}
```

**折叠屏的三种形态**：

```text
1. 折叠（Folded / Closed）
   外屏（小屏）→ 紧凑布局
2. 半折（Half-Open / Tabletop）
   像笔记本一样 → 上半屏内容 + 下半屏操作区
3. 展开（Flat / Open）
   内屏（大屏）→ 双栏 / 大幅布局
```

**`FoldingFeature` 的关键属性**：

| 属性 | 说明 |
| --- | --- |
| `state` | `FLAT` / `HALF_OPENED` / `occlusionType` |
| `isSeparating` | 是否把屏幕分成两个逻辑区域（应避开铰链） |
| `occlusionType` | `NONE` / `FULL`（铰链完全遮挡内容） |
| `bounds` | 铰链在屏幕上的位置 |
| `orientation` | `VERTICAL` / `HORIZONTAL` |

**Activity 的 `resizeableActivity`**：

```xml
<!-- AndroidManifest.xml -->
<activity
    android:name=".MainActivity"
    android:resizeableActivity="true"
    android:screenOrientation="unspecified" />
```

- API 24+ 默认 `true`（允许分屏与自由窗口）。
- **禁止分屏**：`android:resizeableActivity="false"`。
- **大屏适配（Android 12L+）**：Google 要求**必须支持大屏**，不再允许通过 `screenOrientation` 锁定方向。

### 7. 字体缩放与无障碍

```text
用户可调整的缩放设置：

1. 设置 → 显示 → 字体大小（fontScale）
   范围约 0.85 ~ 2.0（部分 ROM 到 3.0+）

2. 设置 → 显示 → 显示大小（display size）
   部分厂商 ROM 会同时缩放 dp（影响布局）

3. 无障碍 → 大字体 / 高对比度
```

**适配建议**：

```text
✅ 字号用 sp（必须）
✅ 布局用 wrap_content / 0dp+weight / ConstraintLayout，不要写死 dp 宽度
✅ 给文本容器设置 maxLines + ellipsize 作为兜底
✅ 重要信息不要只靠字号区分
✅ 点击目标最小 48dp × 48dp
✅ 提供内容描述（contentDescription）
✅ 测试最大 fontScale（2.0）下的布局
```

**Compose 中的字体缩放**：

```kotlin
// 忽略系统字体缩放（谨慎使用，仅用于不需要放大的场景）
CompositionLocalProvider(
    LocalDensity provides Density(density = LocalDensity.current.density, fontScale = 1f)
) {
    MyContent()
}
```

**响应系统缩放（推荐默认行为）**：

```kotlin
val fontScale = LocalDensity.current.fontScale
// 用它做布局决策
if (fontScale > 1.5f) {
    // 放大字体时改用两栏布局
}
```

### 8. 平板适配策略

**Material 3 的自适应布局**：

```text
宽度断点：
  Compact   < 600dp    单栏，手机
  Medium    600-840dp  两栏，或"列表 + 详情"
  Expanded  > 840dp    两栏 + 侧边导航栏

高度断点：
  Compact   < 480dp
  Medium    480-900dp
  Expanded  > 900dp
```

**常见的三种自适应模式**：

| 模式 | 布局 | 适用 |
| --- | --- | --- |
| **List-detail** | 左列表 + 右详情 | 邮件、设置、文件管理 |
| **Feed** | 多列瀑布流 | 内容浏览（相册、商品） |
| **Supporting pane** | 主内容 + 辅助面板 | 文档阅读、视频播放 |

**AndroidX WindowManager 的 `FoldingFeature` + `WindowSizeClass`** 组合是最完整的方案。

**避免的做法**：

```text
❌ 用一个巨大的布局文件覆盖所有设备
❌ 用固定 dp 宽度做界面
❌ 简单地把手机布局拉伸到平板（内容稀疏）
❌ 忽略横屏（默认禁止旋转）
```

### 1. 尺寸单位与换算工具

```kotlin
object DpUtils {

    /** dp → px */
    fun dpToPx(dp: Float, context: Context): Int = TypedValue.applyDimension(
        TypedValue.COMPLEX_UNIT_DIP, dp, context.resources.displayMetrics
    ).toInt()

    /** sp → px（含 fontScale） */
    fun spToPx(sp: Float, context: Context): Float = TypedValue.applyDimension(
        TypedValue.COMPLEX_UNIT_SP, sp, context.resources.displayMetrics
    )

    /** px → dp */
    fun pxToDp(px: Float, context: Context): Float =
        px / context.resources.displayMetrics.density

    /** 当前 density */
    val density: Float
        get() = Resources.getSystem().displayMetrics.density

    /** 当前 fontScale */
    val fontScale: Float
        get() = Resources.getSystem().configuration.fontScale
}
```

### 2. 自适应屏幕尺寸的工具

```kotlin
/** 屏幕尺寸分类（参考 Material 3 Window Size Class） */
enum class WindowSizeClass { COMPACT, MEDIUM, EXPANDED }

fun currentWindowSizeClass(context: Context): WindowSizeClass {
    val metrics = context.resources.configuration
    val widthDp = (metrics.screenWidthDp / metrics.density).toInt()
    // 注意：直接用 screenWidthDp 在分屏时不准确，推荐用 WindowMetrics
    return when {
        widthDp < 600 -> WindowSizeClass.COMPACT
        widthDp < 840 -> WindowSizeClass.MEDIUM
        else -> WindowSizeClass.EXPANDED
    }
}

/** Android 11+ 用 WindowMetrics 获取真实窗口尺寸（分屏/自由窗口准确） */
fun windowSizeDp(context: Context): Pair<Int, Int> {
    return if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.R) {
        val bounds = context.getSystemService(WindowManager::class.java)
            .currentWindowMetrics.bounds
        val metrics = context.resources.displayMetrics
        ((bounds.width() / metrics.density).toInt() to
                (bounds.height() / metrics.density).toInt())
    } else {
        val metrics = context.resources.displayMetrics
        (metrics.widthPixels / metrics.density).toInt() to
                (metrics.heightPixels / metrics.density).toInt()
    }
}
```

### 4. 折叠屏适配（Jetpack WindowManager）

```kotlin
class FoldableActivity : AppCompatActivity() {

    private lateinit var windowInfoTracker: WindowInfoTracker

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_foldable)
        windowInfoTracker = WindowInfoTracker.getOrCreate(this)

        lifecycleScope.launch {
            lifecycle.repeatOnLifecycle(Lifecycle.State.STARTED) {
                windowInfoTracker.windowLayoutInfo(this@FoldableActivity)
                    .collect { layoutInfo ->
                        val foldingFeature = layoutInfo.displayFeatures
                            .filterIsInstance<FoldingFeature>()
                            .firstOrNull()

                        when {
                            foldingFeature == null -> applyExpandedLayout()
                            foldingFeature.isSeparating -> applyDualPaneLayout(foldingFeature)
                            foldingFeature.state == FoldingFeature.State.HALF_OPENED ->
                                applyTabletopLayout(foldingFeature)
                            else -> applyExpandedLayout()
                        }
                    }
            }
        }
    }

    /** 完全展开：大屏双栏 */
    private fun applyExpandedLayout() {
        binding.paneTop.isVisible = false
        binding.paneBottom.isVisible = false
        binding.paneLeft.isVisible = true
        binding.paneRight.isVisible = true
    }

    /** 铰链分隔：双栏，中间避开铰链 */
    private fun applyDualPaneLayout(feature: FoldingFeature) {
        binding.paneLeft.isVisible = true
        binding.paneRight.isVisible = true
        // 用铰链的实际位置作为间隔
        val hingeBounds = feature.bounds
        val metrics = resources.displayMetrics
        val hingeWidthDp = (hingeBounds.width() / metrics.density).toInt()
        binding.splitContainer.setPadding(0, 0, hingeWidthDp, 0)
    }

    /** 半折：上下分屏 */
    private fun applyTabletopLayout(feature: FoldingFeature) {
        binding.paneLeft.isVisible = false
        binding.paneRight.isVisible = false
        binding.paneTop.isVisible = true
        binding.paneBottom.isVisible = true
        // 上半屏放内容，下半屏放操作按钮
    }
}
```

```kotlin
/** 运行时按密度选择合适的位图资源（避免内存浪费） */
fun loadOptimizedBitmap(context: Context, resId: Int, targetWidthDp: Int): Bitmap {
    val metrics = context.resources.displayMetrics
    val targetWidthPx = (targetWidthDp * metrics.density).toInt()

    val options = BitmapFactory.Options().apply {
        inJustDecodeBounds = true
    }
    BitmapFactory.decodeResource(context.resources, resId, options)

    // 计算 inSampleSize（2 的幂次）
    var inSampleSize = 1
    while (options.outWidth / inSampleSize > targetWidthPx * 2) {
        inSampleSize *= 2
    }

    return BitmapFactory.decodeResource(context.resources, resId,
        BitmapFactory.Options().apply { inSampleSize = inSampleSize })
}
```

## 常见问题 / 面试要点

**读者问：`dp` 和 `sp` 有什么区别？为什么字号必须用 `sp`？**

**AI答：**

1. **定义**：
   - `dp`（density-independent pixel）：以 **160dpi** 为基准的密度无关像素，1dp = 1px @mdpi。
   - `sp`（scale-independent pixel）：在 `dp` 的基础上**再乘以 `fontScale`**（用户在系统里设置的字体大小比例）。
2. **换算**：
   ```text
   1 dp = (densityDpi / 160) px
   1 sp = 1 dp × fontScale
   ```
3. **为什么字号必须用 sp**：
   - **无障碍要求**：视力障碍用户会把系统字体放大到 2 倍以上。用 `dp` 写字号时，**字号不会变**，用户依然看不清 → 违反无障碍规范，是产品缺陷。
   - 用 `sp` 时，系统字体设置一改，所有字号**自动等比放大**。
4. **什么时候用 dp**：
   - 所有**非文字尺寸**：间距、宽高、圆角、图标大小、触摸区域（48dp 最小）。
5. **反模式**：
   - ❌ 用 `dp` 写 `textSize` → 用户放大字体无效；
   - ❌ 用 `sp` 写间距 → 用户放大字体时布局被撑开（有时是想要的，但通常不是）；
   - ❌ 写死 px 宽高 → 在不同密度设备上大小完全不同。
6. **面试话术**："**`dp` 管几何，`sp` 管文字。文字用 dp 就是对无障碍的不尊重。**"

---

**读者问：`sw<N>dp`、`w<N>dp`、`h<N>dp` 有什么区别？该怎么选？**

**AI答：**

1. **`sw<N>dp`（smallestWidth）**：
   - 定义：屏幕**最短边**的 dp 值。
   - **与横竖屏无关**（旋转时不变）。
   - **与分屏无关**（是"设备"属性，不是"窗口"属性）——注意：这是它与 `w/h` 的关键区别。
   - **用途**：判断设备类型（手机 vs 平板）。`sw600dp` 是业界公认的"平板"标准。
2. **`w<N>dp`（available width）**：
   - 定义：**当前窗口**的可用宽度。
   - **随横竖屏、分屏、自由窗口变化**。
   - **用途**：响应式布局（双栏 vs 单栏）。
3. **`h<N>dp`**：可用高度，同理。
4. **选择建议**：
   | 场景 | 用哪个 |
   | --- | --- |
   | 区分手机 / 平板（选资源） | `sw600dp` |
   | 区分横屏 / 竖屏布局 | `layout-land` 或 `w840dp` |
   | 分屏时切换双栏 | `w600dp`（或运行时用 `WindowMetrics` 判断） |
   | 可折叠设备 | `sw600dp` + Jetpack WindowManager |
5. **重要提醒**：`sw` 是**设备**属性，`w/h` 是**窗口**属性。在分屏时，`sw` 不变但 `w` 变小 → 如果你想让资源跟随窗口变化，用 `w/h`；如果想跟随设备，用 `sw`。
6. **配置变化**：旋转屏幕时 `w/h` 会变化 → 触发 Activity 重建（或 `onConfigurationChanged`）；`sw` 不变 → 不触发。
7. **面试话术**："**`sw` 看设备（分屏不变），`w/h` 看窗口（分屏会变）。判断平板用 `sw600dp`，做响应式布局用 `w` 或运行时 `WindowMetrics`。**"

---

**读者问：Android 怎么选择资源的？优先级规则是什么？**

**AI答：**

1. **匹配算法**：
   ```text
   1. 过滤掉与设备配置不匹配的限定符组合
   2. 按官方优先级表从高到低逐个比较限定符
   3. 第一个"有差异"的限定符决定胜负（设备配置中指定的更具体 → 赢）
   4. 若配置中该限定符未指定，则该限定符"不比"（双方都算匹配）
   5. 全部相同 → 用该资源
   6. 无完全匹配 → 逐级去掉限定符降级
   7. 最终回退到无限定符目录（values/、drawable/）
   ```
2. **优先级表（前 15 项，节选）**：
   ```text
   MCC/MNC → Locale → LayoutDirection → smallestWidth → available width
   → available height → screen size → screen aspect → round → wide gamut
   → HDR → orientation → UI mode → night mode → density → ...
   ```
3. **关键：多限定符组合的顺序必须与表格一致**：
   ```text
   ✅ values-v21-sw600dp-zh-rCN     （按表：v 之后 sw 之后 locale）
   ❌ values-sw600dp-v21
   ```
   顺序错误 → AAPT 报错。
4. **降级示例**（设备：`night`、`sw720dp`、`land`）：
   ```text
   values-night-sw720dp-land   ← 最匹配
   values-night-sw720dp
   values-night-land
   values-night
   values
   ```
5. **只声明一个限定符**时，其余视为"任意匹配"——这就是为什么 `values-night/colors.xml` 只需写要覆盖的项。
6. **面试话术**："**资源匹配 = 过滤 + 按优先级表逐项比较，第一个差异决定胜负，最后回退到无限定符目录。**"

**读者问：折叠屏需要做哪些适配？Jetpack WindowManager 怎么用？**

**AI答：**

1. **折叠屏的三种形态**（必须都支持）：
   - **外屏（折叠/闭合）**：小屏 → **紧凑布局**（单栏）。
   - **半折（Half-Open / Tabletop）**：像笔记本 → **上下分屏**（上半内容、下半操作）。
   - **内屏（展开）**：大屏 → **双栏 / 大幅布局**。
2. **必须处理的四个问题**：
   - **窗口尺寸变化**：展开/折叠会触发配置变化 → 布局需要重新布局。
   - **铰链遮挡**：`occlusionType == FULL` 时铰链完全遮挡内容 → 需要避开。
   - **铰链分隔**：`isSeparating == true` → 双栏之间必须留出铰链宽度，否则内容被裁剪。
   - **连续性**：折叠/展开时应用不应重建 Activity（Android 官方要求）→ 声明 `configChanges` 或正确处理 `onConfigurationChanged`。
3. **Jetpack WindowManager 的用法**：
   ```kotlin
   val windowInfoTracker = WindowInfoTracker.getOrCreate(this)
   windowInfoTracker.windowLayoutInfo(this).collect { layoutInfo ->
       val foldingFeature = layoutInfo.displayFeatures
           .filterIsInstance<FoldingFeature>().firstOrNull()
       // 根据 foldingFeature.state / isSeparating / occlusionType / bounds 决定布局
   }
   ```
4. **配合 `WindowSizeClass`**（Material 3）：根据**当前窗口宽度**选择紧凑/中等/展开布局，这才是响应式的正确依据。
5. **大屏适配（Android 12L+ / Google Play 政策）**：
   - 从 2024 年起，Google Play 要求上架 App **必须支持大屏**，不允许通过 `android:screenOrientation` 锁定方向或 `resizeableActivity="false"` 禁止缩放。
   - 需要用 `WindowSizeClass` + 资源限定符（`values-w600dp` 等）做真正的自适应。
6. **测试方法**：
   - Android Studio 的 **Foldable / Tablet 预览**（Extended Controls）；
   - 模拟器：Android Emulator 的"折叠设备"外形；
   - 真实设备上的 `adb shell wm size` 模拟不同窗口尺寸。
7. **面试话术**："**折叠屏适配的核心是『根据 FoldingFeature 决定布局形态』：外屏紧凑、内屏双栏、半折上下分屏，并避开铰链区域。**"

**读者问：大字体（fontScale 很大）时布局崩了怎么办？**

**AI答：**

1. **原因**：用户把系统字体放大到 2 倍后，`sp` 文字高度翻倍，固定高度的容器放不下 → 文字被裁剪或重叠。
2. **常见错误**：
   ```xml
   <!-- ❌ 固定高度 + 大字号 -->
   <TextView android:layout_height="40dp" android:textSize="16sp" />
   <!-- ❌ 固定宽度 + 大字号 -->
   <TextView android:layout_width="200dp" />
   ```
3. **正确做法**：
   - **高度用 `wrap_content`** 或 `minHeight`，不要写死。
   - **宽度用 `0dp` + `weight`** 或 `match_parent` + `ConstraintLayout`，让文本自己决定。
   - **容器用可滚动**（`NestedScrollView`）兜底。
   - **必要时限制行数** + `ellipsize`（作为最后手段，不要作为首选）。
   - **按钮**：用 `wrap_content` + `padding`，不要固定宽度。
   - **图标与文字并排**：给图标固定大小，文字 `0dp + weight`。
4. **主动适配字体缩放**（进阶）：
   ```kotlin
   val fontScale = LocalConfiguration.current.fontScale
   if (fontScale >= 1.5f) {
       // 改用纵向排列 / 换更紧凑的布局
   }
   ```
5. **测试方法**：
   ```bash
   adb shell settings put system font_scale 2.0
   ```
   然后遍历主要页面检查。
6. **Compose**：默认行为就是随字号缩放，不要用 `Modifier.height(40.dp)` 写死含文字的容器。
7. **面试话术**："**大字体适配的第一原则：文字容器永远不要写死高度。用 `wrap_content` + `weight` + 可滚动容器。**"

---

**读者问：怎么给不同尺寸的屏幕提供不同资源？常见做法有哪些？**

**AI答：**

1. **四类做法**（推荐组合使用）：
   | 做法 | 资源目录 | 适用 |
   | --- | --- | --- |
   | **差异化资源** | `values-sw600dp/`、`layout-land/` | 尺寸差异大、需要完全不同的布局 |
   | **响应式布局** | 同一份布局 + `ConstraintLayout`/`weight`/`Guideline` | **首选**：结构相似，只是排列不同 |
   | **运行时判断** | `WindowMetrics` / `WindowSizeClass` | 需要动态决策（如双栏 vs 单栏） |
   | **Compose 自适应** | `calculateWindowSizeClass` | Compose 项目 |
2. **典型目录结构**：
   ```text
   res/layout/              默认
   res/layout-land/         横屏
   res/layout-sw600dp/      平板
   res/values/dimens.xml    默认尺寸
   res/values-sw600dp/dimens.xml   平板尺寸（更大的间距）
   res/values-w840dp/       宽屏
   res/drawable/            默认密度
   res/drawable-xhdpi/      高密度
   ```
3. **间距的差异化**（简单且有效）：
   ```xml
   <!-- values/dimens.xml -->
   <dimen name="screen_margin">16dp</dimen>
   <!-- values-sw600dp/dimens.xml -->
   <dimen name="screen_margin">32dp</dimen>
   ```
   → 布局代码不用改，平板上自动更宽松。
4. **⚠️ 陷阱**：资源目录膨胀会显著增加 APK 体积（每份资源 × N 个屏幕 × N 个语言 × N 个密度）。**优先用响应式布局，减少目录数量。**
5. **最佳实践**：
   - 尽量只用 `values-sw600dp`（不区分 land/port）；
   - 横竖屏用响应式布局处理，而不是 `layout-land`；
   - 图片用矢量图，避免密度目录爆炸。
6. **面试话术**："**优先级是：响应式布局 > 差异化资源。差异化资源是不得已的手段，因为它会让资源数量爆炸。**"
