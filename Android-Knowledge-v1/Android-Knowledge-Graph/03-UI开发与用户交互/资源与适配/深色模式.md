# 深色模式

## 一句话定义

深色模式（Dark Theme）在 Android 10（API 29）成为系统特性。它的实现原理是**资源限定符 `night`**：系统切换深浅模式时改变 `Configuration.uiMode`，资源系统据此优先选用 `values-night/` 等目录中的资源。App 侧的核心工作是**提供 night 版本的颜色资源**，并保证对比度与图片的适配。

## 核心原理

### 1. 原理：`night` 限定符

```text
系统切换深色模式
   │
   ├─ Configuration.uiMode 的 UI_MODE_NIGHT_MASK 变为 UI_MODE_NIGHT_YES
   │
   ▼
Resources 重新解析资源表
   │
   ├─ 优先匹配 values-night/、drawable-night/、layout-night/ 中的同名资源
   └─ 未定义的项自动回退到 values/、drawable/、layout/
```

**关键点：按资源名覆盖，不是整目录替换。**

```xml
<!-- res/values/colors.xml -->
<resources>
    <color name="app_background">#FFFFFF</color>
    <color name="app_text">#1C1B1F</color>
    <color name="brand_primary">#6750A4</color>
</resources>

<!-- res/values-night/colors.xml -->
<resources>
    <!-- 只写要覆盖的项；app_text 未写 → 自动沿用浅色值 -->
    <color name="app_background">#1C1B1F</color>
    <color name="brand_primary">#D0BCFF</color>
</resources>
```

**`uiMode` 的常量**：

```java
Configuration.UI_MODE_NIGHT_MASK   // 用于掩码
Configuration.UI_MODE_NIGHT_UNDEFINED  // 0x00 未定义
Configuration.UI_MODE_NIGHT_NO     // 0x10 非夜间
Configuration.UI_MODE_NIGHT_YES    // 0x20 夜间
```

```kotlin
// 判断当前是否深色模式
val isNight = (resources.configuration.uiMode and
        Configuration.UI_MODE_NIGHT_MASK) == Configuration.UI_MODE_NIGHT_YES
```

### 2. 目录与命名规范

| 资源类型 | 浅色目录 | 深色目录 |
| --- | --- | --- |
| 颜色 / 尺寸 / 样式 | `res/values/` | `res/values-night/` |
| 主题 | `res/values/themes.xml` | `res/values-night/themes.xml` |
| 布局 | `res/layout/` | `res/layout-night/`（极少用） |
| 图片 | `res/drawable/` | `res/drawable-night/` |
| 矢量图 | `res/drawable/` | `res/drawable-night/` |
| 动画 | `res/anim/` | `res/anim-night/` |
| 菜单 | `res/menu/` | `res/menu-night/` |

**命名规范（Google 官方推荐）**：

```text
颜色资源名统一使用 md_theme_ 前缀：
  md_theme_primary
  md_theme_onPrimary
  md_theme_primaryContainer
  md_theme_surface
  md_theme_onSurface
  md_theme_error
  md_theme_background
  md_theme_outline
```

> 这是 Material Theme Builder 生成的标准命名，便于后续从 MD2 迁移和跨项目复用。

### 3. Material 3 的颜色角色在深色模式下的调整

**深色模式不是"反色"，而是重新推导对比度**：

```text
浅色模式                          深色模式
────────                          ────────
surface (背景)   #FFFBFE (亮)  →   surface   #1C1B1F (暗)
onSurface (文字) #1C1B1F (暗)  →   onSurface #E6E1E5 (亮)
primary          #6750A4 (中暗) →  primary   #D0BCFF (变亮!)
onPrimary        #FFFFFF (亮)  →   onPrimary #381E72 (变暗!)
primaryContainer #EADDFF (很亮) →  primaryContainer #4F378B (变暗!)
```

**三个反直觉但正确的规则**：

1. **主色在深色模式下变亮**（`primary` 从 `#6750A4` → `#D0BCFF`）。
   - 原因：深色背景上需要亮色前景才看得清。深色主色在深背景上几乎不可见。
2. **`onPrimary` 在深色模式下变暗**（`#FFFFFF` → `#381E72`）。
   - 原因：按钮背景变成了浅色，文字必须用深色。
3. **容器色在深色模式下变暗**（`primaryContainer` 从 `#EADDFF` → `#4F378B`）。
   - 原因：深色模式下"弱化"应通过**降低对比度**实现，而不是提亮。浅色模式下容器是"接近背景的浅色"，深色模式下容器是"接近背景的深色"。

### 4. 主题配置

**推荐：使用 `DayNight` 主题**：

```xml
<!-- res/values/themes.xml -->
<style name="Theme.MyApp" parent="Theme.Material3.DayNight.NoActionBar">
    <item name="colorPrimary">@color/md_theme_primary</item>
    <item name="colorOnPrimary">@color/md_theme_onPrimary</item>
    <!-- ... 其余颜色角色同理 -->
    <item name="android:statusBarColor">@android:color/transparent</item>
    <item name="android:navigationBarColor">@android:color/transparent</item>
    <item name="android:windowLightStatusBar">true</item>   <!-- 浅色状态栏图标 -->
</style>
```

```xml
<!-- res/values-night/themes.xml -->
<resources>
    <style name="Theme.MyApp" parent="Theme.Material3.DayNight.NoActionBar">
        <!-- 颜色不变（自动引用 night 版本），只覆盖需要区分的属性 -->
        <item name="android:windowLightStatusBar">false</item>   <!-- 深色下用白色状态栏图标 -->
    </style>
</resources>
```

**关键**：`Theme.Material3.DayNight` 会在深色模式下**自动**切换到 `Theme.Material3.Dark` 的行为；颜色资源由 `night` 限定符自动切换。

**注意 `windowLightStatusBar`**：
- `true` → 状态栏图标为深色（适合浅色背景）；
- `false` → 状态栏图标为浅色（适合深色背景）；
- 这个属性**不会**因为用了 `DayNight` 主题而自动切换 → **必须**在 `values-night/themes.xml` 里显式覆盖。

### 5. 系统强制深色（Force Dark）

**Android 10 引入的"自动反色"**：

```xml
<!-- 允许系统对不支持深色的 App 强制深色（默认 true，API 29+） -->
<item name="android:forceDarkAllowed">true</item>
```

**行为**：
- 系统会分析 App 的浅色主题，用 `colorPrimary` 等推导出一套深色颜色，**自动反色**背景与文字。
- 因为是"猜"的，效果通常不理想（品牌色可能失真、图标看不清）。

**建议**：
```xml
<!-- App 已经做了深色适配 → 关闭系统强制深色，避免二次处理 -->
<item name="android:forceDarkAllowed" tools:targetApi="q">false</item>
```

**WebView 的强制深色**：

```kotlin
if (WebViewFeature.isFeatureSupported(WebViewFeature.FORCE_DARK)) {
    webView.settings.forceDark = WebSettings.FORCE_DARK_ON
}
```

### 6. 深色模式下的图片处理

**问题**：白底图片放在深色背景上非常刺眼（"白块效应"）。

**解决方案**：

| 方案 | 做法 | 优点 |
| --- | --- | --- |
| **矢量图 + 主题色** | 用 `android:fillColor="?attr/colorOnSurface"` | ✅ **最佳**：自动跟随主题 |
| **`drawable-night/` 备图** | 同一资源名，深色目录放深色版本 | 适合照片、插画 |
| **`ImageView` 的 `night` 限定** | `drawable-night/ic_photo.xml` | 自动切换 |
| **运行时给位图加滤镜** | 深色模式下降低亮度 | 适合动态内容 |
| **Material Theme Builder 生成** | 一键生成整套资源 | 效率最高 |

**矢量图跟随主题（推荐）**：

```xml
<!-- res/drawable/ic_notification.xml -->
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="24dp"
    android:height="24dp"
    android:viewportWidth="24"
    android:viewportHeight="24">
    <!-- 引用主题属性 → 自动跟随深浅模式 -->
    <path
        android:fillColor="?attr/colorOnSurface"
        android:pathData="M12,2L2,7v10l10,5 10,-5V7L12,2z" />
</vector>
```

```xml
<!-- 固定颜色的矢量图：在 night 目录放一个改色版本 -->
<!-- res/drawable/ic_brand.xml -->
<vector ...>
    <path android:fillColor="#6750A4" ... />
</vector>

<!-- res/drawable-night/ic_brand.xml -->
<vector ...>
    <path android:fillColor="#D0BCFF" ... />
</vector>
```

**运行时给位图加暗色滤镜**：

```kotlin
fun applyDarkFilter(bitmap: Bitmap, isDark: Boolean): Bitmap {
    if (!isDark) return bitmap
    val matrix = ColorMatrix().apply {
        setSaturation(0.7f)                              // 降低饱和度
        postConcat(ColorMatrix().apply { setScale(0.8f, 0.8f, 0.8f, 1f) })  // 降低亮度
    }
    return Bitmap.createBitmap(bitmap, 0, 0, bitmap.width, bitmap.height,
        matrix, true)
}
```

**Material 建议**：照片类内容**保持原样**（用户需要看真实照片），UI 图标类内容**跟随主题**。

### 7. Compose 中的深色模式

**`isSystemInDarkTheme()`**：

```kotlin
@Composable
fun MyAppTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    content: @Composable () -> Unit
) {
    val colorScheme = if (darkTheme) DarkColors else LightColors
    MaterialTheme(colorScheme = colorScheme, content = content)
}
```

**`isSystemInDarkTheme()` 的实现**：

```kotlin
@Composable
fun isSystemInDarkTheme(): Boolean = isDarkTheme(LocalConfiguration.current.uiMode)

fun isDarkTheme(uiMode: Int): Boolean =
    (uiMode and Configuration.UI_MODE_NIGHT_MASK) == Configuration.UI_MODE_NIGHT_YES
```

**动态取色（Android 12+）**：

```kotlin
@Composable
fun MyAppTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    dynamicColor: Boolean = true,      // 默认开启动态取色
    content: @Composable () -> Unit
) {
    val colorScheme = when {
        dynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S -> {
            val context = LocalContext.current
            if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context)
        }
        darkTheme -> DarkColors
        else -> LightColors
    }
    MaterialTheme(colorScheme = colorScheme, content = content)
}
```

**手动覆盖（App 内切换）**：

```kotlin
// AppCompat：全局切换（会重建 Activity）
AppCompatDelegate.setDefaultNightMode(AppCompatDelegate.MODE_NIGHT_YES)

// Compose：局部覆盖（推荐，可持久化）
enum class ThemeMode { SYSTEM, LIGHT, DARK }

class ThemePreferences(private val dataStore: DataStore<Preferences>) {
    val mode: Flow<ThemeMode> = dataStore.data.map { prefs ->
        when (prefs[THEME_KEY]) {
            "light" -> ThemeMode.LIGHT
            "dark" -> ThemeMode.DARK
            else -> ThemeMode.SYSTEM
        }
    }
}

@Composable
fun MyApp(viewModel: ThemeViewModel = hiltViewModel()) {
    val mode by viewModel.themeMode.collectAsStateWithLifecycle()
    val darkTheme = when (mode) {
        ThemeMode.SYSTEM -> isSystemInDarkTheme()
        ThemeMode.LIGHT -> false
        ThemeMode.DARK -> true
    }
    MyAppTheme(darkTheme = darkTheme) { /* ... */ }
}
```

### 9. 深色模式下的测试

**手动切换**：

```bash
# 切换系统深色模式
adb shell "cmd uimode night yes"

```

**测试检查清单**：

- [ ] 所有文本与背景的对比度 ≥ 4.5:1（正文）/ 3:1（大字）
- [ ] 图片、图标在深色背景下不刺眼、不可见
- [ ] 阴影/elevation 在深色模式下不明显 → 用**边框或表面色阶**替代
- [ ] 状态栏/导航栏图标颜色正确
- [ ] Dialog、Snackbar、BottomSheet 等浮层颜色正确
- [ ] 图表、Canvas 自绘内容使用了主题色
- [ ] 第三方 SDK（地图、播放器、图表）有自己的深色配置

**对比度检测工具**：

```text
- Android Studio Layout Inspector（可检查对比度）
- Accessibility Scanner（无障碍扫描）
- Chrome DevTools 的对比度检查器
- 手动计算：L1/L2 相对亮度公式
```

### 10. 深色模式下的常见坑

| 坑 | 原因 | 解决 |
| --- | --- | --- |
| 状态栏图标看不清 | `windowLightStatusBar` 没在 night 覆盖 | 在 `values-night/themes.xml` 覆盖 |
| Dialog 背景还是白色 | Dialog 用了独立主题 | 用 `ThemeOverlay` 继承 DayNight |
| 白色图片刺眼 | 位图没做 night 处理 | 换矢量图 / 加滤镜 / 备图 |
| elevation 阴影看不见 | 深色下阴影几乎不可见 | MD3 用 `surfaceContainer` 色阶代替阴影 |
| 自绘 Canvas 颜色没变 | 硬编码了颜色 | 用 `MaterialTheme.colorScheme` 取色 |
| 第三方 SDK 不变暗 | SDK 未适配 | 调 SDK 的深色 API 或加滤镜 |
| 深色下分隔线不可见 | 分隔线用了浅色 | 用 `outlineVariant` 等语义色 |
| 切换时闪烁 | 主题切换触发 Activity 重建 | Compose 局部覆盖，避免重建 |

## 常见问题 / 面试要点

**读者问：深色模式是怎么实现的？`values-night` 的原理是什么？**

**AI答：**

1. **原理**：
   - Android 10（API 29）引入系统级深色模式开关。
   - 切换时系统改变 `Configuration.uiMode` 中的 `UI_MODE_NIGHT_MASK`（`NO` ↔ `YES`）。
   - `Resources` 检测到配置变化后**重新解析资源表**，在候选目录中**优先匹配带 `night` 限定符的**。
   - 匹配时**按资源名覆盖**：`values-night/colors.xml` 里定义的 `app_background` 覆盖 `values/colors.xml` 中的同名项；**未定义的项自动回退到浅色目录**。
2. **`night` 在限定符优先级中的位置**：
   ```text
   ... → 屏幕方向 → UI 模式 → 夜间模式 → 屏幕密度 → ...
   ```
   `night` 的优先级**高于密度、低于方向**。所以 `values-night-xhdpi` 优先于 `values-night`，而 `values-zh-rCN-night` 优先于 `values-night`。
3. **完整实现需要 3 步**：
   - **主题**用 `Theme.Material3.DayNight`（会自动应用 Dark 变体的组件行为）；
   - **颜色资源**提供 `values-night/colors.xml`；
   - **系统栏**在 `values-night/themes.xml` 覆盖 `windowLightStatusBar`（这个属性不会自动切换）。
4. **不需要做的事**：不用在代码里判断深色模式然后 `setBackgroundColor` —— 那是把声明式资源体系退化成命令式。
5. **面试话术**："**深色模式 = `night` 限定符 + `DayNight` 主题。核心是『按资源名覆盖』，所以 `values-night` 只需写差异项。**"

---

**读者问：哪些资源需要做 night 版本？哪些不需要？**

**AI答：**

1. **必须做 night 版本**：
   | 资源 | 原因 |
   | --- | --- |
   | **颜色**（`values-night/colors.xml`） | **核心**，背景、文字、品牌色 |
   | **主题**（`values-night/themes.xml`） | 需要覆盖 `windowLightStatusBar` 等 |
   | **图标/图片**（`drawable-night/`） | 浅色图标在深色背景上看不清 |
   | **矢量图**（推荐用 `?attr/` 引用代替） | 自动跟随主题 |
   | **绘制背景**（`drawable-night/` 中的 shape、gradient） | 阴影/描边色需要调整 |
2. **通常不需要**：
   - **布局**（`layout-night/`）：深浅模式一般布局相同 → 用同一份；
   - **尺寸**（`dimens`）：间距不因深浅变化；
   - **动画**（`anim`）：无关；
   - **字符串**：无关。
3. **推荐做法（优先级）**：
   - **① 矢量图用 `?attr/colorOnSurface` 等主题属性** → **不需要** night 目录，自动跟随；
   - **② 照片类内容保持原样** → 不需要变暗（用户要看真实照片）；
   - **③ UI 图标类用 `drawable-night/` 备图**。
4. **Material 组件自动处理**：`MaterialCardView`、`Snackbar`、`BottomSheet` 等在 `Theme.Material3.Dark` 下有专门的默认颜色 —— 只要主题正确，这些组件**不需要**额外处理。
5. **容易漏掉的**：
   - 自定义 `Canvas` 绘制中硬编码的颜色；
   - 图表库的配色；
   - 地图 SDK 的底图样式；
   - 第三方 SDK 弹窗；
   - `Snackbar` 自定义背景。
6. **面试话术**："**只有『颜色和图片』需要 night 版本。布局、尺寸、动画都不需要。矢量图用 `?attr/` 就连 night 目录都不用建。**"

---

**读者问：Material 3 的颜色角色在深色模式下是怎么调整的？为什么主色要变亮？**

**AI答：**

1. **调整规则（三条，违反其中任何一条都会导致对比度问题）**：
   | 角色 | 浅色 | 深色 | 变化 |
   | --- | --- | --- | --- |
   | `primary` | `#6750A4` | `#D0BCFF` | **变亮** |
   | `onPrimary` | `#FFFFFF` | `#381E72` | **变暗** |
   | `primaryContainer` | `#EADDFF` | `#4F378B` | **变暗** |
   | `onPrimaryContainer` | `#21005D` | `#EADDFF` | **变亮** |
   | `surface` | `#FFFBFE` | `#1C1B1F` | 变暗 |
   | `onSurface` | `#1C1B1F` | `#E6E1E5` | 变亮 |
2. **为什么主色要变亮**：
   - 深色模式的核心目标是**在暗背景上提供足够的对比度**。
   - 主色是"品牌强调色"，通常用于按钮背景、强调文字。
   - 深紫色 `#6750A4` 放在深背景 `#1C1B1F` 上对比度不足（大约 2.5:1），达不到 WCAG AA 的 4.5:1。
   - 换成浅紫 `#D0BCFF` 后对比度大幅提升，**品牌辨识度也保留**（还是同一个紫色家族）。
3. **为什么 `onPrimary` 要变暗**：
   - 主色变浅后，按钮背景是浅色 → 按钮上的文字必须是**深色**，否则白字白底看不见。
   - 这就是 "on 颜色 = 压在上面的颜色" 的规则。
4. **为什么容器色要变暗（反直觉）**：
   - 浅色模式的容器色是"接近背景的浅色调"（弱化但可见）；
   - 深色模式的容器色应该是"接近背景的深色调"（同样弱化但可见）；
   - 如果在深色模式下把容器变亮，会比背景更突出 → **强调关系反了**。
5. **面试话术**："**深色模式不是反色，而是重新推导对比度：背景变暗 → 强调色变亮 → on 色反向。容器色保持『比背景略强』的关系，所以变暗。**"

---

**读者问：`forceDarkAllowed` 是什么？自己的 App 支持深色模式后还要开吗？**

**AI答：**

1. **`forceDarkAllowed`（API 29+）**：Android 10 引入的"**系统强制深色**"功能。
   - 系统分析 App 的浅色主题，**自动推导**出一套深色颜色并应用。
   - 目的是让没适配深色的旧 App 也能在深色模式下不"刺眼"。
2. **默认值**：`true`（API 29+ 默认开启）。
3. **App 已适配深色模式后应该关掉**：
   ```xml
   <item name="android:forceDarkAllowed" tools:targetApi="q">false</item>
   ```
   **原因**：
   - 系统"猜"出来的颜色通常不准确（品牌色可能变味）；
   - 会与你的 `values-night` 资源**叠加/冲突**（可能二次处理，颜色诡异）；
   - 图片、图表的自定义颜色无法被系统正确处理。
4. **什么时候应该开**：
   - 第三方 SDK 组件不支持深色，但**它们没有自己的主题**（系统可以帮到一点）；
   - 实际上大多数情况下都建议**关闭**，转而自己做适配。
5. **WebView 的强制深色**是独立的开关：
   ```kotlin
   if (WebViewFeature.isFeatureSupported(WebViewFeature.FORCE_DARK)) {
       webView.settings.forceDark = WebSettings.FORCE_DARK_ON
   }
   ```
6. **另一个相关选项**：`isLightTheme`（API 29+，WebView 专用）：
   ```kotlin
   webView.settings.isLightTheme = true   // 让网页用浅色主题渲染
   ```
7. **面试话术**："**`forceDarkAllowed` 是系统给旧 App 的『兜底反色』。自己适配了深色模式就必须关掉，否则会和自己的 night 资源打架。**"

---

**读者问：Compose 里怎么实现深色模式？`isSystemInDarkTheme()` 准吗？**

**AI答：**

1. **标准写法**：
   ```kotlin
   @Composable
   fun MyAppTheme(
       darkTheme: Boolean = isSystemInDarkTheme(),
       content: @Composable () -> Unit
   ) {
       MaterialTheme(
           colorScheme = if (darkTheme) DarkColorScheme else LightColorScheme,
           content = content
       )
   }
   ```
2. **`isSystemInDarkTheme()` 的原理**：
   ```kotlin
   @Composable
   fun isSystemInDarkTheme(): Boolean {
       val configuration = LocalConfiguration.current
       return isDarkTheme(configuration.uiMode)
   }
   ```
   - 它读的是 `LocalConfiguration`（受 `Configuration` 变化影响）→ **系统切换深色模式时会自动重组**，无需手动刷新。
3. **⚠️ 它不是绝对准确的**：
   - 它读的是**当前 Activity 的 `Configuration.uiMode`**。
   - 如果 App 自己实现了"App 内主题切换"（不跟随系统），`isSystemInDarkTheme()` 返回的是**系统**的状态，而 App 可能强制浅色。
   - **App 内切换的正确做法**：用一个 `ThemeMode`（SYSTEM/LIGHT/DARK）状态，在根部计算 `darkTheme`，**把它作为参数传给 `MyAppTheme`**，而不是在各处调用 `isSystemInDarkTheme()`。
   ```kotlin
   val darkTheme = when (mode) {
       ThemeMode.SYSTEM -> isSystemInDarkTheme()
       ThemeMode.LIGHT -> false
       ThemeMode.DARK -> true
   }
   MyAppTheme(darkTheme = darkTheme) { ... }
   ```
4. **动态取色（Android 12+）**：
   ```kotlin
   val colorScheme = if (dynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
       if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context)
   } else if (darkTheme) DarkColorScheme else LightColorScheme
   ```
5. **避免 Activity 重建**：Compose 里切换主题**不需要重建 Activity**（不像 `AppCompatDelegate.setDefaultNightMode` 会触发重建）→ 体验更好，状态不丢。
6. **面试话术**："**`isSystemInDarkTheme()` 读的是当前 Configuration，切换系统深色模式会自动重组。但 App 内自定主题时，要用统一的 `darkTheme` 参数往下传，不要到处调 `isSystemInDarkTheme()`。**"

---

**读者问：深色模式下有哪些常见的坑？**

**AI答：**

| 坑 | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| **状态栏图标看不清** | 深色下是黑色图标 | `windowLightStatusBar` 没在 night 覆盖 | `values-night/themes.xml` 中设为 `false` |
| **Dialog 还是白色** | 弹窗刺眼 | Dialog 用了独立的浅色主题 | 用 `ThemeOverlay` 继承 `DayNight`，或用 `MaterialAlertDialogBuilder` |
| **白色图片刺眼** | 深色背景上的白块 | 位图未适配 | 换矢量图 / 备图 / 加滤镜 |
| **elevation 阴影看不见** | 卡片没有层次 | 深色下阴影几乎不可见 | MD3 用 `surfaceContainer` 色阶表达层次 |
| **自绘 Canvas 颜色不变** | 图表还是黑字 | 硬编码颜色 | 用 `MaterialTheme.colorScheme` 取色 |
| **分隔线不可见** | 边界模糊 | 用了浅色分割线 | 用 `outlineVariant`（MD3 有专门的语义色） |
| **Snackbar / BottomSheet 颜色不对** | 浮层不统一 | 自定义了背景 | 用 Material 默认，或引用 `colorSurfaceInverse` 等角色 |
| **第三方 SDK 不变暗** | 地图还是亮色 | SDK 未适配 | 调 SDK 的深色 API / 加滤镜 / 换 SDK |
| **切换时闪烁** | 一闪而过 | Activity 重建 | Compose 局部覆盖主题，不重建 |
| **强制深色二次处理** | 颜色诡异 | `forceDarkAllowed` 没关 | 设为 `false` |
| **`night` 目录漏写某颜色** | 局部颜色不跟随 | 只覆盖了一部分 | 用 Material Theme Builder 生成完整色板 |

**通用原则**：

```text
1. 颜色只从主题拿，绝不硬编码
2. 图片优先用矢量图 + ?attr/
3. elevation 在深色下用"表面色阶"代替阴影
4. 浮层（Dialog/Snackbar/BottomSheet）跟随当前主题
5. 做完 Material Theme Builder 生成的整套色板，不要手写
```
