# 多语言适配

## 一句话定义

多语言适配的本质是**资源限定符（Qualifier）的应用**：Android 根据设备当前的 `Locale`（语言 + 国家/地区）在候选资源目录中挑选最匹配的那一份，因此"一套代码支持多语言"只需要准备多份 `values-xx` 目录与 `strings.xml`，**代码零改动**。

## 核心原理

### 1. Locale 限定符的规则

**目录格式**：

```text
res/values-<language>[-r<REGION>][-b+<BCP47>]/strings.xml
```

| 写法 | 含义 | 说明 |
| --- | --- | --- |
| `values-zh` | 简体中文（泛指所有中文） | 只有语言 |
| `values-zh-rCN` | 中国大陆的简体中文 | `r` + **大写**地区码 |
| `values-zh-rTW` | 台湾地区的繁体中文 | 注意是**简体字**，若要繁体需用 `b+` |
| `values-b+zh+Hant` | 繁体中文（BCP 47） | `b+` 前缀，**不区分地区** |
| `values-b+zh+Hant+TW` | 台湾地区繁体中文 | BCP 47 完整标签 |
| `values-b+zh+Hans+CN` | 中国大陆简体中文 | BCP 47 精确匹配 |
| `values-en-rUS` | 美国英语 | |
| `values-b+sr+Latn` | 塞尔维亚语（拉丁转写） | 脚本/书写系统 |
| `values-en-GB` | 英国英语 | ✅ 正确写法是 `values-b+en+GB` |

> ⚠️ **关键区别**：
> - `values-zh-rCN` 是**旧式（legacy）**语法：只能区分语言 + 地区，**不能区分简体/繁体**、不能区分书写系统。
> - `values-b+zh+Hant` 是 **BCP 47** 语法：可以表达脚本（Script，如 `Hans`/`Hant`）、变体（Variant）、数字系统。
> - **推荐使用 `b+` 语法**，Android 7.0（API 24）+ 完全支持，且能正确处理"繁体中文在台湾 vs 简体中文在大陆"的差异。

**完整的 BCP 47 标签顺序**（**必须严格按此顺序，否则 AAPT 编译报错**）：

```text
language [- script] [- region] [- variant] ... [- extension]
   zh        Hant          TW         

例：values-b+zh+Hant+TW
    └─┬─┘ └─┬─┘ └┬┘
    语言  脚本  地区
```

### 2. 资源的 Locale 匹配算法

Android 12（API 31）起引入了 **`LocaleList`** 与 **`LocaleManager`**，匹配逻辑发生了重要变化。

```text
Android 12+ 的匹配算法：

1. 获取应用的 LocaleList（可以是多个，按优先级排序）
   - 系统按用户设置排列
   - 应用可通过 LocaleManager.setApplicationLocales() 覆盖

2. 资源匹配时：
   - 先找完全匹配的（语言 + 脚本 + 地区）
   - 再逐步降级：地区 → 脚本 → 仅语言
   - 最后回退到默认目录（values/）

3. LocaleList 中每个 locale 依次尝试
```

**Locale 的 fallback 链**（`zh-Hant-TW`）：

```text
zh-Hant-TW  →  zh-Hant  →  zh-TW  →  zh  →  （默认 values/）
```

**App 级别的语言设置（Android 13+ / API 33）**：

```kotlin
// Android 13+：应用内语言切换（无需重启 Activity）
val locale = Locale.forLanguageTag("zh-CN")
LocaleManager.getInstance(context).applicationLocales = LocaleList(locale)
```

```xml
<!-- res/xml/locales_config.xml -->
<locale-config xmlns:android="http://schemas.android.com/apk/res/android">
    <locale android:name="en-US" />
    <locale android:name="zh-CN" />
    <locale android:name="zh-TW" />
    <locale android:name="ja-JP" />
</locale-config>
```

```xml
<!-- AndroidManifest.xml -->
<application
    android:localeConfig="@xml/locales_config"
    ... >
```

**低版本兼容**（AppCompat）：

```kotlin
// AndroidX AppCompat 1.6+：支持所有版本的 per-app language
AppCompatDelegate.setApplicationLocales(LocaleListCompat.forLanguageTags("zh-CN"))
```

### 3. 字符串资源与提取流程

**`strings.xml` 的基本规范**：

```xml
<resources>
    <!-- 简单字符串 -->
    <string name="app_name">我的应用</string>

    <!-- 带格式参数（必须用 positional 格式，避免翻译后语序错乱） -->
    <string name="greeting">你好，%1$s！</string>
    <string name="item_count">%1$d 个项目</string>

    <!-- 转义特殊字符 -->
    <string name="apostrophe">It\'s a test</string>
    <string name="lt">&lt;tag&gt;</string>

    <!-- CDATA：包含 HTML 或复杂格式 -->
    <string name="rich_text"><![CDATA[<b>%1$s</b> 发布了新版本]]></string>

    <!-- 引用其他字符串 -->
    <string name="welcome">欢迎，%1$s！</string>
    <string name="welcome_back">%1$s</string>

    <!-- 不翻译的字符串（品牌名、代码） -->
    <string name="brand_name" translatable="false">MyBrand</string>

    <!-- 标记为需要审校 -->
    <string name="beta_feature" translatable="true">Beta 功能</string>
</resources>
```

**翻译流程（典型工业实践）**：

```text
1. 开发：编写 values/strings.xml（源语言）
       ↓
2. 提取：Android Studio → Tools → Translations Editor
       或使用 Gradle 插件自动导出
       ↓
3. 翻译平台：Crowdin / Transifex / Phrase / Lokalise
       - 上传源文件（strings.xml）
       - 平台自动提取字符串键
       - 译者在线翻译
       ↓
4. 回传：平台生成各语言的 strings.xml
       ↓
5. 集成：放入 res/values-xx/strings.xml
       ↓
6. 校验：
   - Lint 检查 MissingTranslation
   - 伪本地化测试（pseudo-locale）
   - 自动化测试（Espresso 检查文本溢出）
```

**自动提取（Gradle）**：

```kotlin
// build.gradle.kts
android {
    androidResources {
        generateLocaleConfig = true      // 自动生成 locale_config.xml（API 33+）
    }
    // 使用 translation plugin
}
```

```xml
<!-- strings.xml 中的工具指令 -->
<resources xmlns:tools="http://schemas.android.com/tools">
    <!-- 标记不需要翻译 -->
    <string name="app_name" translatable="false">MyApp</string>
    <!-- 标记需要特殊处理 -->
    <string name="legal" tools:ignore="MissingTranslation">...</string>
</resources>
```

### 4. 复数（Plurals）与性别（Gender）

**Plurals（复数）**：不同语言的复数规则差异极大（英语 2 种、中文 1 种、阿拉伯语 6 种、俄语 3~4 种、波兰语 5 种）。

```xml
<!-- values/strings.xml（英语） -->
<plurals name="unread_messages">
    <item quantity="one">%d unread message</item>
    <item quantity="other">%d unread messages</item>
</plurals>

<!-- values-zh/strings.xml（中文） -->
<plurals name="unread_messages">
    <item quantity="other">%d 条未读消息</item>
</plurals>

<!-- values-ar/strings.xml（阿拉伯语，6 种） -->
<plurals name="unread_messages">
    <item quantity="zero">لا توجد رسائل غير مقروءة</item>
    <item quantity="one">رسالة واحدة غير مقروءة</item>
    <item quantity="two">رسالتان غير مقروءتان</item>
    <item quantity="few">%d رسائل غير مقروءة</item>
    <item quantity="many">%d رسالة غير مقروءة</item>
    <item quantity="other">%d رسالة غير مقروءة</item>
</plurals>
```

```kotlin
// 使用
val text = resources.getQuantityString(R.plurals.unread_messages, count, count)
```

**Quantity 的类型**（由 `PluralsRules` 按语言决定）：

| 语言 | zero | one | two | few | many | other |
| --- | --- | --- | --- | --- | --- | --- |
| 英语 | - | ✓ | - | - | - | ✓ |
| 中文 | - | - | - | - | - | ✓ |
| 日语 | - | - | - | - | - | ✓ |
| 俄语 | - | ✓ | - | ✓ | - | ✓ |
| 波兰语 | - | ✓ | - | ✓ | ✓ | ✓ |
| 阿拉伯语 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

**Gender（性别，API 34+）**：处理"他/她/TA"这类语法性别。

```xml
<resources>
    <string name="pronoun">他</string>
    <!-- API 34+ 的 gender 资源 -->
    <string name="invitation">%1$s 邀请你</string>
</resources>
```

```kotlin
// API 34+
// strings.xml
<string name="buy_now">立即购买</string>
```

### 5. RTL（从右到左）支持

**触发条件**：系统语言为 RTL 语言（阿拉伯语、希伯来语、波斯语、乌尔都语等），或用户在开发者选项中强制开启 RTL。

**必须做的适配**：

| 项目 | 错误写法 | 正确写法 |
| --- | --- | --- |
| 边距 | `layout_marginLeft/Right` | `layout_marginStart/End` |
| 布局方向 | `layout_gravity="left"` | `layout_gravity="start"` |
| 绘制方向 | `canvas.drawText(..., x)` 手动算 | `TextView` 自动处理 |
| 箭头图标 | 硬编码 `ic_arrow_right` | `ic_arrow_end` 或用 `layoutDirection` 自动翻转 |
| 对齐 | `textAlignment="viewStart"` | ✅ 用 `viewStart/End` |
| 绝对定位 | `layout_marginLeft` | `layout_marginStart` |

**自动翻转的资源**：系统对 `drawable` 目录中的某些资源**自动镜像**：
- `drawable/` 下的 **位图**在 RTL 下**不会**自动翻转（需要 `drawable-nodpi` 或手动提供 `drawable-ldrtl`）；
- 但**系统自带的**图标（如 `ic_media_next`）会自动翻转（用 `AutoMirrored` 属性）；
- 自定义图标应加上 `android:autoMirrored="true"`。

```xml
<!-- 自定义可自动翻转的图标 -->
<drawable name="ic_arrow" android:autoMirrored="true">
    <vector android:width="24dp" android:height="24dp"
        android:viewportWidth="24" android:viewportHeight="24">
        <path android:fillColor="#FF000000" android:pathData="M10,6L8.59,7.41 13.17,12l-4.58,4.59L10,18l6,-6z" />
    </vector>
</drawable>
```

**Compose 中的 RTL**：

```kotlin
// 读取当前布局方向
val isRtl = LocalLayoutDirection.current == LayoutDirection.Rtl

// 使用 start/end 而不是 left/right
Modifier.padding(start = 16.dp, end = 8.dp)

// 手动镜像图标
val layoutDirection = LocalLayoutDirection.current
Icon(
    painter = painterResource(R.drawable.ic_arrow),
    contentDescription = null,
    modifier = Modifier.graphicsLayer { scaleX = if (layoutDirection == LayoutDirection.Rtl) -1f else 1f }
)
```

**`supportsRtl`（API 17+）**：

```xml
<application
    android:supportsRtl="true"
    ... />
```

> ⚠️ **`android:supportsRtl` 默认为 `true`**（API 17+），但**在 `supportsRtl="true"` 时，Android 会在运行时自动镜像 `drawable` 目录中的某些资源**（具体是那些被标记为需要镜像的系统 drawable）。如果你的图标方向错误，需要 `autoMirrored="false"` 或放到 `drawable-nodpi`。

### 6. 文本溢出与可伸缩文本

**文本溢出的常见原因**：
1. 翻译后文本变长（德语通常比英语长 30%，阿拉伯语可能长 50%）；
2. 用户放大系统字体；
3. 屏幕窄。

**解决方案**：

```xml
<!-- 1. 限制行数 + 省略 -->
<TextView
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:maxLines="2"
    android:ellipsize="end"
    android:text="@string/title" />

<!-- 2. 自适应字号（API 26+） -->
<TextView
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:autoSizeTextType="uniform"
    android:autoSizeMinTextSize="12sp"
    android:autoSizeMaxTextSize="20sp"
    android:autoSizeStepGranularity="1sp"
    android:text="@string/title" />

<!-- 3. 最小宽度 + 自动换行 -->
<TextView
    android:layout_width="0dp"
    android:layout_height="wrap_content"
    android:layout_weight="1"
    android:breakStrategy="high_quality"
    android:hyphenationFrequency="normal"
    android:text="@string/body" />
```

**`breakStrategy` 与 `hyphenationFrequency`（API 23+）**：
- `breakStrategy`：`simple`（快速）/ `high_quality`（高质量，词典断词）/ `balanced`（均衡，API 23+）。
- `hyphenationFrequency`：`none` / `normal` / `full`（连字符断词，需要 `high_quality`）。
- 这两个属性对**德语、芬兰语**等长单词语言效果显著。

**Compose 中的对应**：

```kotlin
Text(
    text = stringResource(R.string.title),
    maxLines = 2,
    overflow = TextOverflow.Ellipsis,
    style = MaterialTheme.typography.titleMedium
)

// 自适应字号
Text(
    text = stringResource(R.string.title),
    style = MaterialTheme.typography.titleMedium.copy(
        autoSize = TextAutoSize.StepBased(
            minTextSize = 12.sp, maxTextSize = 20.sp, stepGranularity = 1.sp
        )
    )
)
```

### 7. 字体资源

```xml
<!-- res/font/my_font.xml（字体家族） -->
<?xml version="1.0" encoding="utf-8"?>
<font-family xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto">
    <font
        android:font="@font/my_font_regular"
        android:fontStyle="normal"
        android:fontWeight="400"
        android:font="@font/my_font_regular" />
    <font
        android:font="@font/my_font_medium"
        android:fontStyle="normal"
        android:fontWeight="500" />
    <font
        android:font="@font/my_font_bold"
        android:fontStyle="normal"
        android:fontWeight="700" />
</font-family>
```

```xml
<!-- 使用：fontFamily 引用 font XML（不是 ttf 文件） -->
<TextView
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:fontFamily="@font/my_font"
    android:text="@string/hello" />
```

**`fontWeight`（API 28+）**：可变字体的粗细支持。

**下载字体（Google Fonts 提供商）**：

```xml
<font-family xmlns:app="http://schemas.android.com/apk/res-auto">
    <font app:fontProviderAuthority="com.google.android.gms.fonts"
        app:fontProviderPackage="com.google.android.gms"
        app:fontProviderQuery="name=Roboto&weight=400"
        app:fontProviderCerts="@array/com_google_android_gms_fonts_certs" />
</font-family>
```

**字体的 RTL 与多语言支持**：
- 阿拉伯语需要**支持阿拉伯字形（Arabic shaping）**的字体，否则字母不连写；
- 希伯来语、泰语、印地语各有特殊排版需求；
- Android 从 4.4 开始支持**字体后备链（fallback）**，系统会自动为缺失字形选择系统字体。

### 8. 日期、时间、数字与货币的本地化

```kotlin
// ✅ 用 java.text 的本地化 API（自动使用 Locale）
val formatter = DateFormat.getDateInstance(DateFormat.LONG, locale)
val dateText = formatter.format(Date())
```

```kotlin
// ✅ 数字本地化（阿拉伯语用东阿拉伯数字）
val numberFormat = NumberFormat.getIntegerInstance(locale)
val text = numberFormat.format(1234567)   // en: "1,234,567"  ar: "١,٢٣٤,٥٦٧"

// ✅ 货币
val currencyFormat = NumberFormat.getCurrencyInstance(locale)
currencyFormat.currency = Currency.getInstance("CNY")
```

```kotlin
// ❌ 错误：手工拼接
val text = "${count} items"      // 不会按 locale 变化
```

**android ICU（API 24+）**：`android.icu.text.NumberFormat` 等更完整的 API。

**Locale 获取的正确方式**：

```kotlin
// ✅ 推荐：Android 13+ 用 LocaleManager
val locale = LocaleManager.getInstance(context).systemLocales[0]

// 或
val locale = context.resources.configuration.locales[0]

// ❌ 错误：Locale.getDefault() 在多语言 App 中不准确
```

### 9. 测试与校验

**伪本地化（pseudo-localization）**：把字符串替换成带框的长字符，暴露布局溢出。

```bash
# 开启伪本地化
adb shell am broadcast -a com.android.intent.action.SET_LOCALE --es com.android.intent.extra.LOCALE en-XA
```

```xml
<!-- values-en-rXA/strings.xml（伪本地化） -->
<resources>
    <string name="app_name">[!!!! MY APP !!!!]</string>
</resources>
```

**其他伪本地化类型**：
- `en-XA`：加长 30%（英文字母 → 带框变长）
- `en-XB`：加长 100%
- `ar-XA`：阿拉伯语 RTL 模拟

**Lint 检查**：

```xml
<!-- build.gradle -->
lint {
    abortOnError = false
    warningsAsErrors = false
    // 缺失翻译检查
    checkDependencies = true
}
```

```kotlin
// 手动运行 Lint 的 MissingTranslation 检查
// ./gradlew lintVitalRelease
```

**Lint 规则**：
- `MissingTranslation`：某语言缺少某个字符串。
- `ExtraTranslation`：某语言有源语言没有的字符串。
- `Typos`：`strings.xml` 中有拼写错误。
- `ImpliedQuantity`：plurals 缺少 `other`。
- `StringFormatInvalid` / `StringFormatCount` / `StringFormatMatches`：格式参数不匹配。

### 10. 其他需要本地化的资源类型

```text
需要多语言版本的不只是 strings.xml：

res/values-xx/strings.xml      字符串
res/values-xx/plurals（同一个文件）
res/values-xx/arrays.xml       字符串数组
res/values-xx/integers.xml     整数数组
res/values-xx/dimens.xml       尺寸（某些语言需要不同边距）
res/values-xx/bools.xml        布尔
res/values-xx/styles.xml       样式
res/values-xx/themes.xml       主题
res/layout-xx/                 布局（极少数语言需要不同布局，如 RTL）
res/drawable-xx/               图片（文字图片需要翻译）
res/menu-xx/                   菜单
res/xml-xx/                    XML 配置
res/raw-xx/                    原始文件
res/font-xx/                   字体（特定语言的字形）
res/anim-xx/                   动画
```

**布局的 RTL 版本**：

```text
res/layout/          默认（LTR）
res/layout-ldrtl/    RTL 专用布局（如果 LTR 和 RTL 布局结构不同）
```

**`layout-ldrtl` 的自动镜像**：
- `android:paddingLeft` → 在 RTL 下自动变成右边；
- `android:drawableLeft` → 自动变成右边；
- 但 `android:layout_marginLeft` **不会**自动镜像（要改用 `layout_marginStart`）。

object LocaleSwitcher {

    fun apply(context: Context, languageTag: String) {

        }
    }
}

## 常见问题 / 面试要点

**读者问：为什么 `strings.xml` 里不建议直接拼接字符串？正确做法是什么？**

**AI答：**

1. **拼接的三个致命问题**：
   - **语序问题**：英语 "You have %d messages" → 中文 "你有 %d 条消息" → 日语 "%d 件のメッセージがあります"（**语序完全不同**）。拼接会导致日语变成"你有 %d 件のメッセージがあります"，非常别扭。
   - **单复数问题**：英语 1 message / 2 messages，中文没有单复数，阿拉伯语有 6 种复数形式 → 拼接无法表达。
   - **性别与格变化**：俄语、法语、德语中名词有性数格变化。
2. **正确做法：完整句子 + 格式化参数**：
   ```xml
   <!-- ✅ 完整句子作为可翻译单元 -->
   <string name="unread_count">%d unread messages</string>
   <string name="welcome">Welcome, %1$s!</string>
   ```
3. **参数必须用带序号的格式**（`%1$s` 而不是 `%s`）：
   - 多个参数时必须编号，否则**翻译后无法调整顺序**（译者需要在译文里调整语序）。
   ```xml
   <!-- ❌ 译者无法调整顺序 -->
   <string name="msg">%s has %s points</string>
   <!-- ✅ 译者可以重排 -->
   <string name="msg">%1$s has %2$s points</string>
   ```
4. **代码获取**：
   ```kotlin
   context.getString(R.string.welcome, userName)
   ```
   **不能用** `context.getString(R.string.welcome)`（不传参数 → 抛 `MissingFormatArgumentException` 或显示原始 `%1$s`）。
5. **复数用 `plurals`**：
   ```kotlin
   resources.getQuantityString(R.plurals.unread_count, count, count)
   ```
   **注意第二个参数 `count` 必须传** —— 它决定选哪个 `quantity`。
6. **面试话术**："**翻译的最小单元是『完整句子』，不是词组。所以要拼接的内容必须整体交给译者，参数用编号格式。**"

**读者问：`values-zh-rCN` 和 `values-b+zh+Hant` 有什么区别？什么时候用哪个？**

**AI答：**

1. **两套语法**：
   | | Legacy（旧式） | BCP 47（新式） |
   | --- | --- | --- |
   | 写法 | `values-zh-rCN` | `values-b+zh+Hant+CN` |
   | 能表达语言 | ✅ | ✅ |
   | 能表达地区 | ✅ | ✅ |
   | **能表达脚本（简/繁）** | ❌ | ✅ |
   | 能表达变体 | ❌ | ✅ |
   | 最低 API | 全部 | API 24+（7.0）完全支持 |
2. **关键限制**：**`values-zh-rCN` 只能区分"语言+地区"，无法区分简体与繁体**。所以：
   - `values-zh-rCN` = 简体（约定俗成）
   - `values-zh-rTW` = **仍然是简体**（只是地区不同）！想用繁体必须用 `b+zh+Hant`。
3. **推荐做法**：
   - **新项目统一用 `b+` 语法**：`values-b+zh+Hans+CN`、`values-b+zh+Hant+TW`、`values-b+en+US`。
   - 只有需要兼容 API 24 以下时才额外保留 legacy 目录。
4. **BCP 47 标签顺序（必须严格遵守）**：
   ```text
   language [- script] [- region] [- variant]...
     zh       Hant      TW
   ```
   顺序错了 AAPT 会直接报错："Invalid resource directory name"。
5. **Android 12+ 的 LocaleList**：系统会按用户的语言偏好排序，逐个尝试匹配，fallback 链为：
   ```text
   zh-Hant-TW → zh-Hant → zh-TW → zh → 默认
   ```
6. **面试话术**："**legacy 语法分不清简繁，`b+` 语法可以。新项目直接用 `b+`，记得 BCP 47 的顺序是『语言-脚本-地区』。**"

**读者问：为什么布局中要用 `start`/`end` 而不是 `left`/`right`？RTL 支持要改哪些地方？**

**AI答：**

1. **原因**：在 RTL 语言（阿拉伯语、希伯来语）下，界面的**阅读方向是镜像的**。用 `left`/`right` 会导致界面"不翻转"，与用户的阅读习惯冲突。
2. **需要改的属性**：
   | 属性 | 应改为 |
   | --- | --- |
   | `layout_marginLeft/Right` | `layout_marginStart/End` |
   | `paddingLeft/Right` | `paddingStart/End`（或保留 left/right，它们**会**自动镜像） |
   | `layout_gravity="left/right"` | `layout_gravity="start/end"` |
   | `layout_alignParentLeft/Right` | `layout_alignParentStart/End` |
   | `drawableLeft/drawableRight` | `drawableStart/drawableEnd` |
   | `textAlignment` | `viewStart` / `viewEnd` |
   | `gravity="left/right"` | `gravity="start/end"` |
3. **镜像规则（容易搞混）**：
   - `paddingLeft/Right`、`drawableLeft/Right`、`layout_gravity` 中的 left/right → **系统会自动镜像**；
   - `layout_marginLeft/Right` → **不会**自动镜像（必须手动用 start/end）；
   - `RelativeLayout` 的 `layout_alignParentLeft` 等 → **不会**自动镜像。
4. **图标镜像**：
   - 系统自带的方向性图标会**自动镜像**；
   - 自定义图标需在 vector 的根标签加 `android:autoMirrored="true"`；
   - 纯位图**不会**自动镜像，需要手动提供 `drawable-ldrtl/` 版本。
5. **Canvas 绘制**：需要在绘制时判断方向：
   ```kotlin
   val isRtl = ViewCompat.getLayoutDirection(this) == ViewCompat.LAYOUT_DIRECTION_RTL
   canvas.drawText(text, if (isRtl) width - x else x, y, paint)
   ```
6. **Compose**：
   - `Modifier.padding(start = , end = )` 自动处理；
   - `LocalLayoutDirection.current` 可判断方向；
   - `Modifier.graphicsLayer { scaleX = if (isRtl) -1f else 1f }` 手动镜像。
7. **面试话术**："**`left/right` 是物理方向，`start/end` 是逻辑方向。RTL 支持就是把物理方向换成逻辑方向。**"

---

**读者问：复数（plurals）为什么要单独处理？不同语言的复数规则差别有多大？**

**AI答：**

1. **规则差异的惊人程度**：
   | 语言 | 复数形式数 | 规则 |
   | --- | --- | --- |
   | 中文、日文、韩文 | **1** | 只有 `other` |
   | 英语、德语 | 2 | `one` / `other` |
   | 法语 | 2 | `one`（0 和 1）/ `other` |
   | 俄语、乌克兰语 | 3~4 | `one` / `few` / `many` / `other` |
   | 波兰语 | **5** | `one` / `few` / `many` / `other` |
   | 阿拉伯语 | **6** | `zero` / `one` / `two` / `few` / `many` / `other` |
   | 希伯来语 | 4 | 现代规则很特殊 |
2. **用法**：
   ```kotlin
   val text = resources.getQuantityString(R.plurals.unread_count, count, count)
   //                                                    ↑ 必须传 count
   ```
3. **中文目录的写法**：
   ```xml
   <plurals name="unread_count">
       <item quantity="other">%d 条未读消息</item>
   </plurals>
   ```
4. **阿拉伯语要写全 6 种**：
   ```xml
   <item quantity="zero">...</item>
   <item quantity="one">...</item>
   <item quantity="two">...</item>
   <item quantity="few">...</item>
   <item quantity="many">...</item>
   <item quantity="other">...</item>
   ```
5. **相关 API**：
   - `getQuantityString(id, quantity, formatArgs...)`
   - `getQuantityText(id, quantity)`
6. **Lint 规则**：
   - `ImpliedQuantity`：缺少 `other` → **运行时崩溃**（`Resources.NotFoundException`）。
   - `PluralsCandidate`：`quantity` 类型不适用于该语言。
7. **面试话术**："**复数规则是 CLDR（Unicode 通用语言资料库）定义的，Android 内置了这些规则。所以不能用字符串拼接表达数量，必须用 plurals。**"

**读者问：翻译文本变长导致 UI 溢出，有哪些应对策略？**

**AI答：**

1. **文本长度差异**：
   - 德语通常比英语长 **30%**；
   - 俄语长 **20~30%**；
   - 阿拉伯语、芬兰语可能长 **50%**；
   - 中文通常比英语**短**（但字符宽度不同）。
2. **应对策略**：
   | 策略 | 做法 |
   | --- | --- |
   | **弹性布局** | 用 `ConstraintLayout` / `weight` / `wrap_content`，避免固定宽度 |
   | **限制行数 + 省略** | `maxLines` + `ellipsize="end"` |
   | **自适应字号** | `autoSizeTextType="uniform"`（API 26+） |
   | **高质量断行** | `breakStrategy="high_quality"` + `hyphenationFrequency="normal"`（API 23+） |
   | **预留空间** | 按钮宽度用 `minWidth` + `wrap_content`；给可能变长的文案预留额外空间 |
   | **可滚动容器** | 内容区放在 `NestedScrollView` 里，溢出可滚动而非裁剪 |
   | **图文化** | 关键信息用图标代替长文案 |
3. **伪本地化测试**（必做）：
   ```bash
   adb shell am broadcast -a com.android.intent.action.SET_LOCALE --es com.android.intent.extra.LOCALE en-XA
   ```
   - `en-XA`：文本加长 30%（英文字母 → 带框变长）
   - `en-XB`：加长 100%
   - `ar-XA`：模拟阿拉伯语（RTL + 长度）
4. **Compose**：
   ```kotlin
   Text(
       text = stringResource(R.string.title),
       maxLines = 2,
       overflow = TextOverflow.Ellipsis,
       style = MaterialTheme.typography.titleMedium.copy(
           autoSize = TextAutoSize.StepBased(12.sp, 20.sp, 1.sp)
       )
   )
   ```
5. **自动化测试**：用 Espresso 检查 `getEllipsisCount() == 0`。
6. **面试话术**："**多语言适配的核心是『永远给文本留弹性』——固定宽度是最反模式的。可伸缩 + 伪本地化测试是标配。**"

**读者问：Android 13+ 的应用内语言切换怎么实现？和 `LocaleManager` 是什么关系？**

**AI答：**

1. **Android 13（API 33）原生支持 per-app language**：
   - 系统设置里会出现"应用语言"选项（前提是 App 声明了 `android:localeConfig`）。
   - 应用内可通过 `LocaleManager` 编程式设置。
2. **实现步骤**：
   ```xml
   <!-- res/xml/locales_config.xml -->
   <locale-config xmlns:android="http://schemas.android.com/apk/res/android">
       <locale android:name="en-US" />
       <locale android:name="zh-CN" />
       <locale android:name="ja-JP" />
   </locale-config>
   ```
   ```xml
   <!-- AndroidManifest.xml -->
   <application android:localeConfig="@xml/locales_config" ... />
   ```
   ```kotlin
   // 编程式切换
   LocaleManager.getInstance(context).applicationLocales =
       LocaleList(Locale.forLanguageTag("zh-CN"))
   ```
3. **自动生成 locale_config**：
   ```kotlin
   // build.gradle.kts
   android {
       androidResources {
           generateLocaleConfig = true   // 扫描 strings.xml 自动生成
       }
   }
   ```
4. **低版本兼容**：AndroidX AppCompat 1.6+ 提供统一 API：
   ```kotlin
   AppCompatDelegate.setApplicationLocales(LocaleListCompat.forLanguageTags("zh-CN"))
   ```
   - 内部在 API 33+ 走 `LocaleManager`，低版本用 `Activity.recreate()` 重建。
   - 需要 `AppLocalesMetadataHolderService` 声明（在 AppCompat 1.6+ 中自动处理）。
5. **注意**：
   - 切换后 Activity 会重建，状态需要通过 `rememberSaveable` / `ViewModel` 保存；
   - 用 `LocaleManager.applicationLocales`（而不是 `systemLocales`）——后者是系统级设置，应用无权修改。
   - `LocaleList` 可以有多个，按优先级排列，资源匹配时逐个尝试。
6. **面试话术**："**Android 13 把『应用语言』提升为系统特性，App 只需声明 `localeConfig` 就能在系统设置里出现语言选项。AndroidX 提供了向下兼容的统一 API。**"
