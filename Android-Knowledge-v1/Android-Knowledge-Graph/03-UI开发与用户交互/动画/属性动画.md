# 属性动画

## 一句话定义

属性动画（Property Animation）是 Android 3.0（API 11）引入的动画体系，核心区别是：**它改变的是对象的属性值（而不是绘制效果）**，因此既能作用于任意 Java 对象（不限于 View），也能真正改变 View 的位置尺寸并触发重新布局，而 View 动画只能"欺骗性地"改变绘制。

## 核心原理

### 1. 三大动画分类

| 分类 | API | 改变什么 | 能否改变真实属性 | 能否作用于非 View |
| --- | --- | --- | --- | --- |
| **View 动画（补间动画）** | `Animation` / `TranslateAnimation` / `RotateAnimation` / `ScaleAnimation` / `AlphaAnimation` | **只改变绘制**（Canvas 的 transform） | ❌ **属性值不变** | ❌ 只能 View |
| **属性动画** | `ValueAnimator` / `ObjectAnimator` / `AnimatorSet` | **改变属性值** | ✅ | ✅ 任意对象 |
| **帧动画** | `AnimationDrawable`（`<animated-list>`） | 逐帧替换图片 | — | — |

**View 动画的致命缺陷**：

```kotlin
// View 动画：只是"画的时候挪一下"
view.startAnimation(TranslateAnimation(0f, 100f, 0f, 0f, 1000))
// view.getX() 仍然是 0！属性没变！
// 点击事件仍然在原位置触发（视觉上错位）

// 属性动画：真的改属性
ObjectAnimator.ofFloat(view, "translationX", 0f, 100f).start()
// view.getX() 变成 100，属性真实变化
```

> 面试点：**View 动画不改变属性，属性动画改变属性。** 这决定了它们在布局、点击命中、后续动画衔接上的根本差异。

### 2. 属性动画的四大特点

1. **改变属性而不是绘制**：
   - 改 `translationX` → View 真的"移动"了，触摸命中区域也跟着移动；
   - 改 `scaleX` → 缩放是真实的布局属性，`getWidth()` 不变但视觉尺寸变。
2. **支持插值器（Interpolator）与加速器（Accelerator）**：
   - 插值器把"时间进度"映射为"属性进度"（如 `AccelerateInterpolator` 加速、`OvershootInterpolator` 回弹）。
   - 加速器改变**动画时长**（如 `CycleAccelerator` 让动画重复 N 遍）。
   - View 动画只有插值器，没有加速器。
3. **可作用于任意对象**：
   ```kotlin
   // 自定义对象的属性
   class Point { var x = 0f; var y = 0f }
   ObjectAnimator.ofObject(point, PointEvaluator(), startPoint, endPoint).start()
   ```
4. **真正的动画类体系**：
   - `Animator`：基类
   - `ValueAnimator`：数值动画（核心）
   - `ObjectAnimator`：对象属性动画（`ValueAnimator` 的子类）
   - `AnimatorSet`：组合多个动画
   - `TimeInterpolator` / `Interpolator`：插值器
   - `TypeEvaluator`：类型求值器

### 3. ValueAnimator 的源码流程

```text
ValueAnimator.start()
   │
   ├─ initAnimation()  → 初始化（时间、插值器、持续时间）
   ├─ addAnimationCallback(...)  → 注册帧回调
   └─ notifyStartListeners() → 通知 onAnimationStart
         │
         ▼
AnimationHandler（一个 ThreadLocal 的 Handler，绑定到 vsync）
   │
   ├─ Choreographer.postFrameCallback(mFrameCallback)
   │
   ▼
每一帧（VSync 到来）：
Choreographer.doFrame
   └─ AnimationHandler.doAnimationFrame(frameTimeNanos)
         └─ mFrameCallback.onAnimationFrame(frameTimeNanos)
               └─ animateValue(frameTimeNanos)
                     ├─ 计算 fraction = (now - mStartTime) / duration
                     ├─ 若 mRunning && fraction >= 1 → endAnimation()
                     └─ 否则：
                          ├─ fraction = mInterpolator.getInterpolation(fraction)
                          ├─ mCurrentFraction = fraction
                          ├─ mAnimation.setCurrentFraction(fraction)  → 触发 onAnimationUpdate
                          └─ invalidate()  → 请求重绘
```

**`AnimationHandler` 的特殊之处**：

```java
private static class AnimationHandler {
    // 用 ThreadLocal 保证每个线程有自己的 Handler（防止多线程动画互相影响）
    private static final ThreadLocal<AnimationHandler> sThreadLocal =
            ThreadLocal.withInitial(AnimationHandler::new);

    private final Choreographer mChoreographer = Choreographer.getInstance();
    private final Choreographer.FrameCallback mFrameCallback = this::doAnimationFrame;

    public void doAnimationFrame(long frameTimeNanos) {
        // 1. 处理动画结束
        // 2. 处理动画开始（mAnimationStates 队列）
        // 3. 计算并设置动画值
        AnimationRecord record = mAnimationStates.get(i);
        ...
        record.animation.setCurrentFraction(animationFraction);
        ...
    }
}
```

> **面试点**：属性动画**不是**用 `Handler.postDelayed` 定时轮询，而是**注册到 `Choreographer` 的 vsync 回调**——所以它与屏幕刷新率对齐，天然 60/120fps 同步，且不会在应用退到后台时无意义地跑。

**关键源码片段（ValueAnimator）**：

```java
void animateValue(long frameTimeMillis) {
    float fraction = getFraction(frameTimeMillis);
    mCurrentFraction = fraction;
    mAnimation.setCurrentFraction(fraction);   // → 触发 onAnimationUpdate
}

float getFraction(long millisSinceStart) {
    if (mDuration == 0) return 1.0f;
    float fraction = (millisSinceStart - mStartTime) / (float) mDuration;
    // 处理 repeat（循环）
    if (mRepeatCount > 0 && millisSinceStart > mStartTime + (1 + mRepeatCount) * mDuration) {
        fraction = 0.0f;
    }
    return clamp(fraction, 0.0f, 1.0f);
}
```

### 4. 插值器（Interpolator）与加速器（Accelerator）

**插值器的作用**：把**时间进度**（0~1）映射为**动画进度**（可以是任意值）。

```text
输入：linear fraction (0.0 → 1.0)
  │
  ▼  Interpolator.getInterpolation(fraction)
输出：animated fraction（可能 >1 或 <0，用于超调）
```

| 插值器 | 效果 | 公式 |
| --- | --- | --- |
| `LinearInterpolator` | 匀速 | `f(t) = t` |
| `AccelerateInterpolator` | 加速 | `f(t) = t²` |
| `DecelerateInterpolator` | 减速 | `f(t) = 1 - (1-t)²` |
| `AccelerateDecelerateInterpolator` | 两头慢中间快 | `f(t) = cos((t+1)π) / 2 + 0.5` |
| `OvershootInterpolator` | 末尾超调回弹 | `f(t) = t-1` 的正弦变换 |
| `AnticipateInterpolator` | 开头反向预备 | 先往回缩一点再走 |
| `BounceInterpolator` | 弹跳 | 多次衰减的抛物线 |
| `PathInterpolator`（API 21+） | 自定义路径 | 用 SVG path 定义曲线 |
| `FastOutSlowInInterpolator` | **MD 规范推荐** | Material 标准曲线 |

**加速器（Accelerator）**：改变**动画时长**，让动画重复 N 次。

```java
public interface TimeAccelerator {
    float accelerate(float time, float duration);
    float getDuration();
}

// 示例：让动画跑 3 遍
public class CycleAccelerator implements TimeAccelerator {
    private final int mCycles;
    public CycleAccelerator(int cycles) { mCycles = cycles; }
    @Override public float accelerate(float time, float duration) {
        return time * mCycles / duration;
    }
    @Override public float getDuration() { return 1; }
}
```

> **区别**：插值器改变**进度曲线**（形状），加速器改变**总时长/次数**（尺度）。View 动画**没有加速器**。

**`PathInterpolator` 自定义曲线**（API 21+）：

```xml
<!-- res/animator/fast_out_slow_in.xml -->
<pathInterpolator
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:pathData="M0,0 L0.4,0 L0.2,1 L1,1" />
```

```kotlin
val interpolator = PathInterpolator(0.2f, 0f, 0f, 1f)   // FastOutSlowIn
```

### 5. ObjectAnimator 与自定义属性

```kotlin
// 1. 直接改 View 的属性
ObjectAnimator.ofFloat(view, View.TRANSLATION_X, 0f, 100f).start()

// 2. 链式调用（Kotlin 扩展）
view.animate()
    .translationX(100f)
    .alpha(0f)
    .setDuration(300)
    .setInterpolator(FastOutSlowInInterpolator())
    .withEndAction { /* ... */ }
    .start()

// 3. 自定义属性：需要 setter/getter
ObjectAnimator.ofFloat(myObject, "progress", 0f, 1f).start()

// 4. 自定义 View 的属性（推荐用 ViewPropertyAnimator 或自定义 property）
ObjectAnimator.ofFloat(this, "ringProgress", 0f, 1f).start()
```

**自定义 View 支持属性动画的关键**：

```kotlin
class RingProgressView : View {
    var ringProgress: Float = 0f
        set(value) {
            field = value
            invalidate()      // 属性变了 → 重绘
        }

    // 可选：告诉动画系统如何在需要时设置属性（Kotlin 属性会生成 getRingProgress/setRingProgress）
}
```

> **Kotlin 属性的坑**：Kotlin 的 `var` 会生成 `getXxx()` / `setXxx()`，**符合 Java 反射规范**，所以 `ObjectAnimator.ofFloat(view, "ringProgress", ...)` 可以直接工作。

### 8. 动画与掉帧

```text
一帧的预算：16.67ms（60Hz） / 8.33ms（120Hz）

一帧内的时间分配：
  ┌────────────────────────────────────────┐
  │ 1. 动画更新（属性计算）                  │  ~1ms
  │ 2. 测量 + 布局（measure/layout）        │  ~2-8ms  ← 布局动画易超
  │ 3. 绘制录制（onDraw → DisplayList）     │  ~2-4ms
  │ 4. GPU 执行 + 合成                      │  独立线程
  └────────────────────────────────────────┘
```

**导致掉帧的常见原因**：

| 原因 | 说明 | 解决 |
| --- | --- | --- |
| **`onDraw` 中创建对象** | GC 抖动 | 提前创建，提到字段 |
| **布局动画触发 `requestLayout`** | 每帧重新测量整棵树 | 改用 `translationX`（只重绘） |
| **`onAnimationUpdate` 中做重活** | 主线程阻塞 | 拆分到子线程 |
| **同时运行多个动画** | 竞争主线程 | 减少动画数量 |
| **低端机 GPU 不足** | 绘制指令过多 | 简化绘制、减少 overdraw |

**重要优化：区分"布局动画"和"属性动画"**：

```kotlin
// ❌ 每帧触发布局重算
ObjectAnimator.ofInt(layoutParams, "width", 100, 500).start()

// ✅ 只重绘
ObjectAnimator.ofFloat(view, "scaleX", 1f, 5f).start()
```

### 9. Compose 动画 API

| API | 用途 | 特点 |
| --- | --- | --- |
| `animate*AsState` | 简单数值动画 | **状态驱动**，目标值变化时自动动画 |
| `Animatable` | 精细控制 | 提供 `animateTo` / `snapTo` / `spring` |
| `Transition` | 状态过渡 | `updateTransition` + `AnimatedContent` |
| `AnimatedVisibility` | 显示/隐藏动画 | 组合 enter/exit |
| `AnimatedContent` | 内容切换动画 | 基于 `Transition` |
| `rememberInfiniteTransition` | 无限循环动画 | `infiniteRepeatable` |
| `Crossfade` | 淡入淡出 | 简化的内容切换 |
| `animateColorAsState` / `animateDpAsState` | 颜色/尺寸动画 | 类型化版本 |

**`animate*AsState`**：

```kotlin
val alpha by animateFloatAsState(
    targetValue = if (pressed) 0.5f else 1f,
    animationSpec = tween(durationMillis = 300),
    label = "alpha"
)
```

> ⚠️ `animate*AsState` 是**状态驱动**的：动画播放期间如果 targetValue 再变，会**从当前值平滑过渡到新目标**（不会重启）。

**`Animatable`**：

```kotlin
val animatable = remember { Animatable(0f) }
LaunchedEffect(Unit) {
    animatable.animateTo(
        targetValue = 1f,
        animationSpec = spring(dampingRatio = 0.5f, stiffness = 300f)
    )
}
// 手动打断
LaunchedEffect(Unit) { animatable.animateTo(0.5f) }
```

**`Transition` + `AnimatedContent`**：

```kotlin
val transition = updateTransition(
    targetState = currentPage,
    label = "pageTransition"
)

transition.AnimatedContent { page ->
    when (page) {
        0 -> HomeContent()
        1 -> DetailContent()
    }
}
```

**`AnimatedVisibility`**：

```kotlin
AnimatedVisibility(
    visible = showToolbar,
    enter = fadeIn() + expandVertically(),
    exit = fadeOut() + shrinkVertically()
) {
    TopBar()
}
```

**`rememberInfiniteTransition`**：

```kotlin
val transition = rememberInfiniteTransition(label = "pulse")
val scale by transition.animateFloat(
    initialValue = 1f,
    targetValue = 1.2f,
    animationSpec = infiniteRepeatable(
        animation = tween(800, easing = FastOutSlowInEasing),
        repeatMode = RepeatMode.Reverse
    ),
    label = "scale"
)
```

### 10. Material Motion 缓动曲线

| 曲线 | 参数 | 用途 |
| --- | --- | --- |
| `FastOutSlowIn` | `(0.2, 0, 0, 1)` | **默认推荐**，通用 |
| `FastOutLinearIn` | `(0.4, 0, 1, 1)` | 加速退出（元素消失） |
| `LinearOutSlowIn` | `(0, 0, 0.2, 1)` | 减速进入（元素出现） |
| `LinearInOut` | `(0, 0, 1, 1)` | 匀速（进度条等） |
| `Standard` | `(0.2, 0, 0, 1)` | Material 3 标准曲线 |

**时长规范**：

| 类型 | 时长 |
| --- | --- |
| 微交互（小反馈） | 100~200ms |
| 页面内元素转场 | 200~300ms |
| 全屏页面转场 | 300~400ms |
| 大型转场（共享元素） | 400~500ms |

## 代码示例

### 1. 完整的属性动画示例（View 体系）

```kotlin
class DetailActivity : AppCompatActivity() {

    private lateinit var imageView: ImageView
    private lateinit var titleView: TextView
    private var titleAnimator: ObjectAnimator? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_detail)

        imageView = findViewById(R.id.iv_cover)
        titleView = findViewById(R.id.tv_title)

        // 1. 进场动画：位移 + 透明度 + 缩放并行
        imageView.apply {
            alpha = 0f
            translationY = 200f
            scaleX = 0.9f
            scaleY = 0.9f
            animate()
                .alpha(1f)
                .translationY(0f)
                .scaleX(1f)
                .scaleY(1f)
                .setDuration(450)
                .setInterpolator(FastOutSlowInInterpolator())
                .start()
        }

        // 2. 延迟出现的标题
        titleView.apply {
            alpha = 0f
            translationY = 60f
            animate()
                .alpha(1f)
                .translationY(0f)
                .setStartDelay(120)
                .setDuration(350)
                .setInterpolator(FastOutSlowInInterpolator())
                .start()
        }

        // 3. 循环脉冲动画
        val pulse = ObjectAnimator.ofFloat(imageView, "scaleX", 1f, 1.05f).apply {
            repeatCount = ValueAnimator.INFINITE
            repeatMode = ValueAnimator.REVERSE
            duration = 1200
        }
        pulse.start()
    }

    /** 4. 数值动画驱动自定义进度 */
    private fun animateProgress(from: Float, to: Float, onUpdate: (Float) -> Unit) {
        ValueAnimator.ofFloat(from, to).apply {
            duration = 800
            interpolator = DecelerateInterpolator()
            addUpdateListener { anim ->
                onUpdate(anim.animatedValue as Float)
            }
            addListener(object : AnimatorListenerAdapter() {
                override fun onAnimationEnd(animation: Animator) {
                    onUpdate(to)   // 结束时校正到精确值，避免浮点误差
                }
            })
            start()
        }
    }
}
```

### 2. 自定义 View 支持属性动画

```kotlin
class RingProgressView @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null,
    defStyleAttr: Int = 0
) : View(context, attrs, defStyleAttr) {

    private val paint = Paint(Paint.ANTI_ALIAS_FLAG)
    private val rect = RectF()

    /** 属性名必须符合 getXxx/setXxx 规范，ObjectAnimator 才能通过反射找到 */
    var ringProgress: Float = 0f
        set(value) {
            field = value
            invalidate()          // 属性变化 → 请求重绘
        }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)
        val radius = min(width, height) / 2f - paint.strokeWidth / 2
        rect.set(width / 2f - radius, height / 2f - radius, width / 2f + radius, height / 2f + radius)
        canvas.drawArc(rect, -90f, 360f * ringProgress, false, paint)
    }

    /** 提供便捷的动画方法 */
    fun animateProgress(target: Float, duration: Long = 1000) {
        ObjectAnimator.ofFloat(this, "ringProgress", ringProgress, target).apply {
            this.duration = duration
            interpolator = FastOutSlowInInterpolator()
            start()
        }
    }
}
```

### 4. 自定义插值器

```kotlin
/** 带回弹的弹性插值器 */
class ElasticOutInterpolator(private val tension: Float = 0.5f) : Interpolator {
    override fun getInterpolation(input: Float): Float {
        if (input == 0f || input == 1f) return input
        val pow = 2.0.pow(10.0 * (input - 1.0)).toFloat()
        return (pow * Math.sin((input - 1.075) * (2 * Math.PI) / 0.3).toFloat()).let {
            1f - it * tension
        }
    }
}

/** 使用 PathInterpolator（API 21+）定义曲线 */
```

### 5. Compose 动画完整示例

```kotlin
@Composable
fun ComposeAnimationDemo() {
    var expanded by remember { mutableStateOf(false) }
    var count by remember { mutableIntStateOf(0) }

    // 1. animate*AsState：状态驱动的简单动画
    val size by animateDpAsState(
        targetValue = if (expanded) 200.dp else 100.dp,
        animationSpec = spring(dampingRatio = 0.6f, stiffness = 300f),
        label = "size"
    )
    val color by animateColorAsState(
        targetValue = if (expanded) MaterialTheme.colorScheme.primary
                      else MaterialTheme.colorScheme.secondary,
        label = "color"
    )

    // 2. Animatable：精细控制 + 可打断
    val offset = remember { Animatable(0f) }
    LaunchedEffect(expanded) {
        offset.animateTo(if (expanded) 300f else 0f, tween(400, easing = FastOutSlowInEasing))
    }

    // 3. Transition：状态过渡
    val transition = updateTransition(targetState = count % 2, label = "countTransition")

    // 4. 无限动画
    val infinite = rememberInfiniteTransition(label = "infinite")
    val pulse by infinite.animateFloat(
        initialValue = 1f,
        targetValue = 1.1f,
        animationSpec = infiniteRepeatable(tween(900), RepeatMode.Reverse),
        label = "pulse"
    )

    Column(
        modifier = Modifier.fillMaxSize().padding(16.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
        verticalArrangement = Arrangement.spacedBy(16.dp)
    ) {
        // AnimatedVisibility：显示/隐藏
        AnimatedVisibility(visible = expanded) {
            Text("展开的内容", style = MaterialTheme.typography.titleMedium)
        }

        Box(
            modifier = Modifier
                .size(size)
                .graphicsLayer {
                    translationX = offset.value
                    scaleX = pulse
                    scaleY = pulse
                }
                .background(color, RoundedCornerShape(16.dp))
                .clickable { expanded = !expanded }
        )

        // AnimatedContent：内容切换
        Button(onClick = { count++ }) {
            transition.AnimatedContent(targetState = count % 2) { state ->
                Text(if (state == 0) "偶数" else "奇数")
            }
        }
    }
}
```

### 6. Compose 弹簧动画 vs 补间动画

```kotlin
// 补间：时长固定，曲线可控
val tweenValue by animateFloatAsState(
    targetValue = target,
    animationSpec = tween(durationMillis = 300, easing = FastOutSlowInEasing),
    label = "tween"
)

// 弹簧：物理模拟，时长不固定，自然
val springValue by animateFloatAsState(
    targetValue = target,
    animationSpec = spring(
        dampingRatio = 0.5f,     // <1 有回弹，1 临界阻尼，>1 过阻尼
        stiffness = Spring.StiffnessMedium
    ),
    label = "spring"
)

// 弹簧关键参数
// dampingRatio: 0.3f → 明显回弹；0.5f → 轻微回弹；1f → 无回弹；2f → 迟滞
// stiffness: 越大越快
```

## 常见问题 / 面试要点

**读者问：View 动画和属性动画有什么区别？什么时候必须用属性动画？**

**AI答：**

1. **本质区别**：
   | | View 动画 | 属性动画 |
   | --- | --- | --- |
   | 改变 | **Canvas 的绘制变换** | **对象的属性值** |
   | 属性值 | **不变**（`getX()` 仍是原值） | **真实改变** |
   | 作用对象 | 只能是 View | 任意对象 |
   | 触发重绘 | 只重绘 | 重绘（`invalidate`）/ 重布局（`requestLayout`） |
   | 插值器 | 有 | 有 |
   | 加速器 | **无** | 有 |
2. **必须用属性动画的场景**：
   - **改变 View 的位置/尺寸**并希望布局真正变化（如展开详情、折叠列表）。
   - **需要点击热区跟随动画**（View 动画期间点击位置错位）。
   - **对非 View 对象做动画**（自定义数值、颜色、路径进度）。
   - **需要动画状态可保存可恢复**。
   - **需要与手势连续衔接**（跟手拖拽后松手 fling）。
3. **View 动画仍适用的场景**（历史遗留）：
   - 简单的淡入淡出/位移（不关心属性值）；
   - 与 `AnimationUtils.loadAnimation` 加载的 XML 动画（老代码）。
4. **常见坑**：
   - 用 View 动画做位移后，后续的 `getX()` 判断全错；
   - `ViewAnimationUtils.createAnimation()`（API 21+）返回 `Animator` 而非 `Animation`，是新 API 但同样**只改绘制**。
5. **面试话术**："**View 动画改的是『画出来的样子』，属性动画改的是『对象本身』。需要真实属性就用属性动画。**"

---

**读者问：属性动画的四大特点是什么？`AnimationHandler` 的帧回调机制是怎样的？**

**AI答：**

1. **四大特点**：
   - **改变属性而非绘制**：属性真变，触摸命中跟着变。
   - **支持插值器 + 加速器**：插值器改曲线形状，加速器改时长/次数（View 动画只有插值器）。
   - **可作用于任意对象**：配合 `TypeEvaluator` 甚至能动画 `Point`、`Path`。
   - **完整的动画类体系**：`Animator` / `ValueAnimator` / `ObjectAnimator` / `AnimatorSet`。
2. **`AnimationHandler` 机制**：
   - 它是一个**内部类 + `ThreadLocal`**（每个线程一个实例，防止多线程互相干扰）。
   - 它持有 `Choreographer`，通过 `postFrameCallback` 注册帧回调。
   - **每帧**：`doAnimationFrame` → 计算 fraction → `mInterpolator.getInterpolation()` → `animation.setCurrentFraction()` → 触发 `onAnimationUpdate` → `invalidate()`。
   - **关键**：属性动画**注册在 `Choreographer` 的 vsync 回调上**，而不是 `Handler.postDelayed` 定时轮询 → 与屏幕刷新率对齐，后台不跑，60/120fps 自适应。
3. **动画时长与帧的关系**：属性动画是**基于时间**的（`SystemClock.uptimeMillis()`），所以掉帧时它会"跳过"中间帧而不是变慢。
4. **面试话术**："**属性动画的驱动源是 `Choreographer` 的 vsync 回调，不是定时器，所以它天生与屏幕刷新率对齐。**"

---

**读者问：插值器和加速器有什么区别？常见的插值器有哪些？**

**AI答：**

1. **区别**：
   - **插值器（Interpolator / TimeInterpolator）**：把**时间进度**映射为**动画进度**。输入 `[0,1]`，输出可任意（超调时 >1 或 <0）。**改变形状**。
   - **加速器（TimeAccelerator）**：改变**动画总时长**。典型实现 `CycleAccelerator` 让动画重复 N 遍。**改变尺度**。
   - **View 动画只有插值器，没有加速器**。
2. **常用插值器**：
   | 名称 | 效果 | 典型场景 |
   | --- | --- | --- |
   | `LinearInterpolator` | 匀速 | 进度条、无物理含义的位移 |
   | `AccelerateInterpolator` | 加速 | 元素退场 |
   | `DecelerateInterpolator` | 减速 | 元素进场、滚动停止 |
   | `AccelerateDecelerateInterpolator` | 两头慢中间快 | 通用（默认感觉） |
   | `OvershootInterpolator` | 末尾超调 | 强调性反馈（弹窗弹出） |
   | `AnticipateInterpolator` | 开头反向预备 | 蓄力感 |
   | `BounceInterpolator` | 弹跳 | 卡通效果 |
   | `FastOutSlowInInterpolator` | MD 标准 | **Material 规范推荐** |
   | `PathInterpolator` | 自定义路径 | 精细定制曲线（API 21+） |
3. **Material 曲线参数**：
   ```text
   FastOutSlowIn     (0.2, 0, 0, 1)     通用
   FastOutLinearIn   (0.4, 0, 1, 1)     加速离场
   LinearOutSlowIn   (0, 0, 0.2, 1)     减速进场
   ```
4. **面试话术**："**插值器管『怎么走』（曲线），加速器管『走多久』（时长）。Material 规范推荐 FastOutSlowIn。**"

---

**读者问：动画为什么会掉帧？怎么排查和优化？**

**AI答：**

1. **一帧的预算**：60Hz = 16.67ms，90Hz = 11.1ms，120Hz = 8.33ms。超了就掉帧。
2. **一帧内的工作**：
   ```text
   动画属性更新 → measure → layout → onDraw 录制 → RenderThread 执行
   ```
3. **常见原因与排查**：
   | 原因 | 表现 | 排查工具 |
   | --- | --- | --- |
   | `onDraw` 中 new 对象 | GC 频繁、帧耗时尖刺 | Memory Profiler、Allocation Tracking |
   | 布局动画触发 `requestLayout` | 每帧 measure/layout 超时 | Systrace 看 `measure`/`layout` 段 |
   | `onAnimationUpdate` 做重活 | 主线程阻塞 | Systrace 看主线程 |
   | 过度绘制（overdraw） | GPU 压力 | GPU Overdraw 调试（开发者选项） |
   | 主线程被其他任务占用 | 随机长帧 | Perfetto / System Trace |
   | 复杂布局层级 | measure 慢 | Layout Inspector |
4. **优化手段**：
   - **`onDraw` 中不 new 对象**（Paint/Path/RectF 提前创建）。
   - **用 `translationX` 而不是改 `width`**：前者只重绘，后者每次都重新测量布局。
   - **动画回调里只做必要的计算**，重的放子线程。
   - **减少同时运行的动画数量**。
   - **`postInvalidateOnAnimation()`** 替代 `invalidate()`，与 vsync 对齐。
   - **降级动画**：低性能设备关闭复杂动画（`ValueAnimator.areAnimatorsEnabled()`）。
5. **面试话术**："**掉帧 90% 是主线程被占满。用 Systrace 看是 measure、layout 还是 onDraw 段超时，然后对症下药。**"

---

**读者问：怎么让动画不中断？比如用户连续点击、或手势被打断？**

**AI答：**

1. **属性动画的默认行为**：新动画启动时，旧的会**被取消**（`onAnimationCancel`）。对于"目标值型"动画（如 `animateFloatAsState`），这是**期望行为**：从当前值平滑过渡到新目标。
2. **想要"抢占式"（新动画立刻接管）**：
   - `ObjectAnimator` 天然如此：新 `start()` 会取消旧的（同一属性）。
   - 需要"排队"时用 `AnimatorSet.playSequentially`。
3. **手势与动画衔接（跟手拖拽 + 松手回弹）**：
   ```kotlin
   // 用 Animatable 保持连续性
   val offset = remember { Animatable(0f) }
   // 拖拽中直接 snapTo
   scope.launch { offset.snapTo(newOffset) }
   // 松手后 animateTo
   scope.launch { offset.animateTo(target, spring(...)) }
   ```
   `Animatable` 的价值就在这里：**动画可以被"打断并从当前值继续"**。
4. **View 体系的做法**：
   - 监听 `onAnimationCancel` 保存当前值；
   - 新动画从当前值开始（`ObjectAnimator.ofFloat(view, "x", view.translationX, target)`）；
   - 或使用 `ViewPropertyAnimator`（自动从当前值继续）。
5. **Compose 的 `animate*AsState` 特点**：target 变化时**从当前动画值继续**到新目标，天然不中断。
6. **动画被打断的系统场景**：
   - Activity 进入后台 → 动画暂停（`onAnimationPause` 由 `Animator` 的 `pause()` 触发）；
   - 屏幕旋转 → Activity 重建 → 动画丢失（需保存状态）。
   - View 分离（`onDetachedFromWindow`）→ 动画应 `cancel()` 以免泄漏。
7. **面试话术**："**要『不中断』，就要用可打断的动画载体：Compose 用 `Animatable`，View 用『从当前值开始新动画』。**"

---

**读者问：Compose 的动画 API 有哪些？怎么选？**

**AI答：**

1. **选型表**：
   | 需求 | 用什么 |
   | --- | --- |
   | 状态驱动的简单数值（alpha、size、color） | `animateFloatAsState` / `animateDpAsState` / `animateColorAsState` |
   | 需要精细控制、打断、手势衔接 | `Animatable` |
   | 两个状态之间的过渡 | `updateTransition` + `AnimatedContent` |
   | 显示/隐藏 | `AnimatedVisibility`（enter / exit） |
   | 无限循环（加载、脉冲） | `rememberInfiniteTransition` |
   | 简单的内容淡入淡出 | `Crossfade` |
   | 弹簧物理效果 | `spring(dampingRatio, stiffness)` |
2. **`animate*AsState` vs `Animatable`**：
   - `animate*AsState`：**状态驱动**，改 target 就会动画；不能手动打断/查询进度；适合"UI 状态"型动画。
   - `Animatable`：**命令驱动**，可以 `animateTo` / `snapTo`，暴露 `value` 供手势读取；适合"交互型"动画。
3. **`spring` vs `tween`**：
   - `tween`：时长固定，曲线可控 → 需要精确时长的场景（转场）。
   - `spring`：物理模拟，时长不定（到达目标才停）→ 手势回弹、自然运动。
   - `dampingRatio`：<1 回弹、1 临界、>1 过阻尼；`stiffness` 越大越快。
4. **`Transition` 的价值**：多个属性由**同一个状态**驱动时，用 `transition.AnimatedContent { state -> ... }`，避免多个独立动画不同步。
5. **Compose 动画的优势**：**天然支持自动打断**（`Animatable` 会被新动画取消并从当前值继续），这是 View 体系很难做到的。
6. **面试话术**："**Compose 动画按『驱动方式』分：状态驱动用 `animate*AsState`，命令驱动用 `Animatable`，状态过渡用 `Transition`。**"

---

**读者问：`ObjectAnimator` 动画自定义属性时有什么坑？Kotlin 的 `var` 能直接用吗？**

**AI答：**

1. **反射查找规则**：`ObjectAnimator` 通过 `Property` 对象或反射查找：
   - 优先找 `setXxx(T)` / `getXxx()` 方法（**Java Bean 规范**）；
   - 找不到则找**字段**（`mXxx` 或 `xxx`）；
   - 都没有 → 抛 `NoSuchMethodException` / `IllegalArgumentException`。
2. **Kotlin 的 `var`**：
   ```kotlin
   var ringProgress: Float = 0f
       set(value) { field = value; invalidate() }
   ```
   Kotlin 会生成 `getRingProgress()` / `setRingProgress(float)` → **完全符合 Java Bean 规范** → `ObjectAnimator.ofFloat(view, "ringProgress", 0f, 1f)` 可直接工作。
3. **坑**：
   - **属性名必须精确**：`"ringProgress"` vs `"ring_progress"` vs `"mRingProgress"` —— 写错运行时才崩（`IllegalArgumentException: Could not find setter/getter`）。
   - **必须调用 `invalidate()`**：只改字段不改绘制 → 看不到变化。**这是最常见的坑**。
   - **`val`（只读属性）不能动画**：没有 setter。
   - **Java 侧的自定义属性**：同样要写标准 getter/setter。
4. **更安全的方式（现代做法）**：
   ```kotlin
   // 显式提供 Property 对象，避免反射
   val PROGRESS = object : FloatProperty<MyView>("progress") {
       override fun get(view: MyView): Float = view.progress
       override fun setValue(view: MyView, value: Float) { view.progress = value }
   }
   ObjectAnimator.ofFloat(myView, PROGRESS, 0f, 1f).start()
   ```
   或 Kotlin 的 `androidx.core` 扩展：
   ```kotlin
   ObjectAnimator.ofFloat(view, View.TRANSLATION_X, 0f, 100f)   // 用内置常量
   ```
5. **面试话术**："**反射找 setter 是最常见的崩溃点；关键是命名规范 + setter 里一定要 invalidate。**"
