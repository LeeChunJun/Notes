# 转场动画

## 一句话定义

转场动画是**界面之间切换时的过渡效果**：Activity 之间的进出、Fragment 的替换、列表项的展开、共享元素（Shared Element）的形变。Android 提供了三套机制：**系统级 Activity 转场**（`overridePendingTransition` / `ActivityOptions`）、**布局/元素转场**（`TransitionManager` + `Transition`）、**Material Motion**（Shared Axis / Container Transform / Fade Through）以及 **Lottie**（JSON 驱动的矢量动画）。

## 核心原理

### 1. 转场动画的分类

```text
转场动画
├── 1. Activity 转场（系统级）
│     ├── overridePendingTransition（简单位移/淡入淡出）
│     ├── ActivityOptions / ActivityOptionsCompat（自定义动画、共享元素）
│     └── overrideActivityTransition（API 34+，跨任务转场）
│
├── 2. Fragment 转场
│     ├── setCustomAnimations（进入/退出/弹入/弹出的 res/anim）
│     ├── setTransition（Transition 对象）
│     └── TransitionManager.beginDelayedTransition + beginTransition
│
├── 3. 布局/元素转场（Transition 框架）
│     ├── TransitionManager.beginDelayedTransition(root, transition)
│     ├── TransitionSet（组合多个 Transition）
│     ├── 共享元素：ChangeBounds + ChangeTransform + ChangeImageTransform
│     └── 自动检测：LayoutTransition（布局变化时动画）
│
├── 4. Material Motion（规范化的转场模式）
│     ├── Shared Axis（共享轴：X / Y / Z）
│     ├── Container Transform（容器变换：卡片展开为详情页）
│     └── Fade Through（淡入淡出）
│
└── 5. Lottie（JSON 驱动的矢量动画）
```

### 2. Activity 转场动画

**基础做法**：

```kotlin
// 启动 Activity
startActivity(Intent(this, DetailActivity::class.java))
// 在 onCreate 之后、onResume 之前设置
overridePendingTransition(R.anim.slide_in_right, R.anim.slide_out_left)
```

> ⚠️ **`overridePendingTransition` 必须在 `startActivity()` 之后调用**（且在 `onResume` 之前），否则不生效。它是**静态方法**（实际是 `Activity` 的静态重载），也可以写成 `overridePendingTransition(...)`（Kotlin 中是成员方法形式）。

**自定义 Activity 转场动画（`ActivityOptions`）**：

```xml
<!-- res/anim/slide_in_right.xml -->
<set xmlns:android="http://schemas.android.com/apk/res/android"
    android:interpolator="@android:interpolator/decelerate_cubic">
    <translate android:fromXDelta="100%p" android:toXDelta="0" android:duration="300" />
    <alpha android:fromAlpha="0.0" android:toAlpha="1.0" android:duration="300" />
</set>
```

```xml
<!-- res/anim/slide_out_left.xml -->
<set xmlns:android="http://schemas.android.com/apk/res/android"
    android:interpolator="@android:interpolator/accelerate_cubic">
    <translate android:fromXDelta="0" android:toXDelta="-30%p" android:duration="300" />
    <alpha android:fromAlpha="1.0" android:toAlpha="0.6" android:duration="300" />
</set>
```

**`ActivityOptions` 的自定义动画**：

```kotlin
val options = ActivityOptions.makeCustomAnimation(
    this,
    R.anim.slide_in_right,      // 进入动画
    R.anim.slide_out_left       // 退出动画
)
startActivity(intent, options.toBundle())
```

**`overrideActivityTransition`（API 34 / Android 14）**：

```kotlin
// API 34+：支持跨 Activity、跨 Task 的转场动画（如"画中画"、桌面模式）
overrideActivityTransition(
    R.anim.slide_in_right,      // 进入
    R.anim.slide_out_left,      // 退出
    ActivityOptions.makeCustomAnimation(this, R.anim.fade_in, R.anim.fade_out)
)
```

> 与 `overridePendingTransition` 的区别：后者只影响"当前 Activity 与新 Activity"，前者（API 34+）可以影响**系统级的跨任务转场**（如任务切换时的"关闭应用"动画）。

### 3. Fragment 转场

```kotlin
supportFragmentManager.commit {
    setCustomAnimations(
        R.anim.slide_in_right,    // 进入
        R.anim.fade_out,         // 退出
        R.anim.fade_in,          // 弹回（pop 时的进入）
        R.anim.slide_out_left    // 弹出（pop 时的退出）
    )
    replace(R.id.container, DetailFragment())
    addToBackStack(null)
}
```

**顺序很重要**：`setCustomAnimations(enter, exit, popEnter, popExit)`。

**Transition 对象方式**：

```kotlin
supportFragmentManager.commit {
    setTransition(TransitionSet()
        .addTransition(ChangeBounds())
        .addTransition(ChangeTransform())
        .setDuration(300)
    )
    replace(R.id.container, DetailFragment())
}
```

### 4. TransitionManager 与 Transition 框架

**原理**：

```text
TransitionManager.beginDelayedTransition(sceneRoot, transition)
   │
   ├─ 1. 记录 sceneRoot 下所有 View 的"起始状态"（位置、尺寸、可见性）
   ├─ 2. 你修改 UI（addView / removeView / setVisibility / 改 LayoutParams）
   └─ 3. TransitionManager 在下一帧（Choreographer）比较"结束状态"与"起始状态"
         └─ 生成对应的 Transition 动画并播放
```

**`Transition` 的子类**：

| Transition | 作用 |
| --- | --- |
| `ChangeBounds` | 位置/尺寸变化 |
| `ChangeTransform` | 旋转/缩放变化 |
| `ChangeImageTransform` | ImageView 的 scaleType/矩阵变化 |
| `ChangeClipBounds` | 裁剪区域变化 |
| `ChangeBounds` + `ChangeTransform` + `ChangeImageTransform` | **共享元素的标准组合** |
| `Visibility` / `Fade` / `Slide` | 可见性变化 |
| `AutoTransition` | 自动选择合适的 Transition 组合 |
| `TransitionSet` | 组合多个 Transition |
| `Explode` | 网格中所有子 View 爆炸式进出（API 21+） |

**基本用法**：

```kotlin
val root = binding.root

// 必须在修改 UI 之前调用
TransitionManager.beginDelayedTransition(
    root,
    AutoTransition().apply {
        duration = 300
        interpolator = FastOutSlowInInterpolator()
    }
)

// 然后修改 UI
binding.detailsGroup.visibility = View.VISIBLE
```

**`LayoutTransition`**（View 增删时自动动画）：

```xml
<!-- res/layout/anim/layout_transition.xml -->
<layoutAnimation xmlns:android="http://schemas.android.com/apk/res/android"
    android:animationOrder="normal"
    android:delay="15%">
    <slide android:duration="300" android:fromXDelta="0" android:toXDelta="100%p" />
    <fade android:duration="300" />
</layoutAnimation>
```

```kotlin
// 代码设置
val transition = LayoutTransition()
transition.enableTransitionType(LayoutTransition.CHANGING)
container.layoutTransition = transition
```

### 5. 共享元素（Shared Element）

**原理**：把两个 Activity 中的两个 View 视为"同一个元素"，系统会在转场时**自动插值**它的位置、尺寸、旋转、缩放。

**必须一致的三个属性**：
1. **transitionName 相同**；
2. **在转场期间都可见**（不能在 `onPause` 里就设 `GONE`）；
3. **不能是同一个 Activity 内的两个 View**（共享元素只跨 Activity 有效；Fragment 内可用 `FragmentTransaction.setSharedElement`。

```xml
<!-- 列表项 -->
<ImageView
    android:id="@+id/iv_thumbnail"
    android:transitionName="image_$id"
    ... />

<!-- 详情页 -->
<ImageView
    android:id="@+id/iv_detail"
    android:transitionName="image_$id"
    ... />
```

```kotlin
// 启动
val extras = IntentCompat.getParcelableExtra(intent, "image", Bitmap::class.java)
val options = ActivityOptionsCompat.makeSceneTransitionAnimation(
    this,
    binding.ivThumbnail,       // 起始 View
    "image_$id"                // transitionName
)
startActivity(intent, options.toBundle())
```

**注意事项**：
- `transitionName` 必须在 Activity 中**唯一**。
- API 21+ 才支持共享元素。
- 用 `ChangeBounds` + `ChangeTransform` + `ChangeImageTransform` 组合效果最好。

### 6. Material Motion 三大模式

| 模式 | 适用场景 | 组成 |
| --- | --- | --- |
| **Shared Axis（共享轴）** | 两个界面在同一轴上滑动 | 位置/透明度插值 |
| **Container Transform（容器变换）** | 卡片/按钮展开为完整页面 | 容器尺寸 + 圆角 + 位置 + 内容淡入 |
| **Fade Through（淡入淡出）** | 同一位置的完全不同内容 | 先淡出 + 缩放，再淡入 + 放大 |
| **Emphasized（强调）** | 交互反馈 | 缩放脉冲 |

**Shared Axis（X 轴）实现**：

```kotlin
// 进入：向 +X 滑动 + 淡入
slideInRight = ObjectAnimator.ofFloat(view, "translationX", width.toFloat(), 0f)
fadeIn = ObjectAnimator.ofFloat(view, "alpha", 0f, 1f)
// 退出：向 -X 滑动 + 淡出
slideOutLeft = ObjectAnimator.ofFloat(view, "translationX", 0f, -width.toFloat() * 0.3f)
fadeOut = ObjectAnimator.ofFloat(view, "alpha", 1f, 0f)
```

**Fade Through 实现**：

```kotlin
// 旧内容：淡出 + 缩小
outAlpha = ObjectAnimator.ofFloat(oldView, "alpha", 1f, 0f)
outScale = ObjectAnimator.ofFloat(oldView, "scaleX", 1f, 0.92f)
// 新内容：淡入 + 放大
inAlpha = ObjectAnimator.ofFloat(newView, "alpha", 0f, 1f)
inScale = ObjectAnimator.ofFloat(newView, "scaleX", 0.92f, 1f)
// 用 AnimatorSet 编排时序
```

**Compose 的 Material Motion**：

```kotlin
// Shared Axis：AnimatedContent + slideIn / slideOut
val slideIn = slideInHorizontally(tween(300, easing = FastOutSlowInEasing)) { it / 4 }
val slideOut = slideOutHorizontally(tween(300, easing = FastOutSlowInEasing)) { -it / 4 }

AnimatedContent(
    targetState = state,
    transitionSpec = {
        (slideIn + fadeIn(tween(220))) togetherWith (slideOut + fadeOut(tween(90)))
    },
    label = "sharedAxis"
) { state ->
    Text("Content for $state")
}
```

### 7. ActivityOptions 与 ActivityOptionsCompat

```text
ActivityOptions（API 16+）
  ├─ makeCustomAnimation(context, enterResId, exitResId)
  ├─ makeScaleUpAnimation(view, startX, startY, startWidth, startHeight)
  ├─ makeScaleDownAnimation(view, startX, startY, startWidth, startHeight)
  ├─ makeThumbnailAnimation(view, thumbnail, startX, startY)
  ├─ makeSceneTransitionAnimation(...)   → 场景转场（共享元素）
  └─ makeRemoteAnimation(...)             → 远程转场（跨设备）

ActivityOptionsCompat（AndroidX）
  └─ 提供向后兼容的封装 + makeSceneTransitionAnimation 的旧 API 兼容
```

**缩放动画（任务切换缩略图）**：

```kotlin

    binding.avatar.left,
    binding.avatar.top,
    binding.avatar.width,
    binding.avatar.height
)
startActivity(intent, options.toBundle())
```

**缩略图动画**：


### 8. Lottie

**Lottie** 是 Airbnb 开源的库，用 **JSON（由 After Effects 导出的 Bodymovin 格式）** 驱动矢量动画。

```kotlin
// 1. 添加依赖
// implementation("com.airbnb.android:lottie-compose:6.4.0")

// 2. Compose 中使用
val composition by rememberLottieComposition(LottieCompositionSpec.Asset("animations/check.json"))
LottieAnimation(
    composition = composition,
    iterations = LottieConstants.IterateForever,
    isPlaying = isPlaying,
    modifier = Modifier.size(120.dp)
)
```

```kotlin
// 3. View 体系
val animationView = findViewById<LottieAnimationView>(R.id.lottie)
animationView.setAnimation("animations/check.json")
animationView.playAnimation()
animationView.addAnimatorListener(object : AnimatorListenerAdapter() {
    override fun onAnimationEnd(animation: Animator) { /* ... */ }
})
```

**优点**：
- 矢量、体积小、可动态换肤；
- 设计师直接产出 JSON，无需开发写动画代码；
- 支持交互（`addValueCallback` 动态控制进度）。

**缺点**：
- 大型 JSON 解析耗时（建议放到后台或用 `setCacheComposition`）；
- 复杂动画的性能不如原生属性动画。

### 10. 常见坑：状态栏颜色闪烁

**现象**：Activity 转场时，状态栏颜色在两个 Activity 之间**跳变**（闪一下白色/黑色）。

**原因**：
1. 两个 Activity 的主题中 `android:statusBarColor` 不一致；
2. 转场过程中旧 Activity 先消失、新 Activity 后绘制，中间系统回退到默认状态栏颜色；
3. Android 12+ 的 **SplashScreen（启动画面）** 的 `windowSplashScreenBackground` 与实际主题不一致。

**解决方案**：

```xml
<!-- 1. 两个 Activity 使用相同的状态栏颜色 -->
<style name="Theme.MyApp" parent="Theme.Material3.DayNight.NoActionBar">
    <item name="android:statusBarColor">@color/status_bar</item>
    <item name="android:windowLightStatusBar">true</item>
</style>
```

```kotlin
// 2. Edge-to-edge（API 35+ 强制 edge-to-edge）
WindowCompat.setDecorFitsSystemWindows(window, false)
```

```kotlin
// 3. 使用 SplashScreen API 时保持一致
installSplashScreen()
splashScreen.setKeepOnScreenCondition { false }
```

```kotlin
// 4. 共享元素转场时，禁用系统的状态栏动画
val options = ActivityOptionsCompat.makeSceneTransitionAnimation(this, pair)
options.makeSceneTransitionAnimation()  // API 34+ 可指定是否影响系统栏
```

**其它常见坑**：

| 坑 | 原因 | 解决 |
| --- | --- | --- |
| `overridePendingTransition` 不生效 | 调用时机不对 | 在 `startActivity` 后、`onResume` 前调用 |
| 共享元素"闪烁" | 两个 View 的 `transitionName` 不一致或内容不同 | 统一 name 与内容 |
| 共享元素位置错乱 | 起始 View 在转场开始前被移出屏幕 | 保持可见 |
| Fragment 转场无效 | 用了 `show/hide` 而非 `replace` | `show/hide` 不支持转场 |
| 动画卡顿 | XML 动画里用了 `layout` 属性（触发重布局） | 改用 `translation` |
| Lottie 首帧卡顿 | 主线程解析 JSON | 提前预加载 / `setCacheComposition` |

### 2. 共享元素转场

```kotlin
class ListActivity : AppCompatActivity() {

    companion object {
        const val EXTRA_IMAGE = "extra_image"
        const val EXTRA_ID = "extra_id"
    }

    private fun openDetail(item: Item, sharedImage: ImageView) {
        val intent = Intent(this, DetailActivity::class.java).apply {

}
```

```kotlin
class DetailActivity : AppCompatActivity() {

        super.onCreate(savedInstanceState)

            supportStartPostponedEnterTransition()   // 图片加载完再开始转场

}
```

### 3. TransitionManager 实现列表项展开

```kotlin
class ExpandableAdapter : RecyclerView.Adapter<VH>() {

    inner class VH(val binding: ItemBinding) : RecyclerView.ViewHolder(binding.root) {
        fun toggle() {
            val root = binding.root
            // 1. 先调用 beginDelayedTransition（在修改 UI 之前）

        }
```

```kotlin
@Composable
fun FadeThroughDemo() {
    var selected by remember { mutableStateOf(Tab.HOME) }

    AnimatedContent(
        targetState = selected,
        transitionSpec = {
            // 旧内容先淡出（快），新内容后淡入（慢）
            val fadeOutSpec = tween<Float>(durationMillis = 90, easing = LinearEasing)
            val fadeInSpec = tween<Float>(durationMillis = 220, easing = LinearOutSlowInEasing)

            val scaleIn = scaleIn(initialScale = 0.92f, targetScale = 1f, animationSpec = fadeInSpec)

        },
        label = "fadeThrough"
    ) { tab ->
        when (tab) {
            Tab.HOME -> HomeContent()
            Tab.SETTINGS -> SettingsContent()
        }
    }
}
```

### 6. Compose NavHost 转场

```kotlin
@Composable
fun AppNavHost(navController: NavHostController) {
    NavHost(
        navController = navController,
        startDestination = "home",
        enterTransition = {
            slideInHorizontally(tween(300, easing = FastOutSlowInEasing)) { fullWidth -> fullWidth / 4 } +
                fadeIn(tween(300))
        },
        exitTransition = {
            slideOutHorizontally(tween(300, easing = FastOutSlowInEasing)) { fullWidth -> -fullWidth / 4 } +
                fadeOut(tween(300))
        },
        popEnterTransition = {
            slideInHorizontally(tween(300, easing = FastOutSlowInEasing)) { fullWidth -> -fullWidth / 4 } +
                fadeIn(tween(300))
        },
        popExitTransition = {
            slideOutHorizontally(tween(300, easing = FastOutSlowInEasing)) { fullWidth -> fullWidth / 4 } +
                fadeOut(tween(300))
        }
    ) {
        composable("home") { HomeScreen(navController) }
        composable("detail/{id}") { backStackEntry ->
            DetailScreen(id = backStackEntry.arguments?.getString("id").orEmpty())
        }
    }
}
```

## 常见问题 / 面试要点

**读者问：Activity 转场动画怎么实现？`overridePendingTransition` 有什么坑？**

**AI答：**

1. **基本用法**：
   ```kotlin
   startActivity(intent)
   overridePendingTransition(R.anim.enter_anim, R.anim.exit_anim)
   ```
2. **四个动画参数**：
   - `enterAnim`：**新** Activity 进入时的动画。
   - `exitAnim`：**旧** Activity 退出时的动画。
   - `popEnterAnim` / `popExitAnim`：`overrideActivityTransition`（API 34+）支持返回时的动画。
3. **坑**：
   - **调用时机**：必须在 `startActivity()` **之后**调用；且要在 `onResume()` 之前（否则不生效）。
   - **设置后又被 `ActivityOptions` 覆盖**：`makeSceneTransitionAnimation` 会替换 `overridePendingTransition` 的设置。
   - **动画文件类型**：必须是 `res/anim/`（不是 `res/animator/`）。`res/animator/` 是属性动画，不能用于 Activity 转场。
   - **同时设置两处**：在 A 的 `onCreate` 和 `onPause` 都调用，会导致"进出场都用同一个动画"的怪异效果。正确做法是：**A 设置进入/退出，B 在 `onCreate` 设置进入**。
4. **API 34+ 的 `overrideActivityTransition`**：签名不同，支持跨任务转场（任务切换动画）。
5. **Compose 中的替代**：`NavHost` 的 `enterTransition` / `exitTransition`（Compose Navigation 2.7+）。
6. **面试话术**："**`overridePendingTransition` 是『静态』的 —— 它描述的是一对 Activity 之间的进出场，调用必须在 `startActivity` 之后。**"

---

**读者问：Material Motion 的 Shared Axis、Container Transform、Fade Through 分别用在哪？怎么实现？**

**AI答：**

1. **Shared Axis（共享轴）**：
   - **场景**：两个**同级**页面之间的切换（如 Tab 切换、列表 → 详情）。
   - **视觉**：两个页面沿同一轴（X 或 Y）错位滑动，**淡入淡出**同时进行；Z 轴则是缩放 + 淡出淡入。
   - **实现**：进入的 View 从 +X 滑入并淡入（`slideInHorizontally + fadeIn`）；退出的 View 往 -X 滑出 30% 并淡出。
   - **Compose**：`AnimatedContent` + `slideInHorizontally/slideOutHorizontally` + `fadeIn/fadeOut`。
2. **Container Transform（容器变换）**：
   - **场景**：**小元素 → 大页面**（卡片展开为详情、Fab 展开为表单、缩略图变全屏）。
   - **视觉**：容器的**尺寸、圆角、位置**连续插值，内部内容淡入淡出。
   - **实现**：`ChangeBounds` + `ChangeTransform` + 圆角动画 + 内容 `Fade`；Compose 中用 `SharedTransitionLayout`。
3. **Fade Through（淡入淡出）**：
   - **场景**：**同一位置**但内容完全不同的切换（如 Tab 内容替换、加载 → 空态）。
   - **视觉**：旧内容**先淡出并缩小**（~90ms），新内容**后淡入并放大**（~220ms）；**不移动位置**。
   - **实现**：`AnimatedContent` + `fadeIn`/`fadeOut` + `scaleIn`/`scaleOut`，用 `togetherWith` 编排。
4. **对比记忆**：
   ```text
   Shared Axis     → 平级页面切换，有位移
   Container Transform → 小变大，容器形变
   Fade Through    → 同位替换，无位移
   ```
5. **面试话术**："**MD3 把转场归纳为三个模式：Shared Axis 管平级切换，Container Transform 管小界面展开成大界面，Fade Through 管原位内容替换。**"

---

**读者问：共享元素（Shared Element）怎么实现？为什么有时会闪烁或错位？**

**AI答：**

1. **原理**：系统识别两个 Activity 中 `transitionName` 相同的 View，把它们视为**同一个元素的两个状态**，转场时自动插值 `bounds`、`transform`、`imageTransform`。
2. **实现步骤**：
   - 两个 View 设置**相同的 `android:transitionName`**（Activity 内唯一）。
   - 启动时用 `ActivityOptionsCompat.makeSceneTransitionAnimation(this, startView, "name")`。
   - 目标 Activity 中设置相同的 name。
   - **转场期间两个 View 都必须可见**（不要在 `onPause` 里设 `GONE`）。
3. **常见问题**：
   | 问题 | 原因 | 解决 |
   | --- | --- | --- |
   | **闪烁** | 两个 View 的内容不同（图片还没加载好） | 用 `supportPostponeEnterTransition()` + `doOnPreDraw { supportStartPostponedEnterTransition() }` 等待图片就绪 |
   | **位置错乱** | 起始 View 用了 `scaleType="centerCrop"` 且目标不同 | 统一 `scaleType`，或用 `ChangeImageTransform` |
   | **不生效** | API < 21，或 name 不一致 | 检查 API 与 name |
   | **多个元素冲突** | name 重复 | 用 `image_$id` 动态命名保证唯一 |
   | **圆角丢失** | 没有 `ChangeClipBounds` | 加入 `ChangeClipBounds` Transition |
4. **Compose 的方案**：`SharedTransitionLayout` + `Modifier.sharedElement`（Compose 1.7+，仍为实验性 API）。
5. **面试话术**："**共享元素转场的关键是 `transitionName` 一致 + 内容就绪 + 可见性保持。闪烁基本都是因为图片没加载完就开始转场了。**"

---

**读者问：Fragment 转场动画怎么写？`setCustomAnimations` 和 `TransitionManager` 有什么区别？**

**AI答：**

1. **`setCustomAnimations`（View 动画）**：
   ```kotlin
   supportFragmentManager.commit {
       setCustomAnimations(R.anim.enter, R.anim.exit, R.anim.popEnter, R.anim.popExit)
       replace(R.id.container, DetailFragment())
       addToBackStack(null)
   }
   ```
   - 四个参数顺序：**进入 / 退出 / 弹回进入 / 弹出退出**。
   - 使用 `res/anim/` 的 **View 动画**（`TranslateAnimation` 等）。
   - **注意**：`show()` / `hide()` **不支持**转场，必须用 `replace()` + `addToBackStack()`。
2. **`setTransition`（Transition 对象）**：
   ```kotlin
   supportFragmentManager.commit {
       setTransition(TransitionSet()
           .addTransition(ChangeBounds())
           .addTransition(ChangeTransform())
           .setDuration(300))
       replace(R.id.container, DetailFragment())
   }
   ```
   - 使用 `android.transition` 框架，效果更好（能处理共享元素、尺寸插值）。
3. **`TransitionManager`**：在 Fragment 事务**外部**对整个容器做布局转场：
   ```kotlin
   TransitionManager.beginDelayedTransition(container, AutoTransition().setDuration(300))
   supportFragmentManager.commit { replace(...) }
   ```
4. **对比**：
   | | `setCustomAnimations` | `Transition` / `TransitionManager` |
   | --- | --- | --- |
   | 动画类型 | View 动画（只改绘制） | 属性动画（改真实属性） |
   | 支持共享元素 | ❌ | ✅ |
   | 尺寸变化 | 视觉假的 | 真实插值 |
   | 适用范围 | Fragment 事务 | 任意 View 树变化 |
5. **面试话术**："**`setCustomAnimations` 是 View 动画版，`Transition` 是属性动画版。`Transition` 才能做共享元素。**"

---

**读者问：转场动画时状态栏颜色闪烁怎么解决？**

**AI答：**

1. **原因**：
   - 两个 Activity 的 `android:statusBarColor` 不一致；
   - 转场时旧 Activity 先销毁、新 Activity 还没绘制，**中间态**系统用了默认状态栏颜色；
   - Android 12+ 的 SplashScreen 背景与实际主题不一致也会闪。
2. **解决方案**：
   - **统一主题**：两个 Activity 用**同一个** Theme（或至少状态栏相关属性一致）。
   - **Edge-to-edge**（推荐）：API 35+ 强制 edge-to-edge；低版本用 `WindowCompat.setDecorFitsSystemWindows(window, false)`，状态栏透明 → 就没有"颜色切换"的问题。
   - **SplashScreen 一致**：`installSplashScreen()` 后设置 `windowSplashScreenBackground` 与主题背景一致。
   - **共享元素转场**：转场期间系统栏也可能参与动画，需要检查 `transitionName` 冲突。
   - **设置 `android:windowDrawsSystemBarBackgrounds`**（API 21+）并统一 `statusBarColor`。
3. **代码示例**：
   ```kotlin
   override fun onCreate(savedInstanceState: Bundle?) {
       super.onCreate(savedInstanceState)
       WindowCompat.setDecorFitsSystemWindows(window, false)
       // 状态栏透明，图标颜色由主题控制
       WindowInsetsControllerCompat(window, window.decorView).isAppearanceLightStatusBars = true
   }
   ```
4. **其它常见转场坑**：
   - **动画卡顿**：XML 转场动画里用了 `layout` 属性 → 触发重新测量布局 → 改用 `translation`。
   - **返回动画不对**：`overridePendingTransition` 需要在 A 的 `onPause` 和 B 的 `onCreate` 各设置一次。
   - **Fragment 转场无效**：用了 `show/hide`。
5. **面试话术**："**状态栏闪烁本质是『两个 Activity 的系统栏属性不一致 + 转场中间态』。根治办法是 edge-to-edge + 统一主题。**"

**读者问：Lottie 是什么？什么时候用 Lottie，什么时候用原生动画？**

**AI答：**

1. **Lottie**：Airbnb 开源的库，用 **JSON（After Effects 通过 Bodymovin 插件导出）** 描述矢量动画，运行时解析并渲染。
2. **优点**：
   - **设计师可直接产出**，开发不写动画代码；
   - **矢量**，任意分辨率清晰，体积小；
   - 支持**动态换肤**（改颜色）、**交互**（`addValueCallback` 控制进度）、**文字替换**。
3. **缺点**：
   - 大型 JSON **解析耗时**（主线程解析会卡顿）；
   - 复杂动画性能不如原生属性动画；
   - 需要设计协作规范（导出规范：不用表达式、不用遮罩某些特性）。
4. **选型建议**：
   | 场景 | 选择 |
   | --- | --- |
   | 加载指示、点赞、开关等**简单反馈** | **原生动画**（更轻、更可控） |
   | 复杂插画、品牌形象、引导页 | **Lottie** |
   | 需要跟随手势的连续交互 | **原生动画**（`Animatable`） |
   | 骨架屏 / 加载状态 | 原生动画或 `AnimatedVisibility` |
5. **性能建议**：
   ```kotlin
   // 提前在非主线程预加载，或缓存 composition
   val composition by rememberLottieComposition(LottieCompositionSpec.Asset("a.json"))
   ```
   - 避免在列表 item 中频繁解析同一 JSON（用 `LottieCompositionSpec` 缓存）。
6. **面试话术**："**Lottie 是『设计驱动动画』的方案，原生属性动画是『逻辑驱动动画』的方案。前者省开发时间，后者性能和可控性更好。**"
