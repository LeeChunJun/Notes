## 二、HTTP 请求

### 2.1 基本用法

```ts
import { http } from '@kit.NetworkKit';
import { BusinessError } from '@kit.BasicServicesKit';

class ApiClient {
  private baseUrl: string = 'https://api.example.com';

  async get<T>(path: string, params?: Record<string, string | number>): Promise<T> {
    const request = http.createHttp();
    try {
      const res = await request.request(
        `${this.baseUrl}${path}`,
        {
          method: http.RequestMethod.GET,
          expectDataType: http.HttpDataType.STRING,   // ★ 必须指定
          header: {
            'Content-Type': 'application/json',
            'Authorization': `Bearer ${AppStorage.get<string>('token')}`
          },
          extraData: {
            // query 参数
          }
        }
      );

      if (res.responseCode !== 200) {
        throw new Error(`HTTP ${res.responseCode}`);
      }

      const data = res.result as string;
      return JSON.parse(data) as T;
    } catch (err) {
      const e = err as BusinessError;
      console.error(`请求失败: ${e.code} ${e.message}`);
      throw err;
    } finally {
      request.destroy();     // ★ 释放
    }
  }

  async post<T>(path: string, body: Object): Promise<T> {
    const request = http.createHttp();
    try {
      const res = await request.request(`${this.baseUrl}${path}`, {
        method: http.RequestMethod.POST,
        expectDataType: http.HttpDataType.STRING,
        header: { 'Content-Type': 'application/json' },
        extraData: JSON.stringify(body)
      });
      return JSON.parse(res.result as string) as T;
    } finally {
      request.destroy();
    }
  }
}
```

### 2.2 关键参数说明

```ts
interface HttpRequestOptions {
  method: http.RequestMethod;        // GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS/TRACE/CONNECT
  expectDataType: http.HttpDataType; // ★ STRING / OBJECT / ARRAY_BUFFER / OBJECT
  extraData?: string | Object | ArrayBuffer;  // 请求体
  header?: Object;                    // 请求头
  readTimeout?: number;              // 默认 60000ms
  connectTimeout?: number;           // 默认 60000ms
  usingCache?: boolean;              // 是否使用缓存
  usingProtocolCache?: boolean;      // 协议层缓存
  usingProxy?: boolean;              // ★ 代理
  priority?: http.RequestPriority;   // 优先级
  sslVerifyOptions?: http.SSLVerifyOptions;  // 证书校验
  trace?: http.HttpTrace;            // 链路追踪
}
```

**`expectDataType` 必须显式指定**（鸿蒙的要求）：
- `STRING` —— 返回字符串
- `OBJECT` —— 自动 JSON 解析为对象
- `ARRAY_BUFFER` —— 二进制

> **面试话术**："鸿蒙 HTTP 的 `expectDataType` 是必填项，这是为了避免隐式的 JSON 解析开销和歧义，也是 AOT 优化的一部分。开发时必须显式声明返回类型，是很多从 Android 迁移过来会踩的第一个坑。"

### 2.4 证书校验（安全面试题）

```ts
// 默认严格校验（推荐）
const res = await request.request(url, {
  method: http.RequestMethod.GET,
  expectDataType: http.HttpDataType.STRING,
  sslVerifyOptions: {
    verifyPeer: true,          // ★ 校验服务端证书
    verifyHostname: true       // ★ 校验主机名
  }
});

// ★ 信任用户 CA（仅调试用，线上禁用）
const certMgr = http.createCertManager();
certMgr.addTrustedCert(cert);
const request = http.createHttp(certMgr);
```

> **面试话术**："HarmonyOS 默认强制校验 HTTPS 证书，包括对系统 CA 和用户 CA 的区分处理。生产环境必须保持 verifyPeer 和 verifyHostname 都为 true，绝不能为了解决自签名证书问题而在生产代码里关闭校验——这是最常见的合规和安全问题。"

## 三、WebSocket

```ts
import { webSocket } from '@kit.NetworkKit';
import { BusinessError } from '@kit.BasicServicesKit';

class WebSocketClient {
  private ws: webSocket.WebSocket | undefined = undefined;

  connect(url: string): void {
    this.ws = webSocket.createWebSocket();
    this.ws.on('open', (): void => {
      console.info('WebSocket 已连接');
      this.send({ type: 'login', token: 'xxx' });
    });
    this.ws.on('message', (event: webSocket.MessageEvent): void => {
      console.info(`收到消息: ${event.data}`);
      // WebSocket 收到的是 ArrayBuffer
      const text = new TextDecoder().decode(event.data as ArrayBuffer);
    });
    this.ws.on('close', (code: number, reason: string): void => {
      console.info(`连接关闭: ${code} ${reason}`);
      // ★ 断线重连
    });
    this.ws.on('error', (err: BusinessError): void => {
      console.error(`WebSocket 错误: ${err.code}`);
    });

    this.ws.connect(url);
  }

  send(data: Object): void {
    this.ws?.send(JSON.stringify(data));
  }

  close(): void {
    this.ws?.close({ code: 1000, reason: 'normal' });
  }
}
```

**断线重连（带指数退避）**：
```ts
private reconnectCount: number = 0;

private tryReconnect(): void {
  this.reconnectCount++;
  const delay = Math.min(1000 * Math.pow(2, this.reconnectCount), 30000);
  setTimeout(() => this.connect(this.url), delay);
}
```

## 四、后台任务框架

### 4.1 三类后台任务对比

| 类型 | API | 触发方式 | 典型场景 |
|---|---|---|---|
| **短时任务** | `backgroundTaskManager.requestShortTimeAccess` | 立即（申请后几秒内） | 短暂计算、跳转其他 App 前保存 |
| **长时任务** | `backgroundTaskManager.startLongRunningTask` | 立即，需声明类型 | 音乐播放、导航、下载、录音 |
| **延迟任务** | `workScheduler.startWork` | **系统按条件调度**（不保证准时） | 定期同步、清理缓存 |
| **代理提醒** | `reminderAgentManager.publishReminder` | **定时**（用户可见的闹钟） | 闹钟、待办提醒 |
| **后台数据传���** | `backgroundDataTransfer` | 立即 | 大文件上传/下载 |

### 4.2 短时任务


### 4.3 长时任务

```ts
export default class EntryAbility extends UIAbility {
```

| 类型 | 说明 | 需要的权限/通知 |
|---|---|---|
| `dataTransfer` | 数据传输 | — |
| `audioPlayback` | 音频播放 | 需在控制中心显示 |
| `audioRecording` | 音频录制 | 麦克风权限 |
| `location` | 位置服务 | 位置权限 |
| `dataSync` | 数据同步 | — |

> **面试话术**："HarmonyOS 的后台模型是声明式的：你要告诉系统'我在做什么类型的长期后台工作'，系统据此决定资源配额并向用户透明展示。播放音乐必须有通知，这是通过长时任务的 notificationId 与 Notification 联动实现的，用户能看到'正在播放'。这跟 Android 的前台服务通知是同一个思路，但鸿蒙把类型枚举化了，管控更细。"

### 4.4 延迟任务 WorkScheduler

```ts
import { workScheduler } from '@kit.BackgroundTasksKit';
import { BusinessError } from '@kit.BasicServicesKit';

// 1. 配置（在 module.json5 的 abilities 里声明）
/*
{
  "abilities": [{
    "name": "EntryAbility",
    "backgroundModes": ["dataTransfer"]
  }]
}
*/

// 2. 实现 WorkScheduler 回调
export class SyncWorker implements workScheduler.WorkScheduler {
  onStart(workRequest: object): void {
    // 执行同步任务
  }
  onStop(workRequest: object): void {
    // 任务被停止
  }
  onCancel(workRequest: object): void {
  }
}

// 3. 启动
const workInfo: workScheduler.WorkInfo = {
  id: 1234,
  urgency: workScheduler.Urgency.LOW,           // 优先级
  delay: 60 * 60 * 1000,                       // 延迟 1 小时
  repeatCycleTime: { interval: 24 * 60 * 60 * 1000 },  // 重复周期
  conditions: {                                 // ★ 触发条件
    network: 'ANY' as workScheduler.NetworkCondition,
    charging: false,
    deviceIdle: true                            // 设备空闲时
  },
  maxRunTime: 5 * 60 * 1000,                   // 最长运行 5 分钟
  workSchedulerExtensionAbility: 'com.example.myapp.SyncWorker'
};

workScheduler.startWork(workInfo, (err: BusinessError) => {
  if (err.code) {
    console.error(`延迟任务启动失败: ${err.code}`);
  }
});

// 4. 查询 / 取消
workScheduler.getWorkStatus(1234);
workScheduler.cancelWork(1234);
```

> **重要**：`WorkScheduler` **不保证执行时间**，系统会根据电量、网络、用户使用习惯综合调度。只适合"最终会执行"的场景（如夜间数据同步），不能用于精确定时。

## 五、网络层工程化设计（面试项目亮点）

### 5.1 统一响应处理

```ts
interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
}

class ApiError extends Error {
  code: number;
  constructor(code: number, message: string) {
    super(message);
    this.code = code;
  }
}

class HttpClient {
  private request: http.Http | undefined = undefined;

  async request<T>(config: RequestConfig): Promise<T> {
    const req = http.createHttp();
    try {
      const res = await req.request(config.url, {
        method: config.method ?? http.RequestMethod.GET,
        expectDataType: http.HttpDataType.STRING,
        header: this.buildHeaders(config),
        extraData: config.body ? JSON.stringify(config.body) : undefined,
        readTimeout: config.timeout ?? 15000,
        usingCache: config.useCache ?? false,
        priority: config.priority ?? http.RequestPriority.DEFAULT
      });

      // 业务错误处理
      if (res.responseCode < 200 || res.responseCode >= 300) {
        throw new ApiError(res.responseCode, `HTTP ${res.responseCode}`);
      }

      const body = JSON.parse(res.result as string) as ApiResponse<T>;
      if (body.code !== 0) {
        // 401 → 触发登录失效
        if (body.code === 401) {
          this.onUnauthorized();
        }
        throw new ApiError(body.code, body.message);
      }
      return body.data;
    } finally {
      req.destroy();
    }
  }

  private buildHeaders(config: RequestConfig): Record<string, string> {
    const headers: Record<string, string> = {
      'Content-Type': 'application/json'
    };
    const token = AppStorage.get<string>('token');
    if (token) {
      headers['Authorization'] = `Bearer ${token}`;
    }
    return headers;
  }
}
```

### 5.2 拦截器机制

```ts
interface Interceptor {
  onRequest?(config: RequestConfig): RequestConfig;
  onResponse?(response: any): any;
  onError?(error: Error): void;
}

class InterceptorManager {
  private interceptors: Interceptor[] = [];

  use(interceptor: Interceptor): void {
    this.interceptors.push(interceptor);
  }

  async run(config: RequestConfig): Promise<any> {
    for (const i of this.interceptors) {
      if (i.onRequest) config = i.onRequest(config);
    }
    return config;
  }
}
```

### 5.3 请求取消（防竞态，面试加分）

```ts
class ApiClient {
  private pending: Map<string, http.Http> = new Map();

  async search(keyword: string): Promise<Result> {
    // 同 key 的旧请求直接取消，避免竞态（旧响应覆盖新响应）
    this.cancel(keyword);

    const req = http.createHttp();
    this.pending.set(keyword, req);

    try {
      const res = await req.request(url, { /* ... */ });
      return res.result;
    } finally {
      this.pending.delete(keyword);
      req.destroy();
    }
  }

  cancel(key: string): void {
    this.pending.get(key)?.destroy();
    this.pending.delete(key);
  }
}
```

### 5.4 重试与超时

```ts
async function requestWithRetry<T>(
  fn: () => Promise<T>,
  maxRetries: number = 3
): Promise<T> {
  let lastError: Error;
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await fn();
    } catch (e) {
      lastError = e as Error;
      // 指数退避
      await new Promise(resolve => setTimeout(resolve, 1000 * Math.pow(2, i)));
    }
  }
  throw lastError;
}
```

## 六、并发与性能优化（面试高频）

### 6.1 计算密集型任务 → TaskPool

```ts
import { taskpool } from '@kit.ArkTS';

@Concurrent
function processImageChunk(data: ArrayBuffer): number {
  // 重计算逻辑
  let sum = 0;
  for (let i = 0; i < data.byteLength; i++) {
    sum += data[i];
  }
  return sum;
}

async function processData(data: ArrayBuffer): Promise<number> {
  const task = new taskpool.Task(processImageChunk, data);
  try {
    return await taskpool.execute(task, taskpool.Priority.HIGH) as number;
  } finally {
    taskpool.release(task);      // ★ 必须释放
  }
}
```

### 6.2 UI 线程卡顿的排查与解决

| 症状 | 可能原因 | 解决方案 |
|---|---|---|
| 首屏慢 | onCreate 做重活 | 延迟初始化；异步加载 |
| 列表滑动掉帧 | item 复杂 / 未懒加载 | `lazyForEach` + `cachedCount`；简化 item 层级 |
| 动画掉帧 | 主线程任务阻塞 | 把计算挪到 TaskPool |
| 复杂布局计算慢 | 大量嵌套 | 用 `GridRow` 替代嵌套 Row/Column |
| build() 频繁执行 | 状态粒度过粗 | 拆分组件，让状态更局部化 |

**ArkUI 性能优化口诀**：
1. **状态尽量下沉**（减少无效刷新范围）
2. **列表用 ForEach + key + 懒加载**
3. **复杂计算放 TaskPool**
4. **减少 build() 中的逻辑**
5. **图片用 `Image` + 缓存 + 异步解码**

### 6.3 启动优化（面试项目亮点）

```
冷启动耗时 = 进程创建 + Ability 初始化 + WindowStage 创建 + loadContent + 首帧渲染
```

优化手段：
1. **onCreate 只做必要初始化**，其余异步/延迟。
2. **首屏数据本地优先**，先渲染再请求网络。
3. **预置首屏 UI**：`loadContent` 先加载骨架，数据显示后填充。
4. **减少首屏组件层级**。
5. **AppStorage 预热**：提前初始化全局状态。

## 七、网络安全与合规

### 7.1 必须做的

1. **全站 HTTPS**，禁止明文 HTTP。
2. **证书校验**（verifyPeer/verifyHostname）。
3. **敏感数据加密存储**（密码用 KeyStore 生成的密钥加密）。

## 八、常见坑

| 坑 | 现象 | 原因 | 解决 |
|---|---|---|---|
| HTTP 请求返回 undefined | result 为空 | 忘设 `expectDataType` | 显式指定 |
| 请求卡住不返回 | 未处理异常 | 没 try/finally | 加超时与错误处理 |
| 内存泄漏 | 内存持续涨 | `http.Http` 未 destroy | finally 中 destroy |
| 后台任务不执行 | 期望准时执行 | WorkScheduler 不保证 | 用代理提醒（alarm） |
| 长时任务被杀 | 未声明类型或被用户关闭 | 缺 backgroundModes 配置 | module.json5 配 backgroundModes |
| 图片加载慢/内存高 | 大图未压缩 | 未指定尺寸 | Image 的 width/height 必设 |
| 弱网请求失败 | 无重试 | 未实现重试 | 指数退避重试 |
| token 失效未处理 | 401 反复请求 | 无拦截 | 响应拦截统一处理 |

## 十、参考答案要点

1. 必须。`expectDataType` 决定返回值的解析方式（STRING/OBJECT/ARRAY_BUFFER），显式声明避免隐式 JSON 解析的歧义和开销，是 AOT 优化的一部分。
2. 不需要。网络访问是默认开放能力，无需申请权限。只有涉及个人信息的权限（位置、相机、麦克风、通讯录等）才需要。
3. Http 对象持有底层网络资源，不 destroy 会造成资源泄漏，长时间运行会导致内存增长甚至连接耗尽。
4. 短时任务：申请后立即获得短时间的后台执行权；长时任务：声明类型（播放/导航/下载等）持续在后台运行，用户可见；延迟任务：系统按条件调度，不保证时间；代理提醒：定时且用户可见（闹钟类）。
5. conditions 支持 network、charging、deviceIdle、temperatureWarning 等条件。不保证准时，系统按电量、用户习惯调度，只保证最终会执行。
6. audioPlayback、audioRecording、location、dataTransfer、dataSync、videoPlayback 等。用户能在控制中心/设置中看到应用正在进行的活动（通过通知联动）。
7. 用 key 维护 pending 请求 Map，同 key 发起新请求前 destroy 掉旧请求；或使用 AbortController 风格的取消令牌。
8. 开启 lazyForEach + 合理 cachedCount；提供稳定唯一的 keyGenerator；简化 item 组件层级（减少嵌套），必要时用 @Reuse 保留状态。
9. HUKS（@kit.UniversalKeystoreKit），提供密钥生成、加密解密、密钥轮换等能力，密钥存储在系统 TEE 中。
10. 先读本地持久化数据立即渲染，网络数据到达后再更新；写操作先落本地并标记待同步状态，后台批量同步。落地上：Repository 层封装"本地优先 + 后台同步"，网络层做失败回退到缓存。
