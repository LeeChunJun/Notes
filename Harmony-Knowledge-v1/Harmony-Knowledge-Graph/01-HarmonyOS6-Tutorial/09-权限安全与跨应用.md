## 一、鸿蒙权限模型（与 Android 的根本差异）

### 1.1 对比表

| 维度 | Android | HarmonyOS |
|---|---|---|
| 权限声明 | `AndroidManifest.xml` | `module.json5` 的 `requestPermissions` |
| 申请时机 | 运行时动态申请 | 运行时动态申请（同类接口） |
| 系统弹窗 | 首次申请弹窗 | **不再弹窗**！用户拒绝后不再询问 |
| 用户主动授权 | 设置里手动开 | **设置里一键授权**，或**弹窗二次确认** |
| 权限粒度 | 粗（读写存储、相机） | **细**（无存储权限，文件靠 Picker） |
| 敏感权限 | user_granted / dangerous | **user_granted / system_granted** |

### 1.2 鸿蒙权限的三个等级

```
user_granted  → 用户授权（相机、麦克风、位置、通讯录…）
                 └─ 可动态申请
                 
system_granted → 系统授权（读写系统文件、输入法…）
                 └─ 需在申请时声明 reason + usedScene

ohos.permission.DEMO → 系统弹窗授权（仅系统应用）
```

### 1.3 关键特性：授权弹窗的两阶段（重点面试题）

**HarmonyOS 的授权流程与 Android 完全不同**：

```
应用调用 API 触发权限检查
        │
        ▼
系统检查用户设置
        │
   ┌────┴─────┐
   │          │
 未授权     已授权
   │          │
   ▼          ▼
【系统侧】    直接调用成功
弹出【授权弹窗】
（"允许XX应用使用相机吗？"）
   │          │
   ▼          ▼
用户点击允许 → 调用成功
用户点击拒绝 → 调用失败（抛异常）
   │
   ▼
★ 用户拒绝后，系统设置里会【永久记住拒绝】
  再次调用 API 不再弹窗，直接失败！
  → 必须引导用户去【设置】手动开启
```

> **面试话术（必背）**："HarmonyOS 的权限有两个关键差异：第一，系统不再替应用弹出二次确认框，而是由应用自己实现 UI 弹窗解释用途，用户同意后系统记录授权状态；第二，用户一旦拒绝，系统会永久记住，不会再问第二次。所以应用必须做两件事——用 `requestPermissionsFromUser` 弹自己的引导框，以及在用户已永久拒绝时（authResults 为 denied 且再次申请不弹窗）引导去设置页手动开启。这跟 Android 的'拒绝两次后不再询问、引导去设置'逻辑类似，但实现的 API 和位置不同。"

### 1.4 检测用户永久拒绝的技巧（实战坑）

```ts
import { abilityAccessCtrl, common } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';

async function checkAndRequest(context: common.UIAbilityContext): Promise<boolean> {
  const atManager = abilityAccessCtrl.createAtManager();

  // 1. 先查询当前权限状态
  const result = await atManager.checkPermissionsFromUser(context, ['ohos.permission.CAMERA']);
  const permissionStatus = result.permissions[0];

  console.info(`权限状态: ${permissionStatus}`);

  if (permissionStatus === abilityAccessCtrl.PermissionStatus.GRANTED) {
    return true;
  }

  if (permissionStatus === abilityAccessCtrl.PermissionStatus.DENIED) {
    // 可再次申请（会弹系统框）
    try {
      const requestResult = await atManager.requestPermissionsFromUser(
        context,
        ['ohos.permission.CAMERA']
      );
      const auth = requestResult.authResults[0];
      return auth === abilityAccessCtrl.GrantStatus.PERMISSION_GRANTED;
    } catch (err) {
      console.error(`申请失败: ${(err as BusinessError).code}`);
      return false;
    }
  }

  // PERMANENTLY_DENIED：已永久拒绝，只能引导去设置
  if (permissionStatus === abilityAccessCtrl.PermissionStatus.PERMANENTLY_DENIED) {
    this.showGoToSettingDialog();
    return false;
  }

  return false;
}
```

## 二、权限声明与配置

### 2.1 module.json5 中的声明

```json5
{
  "module": {
    "requestPermissions": [
      {
        "name": "ohos.permission.INTERNET",              // 网络（虽然不需要申请，但要声明吗？）
        "reason": "$string:reason_internet",
        "usedScene": {
          "abilities": ["EntryAbility"],
          "when": "inuse"
        }
      },
      {
        "name": "ohos.permission.CAMERA",
        "reason": "$string:reason_camera",               // ★ 必填：申请理由
        "usedScene": {
          "abilities": ["EntryAbility"],
          "when": "inuse"                               // inuse(使用时) / always(始终)
        }
      },
      {
        "name": "ohos.permission.READ_IMAGEVIDEO",       // system_granted 级别需要 reason
        "reason": "$string:reason_media",
        "usedScene": {
          "abilities": ["EntryAbility"],
          "when": "inuse"
        }
      }
    ]
  }
}
```

> **注意**：HarmonyOS 中 `ohos.permission.INTERNET` 通常**不需要**在 `requestPermissions` 里声明（网络是默认能力）。实际开发中网络、震动等通常不声明。

### 2.2 reason 的写法（审核要点）

**reason 是审核的关键**，必须写清楚"为什么需要"：

```json5
// resources/base/element/string.json
{
  "string": [
    {
      "name": "reason_camera",
      "value": "用于拍摄商品照片以便您发布商品信息"
    }
  ]
}
```

> **审核不通过的常见原因**：reason 写成"需要相机权限"这种无信息量的表述，或者与实际使用场景不符。审核会检查代码中是否真的调用了对应 API。

### 2.3 `usedScene.when` 的选择

| 值 | 含义 | 何时用 |
|---|---|---|
| `inuse` | 使用该功能时申请 | 绝大多数场景（推荐） |
| `always` | 始终需要 | 如后台定位导航 |

### 2.4 常见权限清单

| 权限 | 级别 | 说明 |
|---|---|---|
| `ohos.permission.CAMERA` | user_granted | 相机 |
| `ohos.permission.MICROPHONE` | user_granted | 麦克风 |
| `ohos.permission.READ_IMAGEVIDEO` | user_granted | 读取图片/视频 |
| `ohos.permission.WRITE_IMAGEVIDEO` | user_granted | 写入图片/视频 |
| `ohos.permission.READ_MEDIA` | user_granted | 读取媒体（API 12+） |
| `ohos.permission.WRITE_MEDIA` | user_granted | 写入媒体 |
| `ohos.permission.LOCATION` | user_granted | 位置 |
| `ohos.permission.APPROXIMATELY_LOCATION` | user_granted | 模糊位置 |
| `ohos.permission.READ_CONTACTS` | user_granted | 通讯录 |
| `ohos.permission.READ_CALENDAR` | user_granted | 日历 |
| `ohos.permission.GET_NETWORK_INFO` | system_granted | 网络状态 |
| `ohos.permission.KEEP_BACKGROUND_RUNNING` | system_granted | 后台运行 |

## 三、Want 跨应用调用

### 3.1 启动其他应用的 Ability

```ts
import { common, Want } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';

export default class EntryAbility extends UIAbility {
  async launchOtherApp(): Promise<void> {
    // 1. 显式 Want
    const want: Want = {
      bundleName: 'com.tencent.mm',          // 微信
      abilityName: 'com.tencent.mm.ui.LauncherUI'
    };

    try {
      await this.context.startAbility(want);
    } catch (err) {
      const e = err as BusinessError;
      if (e.code === 16000001) {
        console.error('目标应用未安装');
      } else if (e.code === 16000004) {
        console.error('目标应用不支持该操作');
      } else {
        console.error(`启动失败: ${e.code} ${e.message}`);
      }
    }
  }

  // 2. 隐式 Want（系统选择器）
  async launchImplicit(): Promise<void> {
    const want: Want = {
      action: 'ohos.want.action.editData',
      entities: ['entity.system.browsable'],
      uri: 'https://example.com'
    };
    await this.context.startAbility(want);
  }
}
```

| 错误码 | 含义 |
|---|---|
| `16000001` | 目标应用不存在（未安装） |
| `16000004` | 目标应用不支持该操作 |
| `16000006` | 目标应用没有匹配的 Ability |
| `16000007` | 参数错误 |
| `16000008` | 跨应用调用受限 |

## 四、剪贴板

```ts
import { pasteboard } from '@kit.BasicServicesKit';
import { BusinessError } from '@kit.BasicServicesKit';

async function copyText(text: string): Promise<void> {
  const pasteboard = pasteboard.getSystemPasteboard();
  const pasteData = pasteboard.createData(pasteboard.MIMETYPE_TEXT_PLAIN, text);
  pasteboard.setData(pasteData).then(() => {
    console.info('复制成功');
  }).catch((err: BusinessError) => {
    console.error(`复制失败: ${err.code}`);
  });
}

async function readText(): Promise<string> {
  const pasteboard = pasteboard.getSystemPasteboard();
  const data = await pasteboard.getData();
  const text = data.getPrimaryText();
  return text ? text.toString() : '';
}
```

**隐私保护**：读取剪贴板在 Android 12+ 有后台限制，鸿蒙也有类似限制 —— 应用只能在前台或用户主动触发时读取。

## 七、应用安全要点

### 7.1 沙箱隔离

每个应用有**独立沙箱**：
```
/data/app/el2/100/base/<bundleName>/
├──haps/entry/            应用包
├──haps/entry/files/      私有文件
├──haps/entry/cache/      缓存
├──haps/entry/database/   数据库
└──haps/entry/preferences/ 首选项
```

- 应用之间**不能直接访问**对方文件。
- 跨应用数据共享必须通过 **DataShare / Want 参数 / Picker 授权**。
- **userId 隔离**：多用户设备上，不同用户有独立的 `el2` 目录。

### 7.2 应用签名

- 每个应用必须**用开发者证书签名**。
- 调试签名（自动生成）与发布签名（手动配置）不同。
- 生产环境**必须关闭调试**、启用代码混淆。

```json5
// build-profile.json5
{
  "signingConfigs": [
    {
      "name": "release",
      "material": {
        "storeFile": "xxx.p12",
        "storePassword": "...",
        "keyAlias": "xxx",
        "keyPassword": "...",
        "signAlg": "SHA256withECDSA",
        "profile": "xxx.p7b"
      }
    }
  ],
  "buildOption": {
    "strictMode": { "caseSensitiveCheck": true, "useNormalizedOHMUrl": true }
  }
}
```

### 7.3 敏感数据保护

| 数据 | 保护方式 |
|---|---|
| 密码 | 不可逆哈希（加盐）或 HUKS 加密 |
| Token | HUKS 加密存储，或首选项 + 设备绑定 |
| 个人信息 | 最小化采集、脱敏展示 |
| 数据库 | 选择合适 SecurityLevel |
| 网络传输 | HTTPS + 证书校验 |

### 7.4 应用完整性

- **应用签名校验**防止篡改。
- **权限最小化**：不申请用不到的权限。
- **数据不外传**：遵循隐私合规要求。

## 八、隐私合规（HarmonyOS 6 重点，上架必过）

### 8.1 隐私弹窗时机（高频踩坑）

**必须在"获取个人信息之前"弹隐私协议**，而不是启动就弹，也不是用完才弹。

```
❌ 错误：App 启动 → 直接请求位置权限 → 用户拒绝 → 弹隐私协议
✅ 正确：App 启动 → 弹隐私协议 → 用户同意 → 首次用到某功能 → 再申请对应权限
```

**合规要求**：
1. 首次启动展示**隐私政策**与**用户协议**，需用户**主动勾选同意**后才能继续。
2. 弹窗必须提供**完整、可读的**政策文本链接。
3. 用户拒绝后**不能强制退出**（需提供"不同意则退出"或"不同意则不使用该功能"的路径，但二选一需合规设计）。
4. **二次弹窗时机**：不同意时再次弹出。

### 8.2 隐私相关的系统 API

```ts
import { privacyManager } from '@kit.PrivacyKit';

// 注册隐私同意状态
const result = privacyManager.addCustomizedPrivacyPolicy({
  privacyPolicyId: 'xxx',
  privacyPolicyName: '隐私政策',
  privacyPolicyContent: '...'
});

// 查询是否同意
const isAgreed = privacyManager.checkCustomizedPrivacyPolicyAgreed('xxx');
```

### 8.3 上架审核要点

- 必须提供**权限用途说明**（reason），且与实际调用一致。
- 必须有**隐私政策弹窗**且时机合规。
- **不得申请无关权限**（如只做工具类应用却申请位置权限 → 驳回）。
- 涉及**儿童/青少年**需额外合规。
- **数据安全**章节需说明数据存储位置、是否加密、是否上传服务器。

## 九、实际项目的权限封装（工程实践）

```ts
// PermissionManager.ts —— 统一封装
import { abilityAccessCtrl, common } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';
import { promptAction } from '@kit.ArkUI';

export class PermissionManager {
  private static atManager: abilityAccessCtrl.AtManager = abilityAccessCtrl.createAtManager();

  /**
   * 申请权限（带自定义说明弹窗）
   */
  static async request(
    context: common.UIAbilityContext,
    permissions: string[],
    reasonText: string
  ): Promise<boolean> {
    // 1. 查询状态
    const statusResult = await this.atManager.checkPermissionsFromUser(context, permissions);
    const statuses = statusResult.permissions;

    // 2. 全部已授权
    if (statuses.every(s => s === abilityAccessCtrl.PermissionStatus.GRANTED)) {
      return true;
    }

    // 3. 有永久拒绝的 → 引导去设置
    const hasPermanent = statuses.some(s => s === abilityAccessCtrl.PermissionStatus.PERMANENTLY_DENIED);
    if (hasPermanent) {
      this.showSettingDialog(context);
      return false;
    }

    // 4. 显示自定义说明弹窗
    const agreed = await this.showReasonDialog(context, reasonText);
    if (!agreed) return false;

    // 5. 正式申请
    try {
      const result = await this.atManager.requestPermissionsFromUser(context, permissions);
      return result.authResults.every(a => a === abilityAccessCtrl.GrantStatus.PERMISSION_GRANTED);
    } catch (err) {
      console.error(`权限申请异常: ${(err as BusinessError).code}`);
      return false;
    }
  }

  private static showReasonDialog(context: common.UIAbilityContext, text: string): Promise<boolean> {
    return new Promise((resolve) => {
      AlertDialog.show({
        title: '权限说明',
        message: text,
        primaryButton: { value: '取消', action: () => resolve(false) },
        secondaryButton: { value: '同意', action: () => resolve(true) }
      });
    });
  }

  private static showSettingDialog(context: common.UIAbilityContext): void {
    AlertDialog.show({
      title: '需要开启权限',
      message: '该权限已被拒绝，请在设置中手动开启',
      primaryButton: { value: '取消', action: () => {} },
      secondaryButton: {
        value: '去设置',
        action: () => {
          const want = {
            bundleName: 'com.huawei.hmos.settings',
            abilityName: 'com.huawei.hmos.settings.appmanager.MainAbility',
            uri: 'package://application'
          };
          context.startAbility(want);
        }
      }
    });
  }
}
```

## 十一、参考答案要点

1. ① 系统不再弹授权框，应用自行实现说明弹窗；② 用户拒绝后系统永久记住，不再询问，需引导去设置；③ 权限粒度更细、无粗粒度存储权限，文件访问靠 Picker。
2. user_granted（动态申请）、system_granted（需声明 reason + usedScene）、ohos.permission.DEMO（仅系统应用）。when 取 inuse / always。
3. 用 `checkPermissionsFromUser` 查询状态，若为 PERMANENTLY_DENIED 则无法再弹窗，应弹窗引导用户跳转到应用设置页手动开启（bundleName 为 com.huawei.hmos.settings，uri 为 package://application）。
4. PERMISSION_GRANTED（授权成功）/ PERMISSION_DENIED（拒绝）/ PERMISSION_CANCELLED（取消）。
5. reason 是申请理由的文本资源，会展示给用户，审核会核对 reason 与实际 API 调用是否一致。空洞或不符会被驳回。
6. WantAgent 可以在无 UI 交互的情况下按预定义 Want 自动启动组件（如后台推送到达后自动拉起指定页面），系统负责保活与参数传递。
7. 每个应用有独立的 /data/app/el2/... 沙箱目录，应用之间不能直接访问对方文件；跨应用共享需通过 DataShare、Want 参数或 Picker 用户授权。设备按 userId 隔离 el1/el2 目录。
8. 应在"首次获取个人信息之前"展示。常见不合规：启动即弹隐私协议、用完才弹、隐私政策链接不可达、不同意就强退、隐私协议内容与实际采集不符。
9. 步骤：① 查询权限状态 → ② 全部授权则返回 → ③ 有永久拒绝则引导设置 → ④ 弹自定义说明弹窗 → ⑤ 调用 requestPermissionsFromUser → ⑥ 处理 authResults。
10. 用 HUKS 生成密钥对敏感数据加密后存储在首选项/数据库；或用系统 KeyStore 保护；绝不明文存储，也不要放在日志中。
