# 教程 01：HarmonyOS 6 架构总览与工程体系复习

> **目标**：重建对 HarmonyOS 6 整体架构、Stage 模型、工程目录、开发工具链的认知骨架。这是面试中最常被问"宏观认知"的部分，也是理解后续所有 API 的前提。
>
> **对应版本**：HarmonyOS 6.0.0（API 20），HarmonyOS NEXT（纯血鸿蒙，无 AOSP 兼容层）
> **预计阅读**：40 分钟

---

## 一、先建立时间线：HarmonyOS 演进的三个关键节点

很多面试官爱问"你做的是哪个版本的鸿蒙"，答错版本号会显得不专业。必须记住：

| 版本 | API 版本 | 关键特征 |
|---|---|---|
| HarmonyOS 1.0 / 2.0 / 3.0 | 7 ~ 9 | 仍基于 Android 兼容层，叫"HarmonyOS"，发布于 2020~2022 |
| HarmonyOS 4.x | 10 ~ 12 | 仍兼容 AOSP，双框架并存 |
| **HarmonyOS NEXT / 5.0** | 12 ~ 14 | **纯血鸿蒙**，去掉 AOSP 兼容层，只支持 ArkTS/ArkUI 原生开发 |
| **HarmonyOS 6.0** | **20**（API 20） | 当前最新正式版，2025 年 10 月正式推送；新增 Agent 框架、意图框架等 |

**关键结论**：
- 现在做原生开发，默认就是 **Stage 模型 + ArkTS + ArkUI + API 20**。
- **FA（Feature Ability）模型已彻底废弃**。面试时说 FA 会直接暴露知识陈旧。FA 是 4.x 之前的旧模型，Ability 直接绑定 UI 页面，没有 WindowStage 概念。
- HarmonyOS 6 版本号命名规则：`HarmonyOS 6.0.0(20)`，括号里是 **API Level**，写代码时 `compileSdkVersion: 20`。

## 二、HarmonyOS 6 的分层架构

### 2.1 四层结构（自下而上）

```
┌──────────────────────────────────────────────────────────┐
│  应用层：ArkTS 业务逻辑 + ArkUI 声明式 UI                   │
├──────────────────────────────────────────────────────────┤
│  框架层：AbilityKit(Ability框架) / ArkUI(方舟UI)           │
│          ArkData(数据) / ArkNetwork(网络) / ArkTS(语言)     │
├──────────────────────────────────────────────────────────┤
│  系统服务层：分布式软总线 / 分布式数据管理 / 分布式调度     │
│              窗口管理 / 事件通知 / 公共基础库                │
├──────────────────────────────────────────────────────────┤
│  内核层：内核子系统 / 驱动子系统 / 扩展子系统(HAP包管理)     │
└──────────────────────────────────────────────────────────┘
```

### 2.2 各层核心概念速查（面试高频）

**分布式软总线（Soft Bus）**
- HarmonyOS 的"通信中枢"，让设备在物理上靠近时自动发现并建立低时延、高带宽的通道。
- 应用层通过 `distributedHardwareManager` 等 Kit 感知设备，开发时无需关心底层是 Wi-Fi/NFC/蓝牙。
- **面试话术**："分布式软总线屏蔽了底层传输差异，上层用统一 API 做设备发现与传输，这是鸿蒙'超级终端'体验的技术底座。"

**分布式数据管理（ArkData / `distributedDataManager`）**
- 让多设备间的数据自动同步（如剪贴板、跨端编辑）。
- 典型 API：`@ohos.distributedDataManager` 的 `distributedKVStore`。

**分布式硬件 / 分布式调度**
- 跨端任务流转（手机上的视频传到平板继续播）的调度能力。

### 2.3 HarmonyOS 6 新增的三层关键能力（必答亮点）

这是 HarmonyOS 6 区别于 5 的标志性变化，**面试必背**：

**① 星闪（NearLink）2.0 + 碰一碰跨端传输**
- 华为自研近场通信协议，跑在 2.4GHz 频段，相比蓝牙功耗更低、带宽更高、抗干扰更强。
- "碰一碰"实现的是 **纯本地、端到端** 的文件传输，不走云端。
- 开发侧影响：跨设备文件分享可通过 `distributedFileManager` 等能力实现。

**② 鸿蒙智能体框架 HMAF（HarmonyOS Agent Framework）**
- 系统级多智能体协同架构，三层结构：
  - **感知层**：统一处理语音、文字、图像等多模态输入，语义化
  - **决策层**：大模型做意图识别 + 任务规划（Task Planning）
  - **执行层**：调用系统 API 与第三方服务实际完成动作
- 开发侧：应用可通过 **意图框架（Intents Kit）** 和 **Agent Kit** 暴露自身能力，让系统智能体能够调度你的应用。

**③ AI 安全（星盾安全架构）**
- AI 防窥、AI 防诈等能力下沉到系统，敏感推理在 TEE 可信执行环境 + NPU 中完成，数据不出端。

### 2.4 其他 HarmonyOS 6 关键更新

- **方舟引擎（Ark Compiler / ArkTS Runtime）**：对热点代码做更激进的优化（内联、向量化），CPU 密集型任务相比 5.0 有可观提升；配合智能预加载，冷启动显著变快。
- **元服务（Atomic Service）**：免安装、秒开，HarmonyOS 6 对元服务的意图与智能搜索支持更完善。
- **仓颉（Cangjie）语言**：2025 年 7 月开源，华为自研静态类型语言，语法融合 Kotlin/Swift 特性，与 HMAF 深度集成。目前生态尚在早期，面试提及作为技术视野加分项即可。

## 三、工程体系：一个 HarmonyOS 应用的完整骨架

### 3.1 HAP / HSP / HAR 三种包

这是面试必考的基础概念。

| 包类型 | 全称 | 作用 | 能否被其他应用引用 |
|---|---|---|---|
| **HAP** | Harmony Ability Package | 应用的**原子能力包**，包含 Ability、页面、资源。一个应用可以有多个 HAP（一个主 HAP + 若干 Feature HAP） | 否，独立安装 |
| **HSP** | Harmony Shared Package | **共享包**，用于多个 HAP 之间共享代码和资源，避免重复打包 | 内部共享（同应用多 HAP） |
| **HAR** | Harmony Archive | 静态库包，构建期编译进依赖方，适合纯逻辑模块（不依赖上下文） | 内部共享 |

> **记忆口诀**：HAP = 能跑的应用单元；HSP = 应用内共享；HAR = 纯静态库。
>
> **迁移/升级提醒**：从 HAP/HSP 体系，HarmonyOS 6 推荐使用 **HAR + HSP** 或 **本地库（Native .so）**；另外近年也支持 **共享包（SharedPackage）** 跨应用分发。

### 3.2 工程目录结构（Default 模板）

```
entry/                                # 主 HAP 模块
├── src/main/
│   ├── ets/
│   │   ├── entryability/            # UIAbility 入口
│   │   │   └── EntryAbility.ets
│   │   ├── pages/                   # 页面组件
│   │   │   └── Index.ets
│   │   ├── model/                   # 数据模型
│   │   ├── viewmodel/               # 视图模型（MVVM）
│   │   └── common/                  # 公共工具
│   ├── resources/base/
│   │   ├── element/                 # string.json / color.json / float.json
│   │   ├── media/                   # 图片、字体、raw 文件
│   │   └── profile/
│   │       ├── main_pages.json      # ★ 页面路由表
│   │       ├── main_ability.json    # ★ Ability 配置
│   │       └── backup_config.json
│   └── module.json5                 # ★ 模块级配置
├── build-profile.json5              # 模块构建配置
├── hvigorfile.ts                    # 模块构建脚本
└── oh-package.json5                 # 模块依赖声明

oh-package.json5                     # 工程级依赖 + 引用 HSP/HAR
build-profile.json5                  # 工程构建配置
hvigorfile.ts                        # 工程构建脚本
```

**几个必背的配置文件的区别（经典面试题）**：

- `module.json5` —— **模块级**，声明这个 HAP 有哪些 Ability、权限、metadata。
- `AppScope/app.json5` —— **应用级**，声明应用全局信息（bundleName、版本号、icon、label）。
- `build-profile.json5` —— 构建配置：`products`（不同产品形态）、`targets`（SDK 版本）、`signingConfigs`（签名）。
- `oh-package.json5` —— 依赖声明，等价于 npm/pnpm 的 package.json。

### 3.3 关键配置片段（背下来，面试能直接写）

**AppScope/app.json5**
```json5
{
  "app": {
    "bundleName": "com.example.myapp",
    "vendor": "example",
    "versionCode": 1000000,
    "versionName": "1.0.0",
    "icon": "$media:app_icon",
    "label": "$string:app_name"
  }
}
```

**EntryAbility 的 module.json5 片段**
```json5
{
  "module": {
    "name": "entry",
    "type": "entry",
    "description": "$string:module_desc",
    "mainElement": "EntryAbility",          // ★ 指定启动页
    "deviceTypes": ["phone", "tablet"],      // ★ 支持的设备类型
    "deliveryWithInstall": true,             // 安装即交付（免安装需 false）
    "installationFree": false,               // 是否免安装（元服务 true）
    "pages": "$profile:main_pages",          // ★ 路由表
    "abilities": [
      {
        "name": "EntryAbility",
        "srcEntry": "./ets/entryability/EntryAbility.ets",
        "description": "$string:EntryAbility_desc",
        "icon": "$media:layered_image",
        "label": "$string:EntryAbility_label",
        "startWindowIcon": "$media:startIcon",
        "startWindowBackground": "$color:start_window_background",
        "exported": true,                    // ★ 是否可被外部拉起
        "skills": [
          {
            "entities": ["entity.system.home"],
            "actions": ["action.system.home"]  // ★ 桌面图标
          }
        ]
      }
    ]
  }
}
```

**main_pages.json**
```json5
{
  "src": [
    "pages/Index",
    "pages/Detail"
  ]
}
```

## 四、Stage 模型 vs FA 模型（面试必对比）

| 维度 | FA 模型（已废弃） | Stage 模型（现在） |
|---|---|---|
| Ability 与 UI 关系 | Ability 直接持有页面 | **Ability → WindowStage → 窗口 → 页面**，UI 独立 |
| 窗口管理 | 无 WindowStage 概念 | `WindowStage` 统一管理窗口生命周期 |
| 形态 | FA（一个 Ability = 一个界面） | **UIAbility**（界面）/ **ExtensionAbility**（无界面服务） |
| 内存 | Ability 销毁即页面销毁 | Ability 生命周期与页面生命周期解耦 |
| 多设备 | 支持有限 | 天然支持多端部署/流转 |
| 状态保存 | 弱 | `onSaveState` / `Want` / `AppStorage` 完整链路 |

**一句话总结**：Stage 模型把「Ability 生命周期」与「UI 生命周期」解耦，通过 WindowStage 作为中间层，让 Ability 可以在 UI 不存在时继续存活（如后台播放音乐），这是分布式流转和后台任务的基础。

## 五、开发环境：DevEco Studio 实战

### 5.1 必装组件

1. **DevEco Studio**（最新版，HarmonyOS 6 对应 6.0.x）
2. **HarmonyOS SDK**（API 20）
3. **JDK 17**（DevEco 6 要求）
4. **Node.js**（用于 hvigor 构建）
5. **hdc**（HarmonyOS Device Connector，替代 adb）

### 5.2 命令行速查

```bash
# 连接设备
hdc list targets

# 安装 HAP
hdc install -r entry-default-signed.hap

# 启动 Ability
hdc shell aa start -a EntryAbility -b com.example.myapp

# 查看日志（重点：HiLog）
hdc shell hilog | grep MyApp

# 实时跟踪 ArkTS 日志
hilog -T MyTag

# 推送文件到设备
hdc file send ./a.txt /data/local/tmp/

# 截图
hdc shell snapshot_display -f /data/local/tmp/screenshot.jpeg
hdc file recv /data/local/tmp/screenshot.jpeg ./
```

> **面试提示**：说得出 `hdc` 而不是 `adb`，并知道 `hilog` 是鸿蒙的日志工具（日志级别 DEBUG/INFO/WARN/ERROR/FATAL，通过 `hilog -L` 切换），会显得有实战经验。

### 5.3 调试技巧

| 场景 | 手段 |
|---|---|
| 看日志 | `HiLog` API（`import { hilog } from '@kit.PerformanceAnalysisKit'`）+ `hdc shell hilog` |
| 断点调试 | DevEco 图形化调试器，支持表达式求值、变量观察 |
| 查看布局树 | DevEco 的 `Layout Inspector`（ArkUI Inspector） |
| 性能分析 | **SmartPerf**（CPU/内存/帧率），**ArkTS Profiler** |
| 内存泄漏 | **LeakInspector**（内存快照，定位未释放对象） |
| 抓包 | **Network Inspector** 或系统抓帧工具 |

### 5.4 预览器（Previewer）

- DevEco 内置 ArkUI 预览器，可实时渲染 UI，支持多设备尺寸、Dark Mode、深浅色切换。
- 预览器里 `@State` 会正常响应，但**不能调用系统 API**（如 `getContext()` 有限支持），所以复杂逻辑要在模拟器/真机验证。

## 六、HarmonyOS 6 应用形态一览

| 形态 | 入口类 | 是否有界面 | 典型场景 |
|---|---|---|---|
| **手机/平板应用** | `UIAbility` | ✅ | 普通应用 |
| **元服务 (Atomic Service)** | `UIAbility`（配置 `installationFree: true`） | ✅ | 免安装、秒开 |
| **卡片服务** | `FormExtensionAbility` | 桌面卡片 | 信息卡片 |
| **输入法** | `InputMethodExtensionAbility` | 键盘 | 输入法应用 |
| **后台服务** | `ServiceExtensionAbility` | ❌ | 长期后台任务 |
| **数据服务** | `DataShareExtensionAbility` | ❌ | 数据共享 |
| **通知提醒** | `NotificationExtensionAbility` | ❌ | 本地通知 |
| **UI 扩展** | `UIExtensionAbility` | ✅（独立窗口） | 悬浮窗、选单面板 |

**面试话术**："HarmonyOS 的 Ability 有两大类：UIAbility 有界面，ExtensionAbility 无界面。ExtensionAbility 又细分了 Service、DataShare、Form、InputMethod、Notification 等多种形态，各自有独立的生命周期与启动约束。"

## 八、参考答案要点

1. API 20；去掉 AOSP（Android 兼容层），转纯血鸿蒙内核与运行时。
2. HAP 是可独立安装运行的原子能力包；HSP 是应用内多 HAP 共享的动态共享包；HAR 是编译期链接的静态库。多 HAP 共享 → HSP。
3. module.json5 = 模块级（Ability 列表、权限、页面路由、deviceTypes）；app.json5 = 应用级（bundleName、版本、图标、名称）。
4. Ability 生命周期与 UI 生命周期解耦，引入 WindowStage 作为中间层，支持无界面后台存活、跨端流转。
5. 星闪 2.0 与碰一碰跨端传输；鸿蒙智能体框架 HMAF（感知层 / 决策层 / 执行层）；星盾 AI 安全。同时还有方舟引擎性能优化。
6. hdc 是鸿蒙设备连接工具，命令风格类似 adb 但针对鸿蒙设备；`hdc install -r xxx.hap`。
