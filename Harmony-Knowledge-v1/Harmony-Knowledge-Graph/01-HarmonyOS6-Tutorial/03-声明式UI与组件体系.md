## 一、声明式 UI 的心智模型

### 1.1 命令式 vs 声明式（面试经典对比）

| | 命令式（Android View / iOS UIKit） | 声明式（ArkUI / Flutter / React） |
|---|---|---|
| 写法 | 一步步命令："创建控件 → 设置属性 → 添加到父容器 → 布局" | **描述"UI 应该是什��样子"**，框架负责 diff |
| 状态驱动 | 手动刷新（`setText`、`notifyDataSetChanged`） | **状态变了 → UI 自动更新** |
| 核心概念 | 控件树（对象引用） | **状态 + 视图 = f(state)** |
| 性能 | 依赖开发者手动优化 | 框架做 **差量更新（diff）**，只更新变化节点 |

**ArkUI 的心智模型一句话**：

```
UI = f(state)
```

状态变了，框架重新"描述"一次 UI，但通过 diff 算法**只把真正变化的属性同步到原生控件**上。

### 1.2 ArkUI 的两阶段渲染（进阶，面试加分）

ArkUI 的渲染是**异步 + 分帧**的：

1. **build() 阶段（首次）**：完整执行 `build()`，生成整棵 UI 树（VDOM / 节点树），执行耗时较长。
2. **update 阶段（后续）**：状态变化后，**不再执行 build()**，而是记录状态依赖的组件，直接更新对应节点的属性。

```
状态变更
   │
   ├─ 标记该状态依赖的组件为 dirty
   │
   ├─ 在下一帧（vsync）统一处理
   │     ├─ 执行状态装饰器的 observed 回调
   │     ├─ 局部更新（update）而非全量 build
   │     └─ 触发重新布局/重绘
   │
   └─ 下一帧渲染到屏幕
```

> **面试话术**："ArkUI 首次渲染会执行 build() 生成节点树，之后状态变更走 update 阶段的局部更新，只重绘受影响节点。所以 build() 里不能做耗时操作或副作用，否则首屏性能会崩；状态粒度也要设计合理，粒度过粗会导致大范围重绘。"

### 1.3 状态管理的第一性原理

状态管理解决三个问题：
1. **谁持有状态** —— 父组件、子组件、全局
2. **谁消费状态** —— 组件的哪些属性需要被观察
3. **如何通知更新** —— 观察者模式 + 框架 diff

这就是 `@State` / `@Link` / `@Prop` / `@Provide` / `@Consume` 这一族装饰器的分工。

## 二、自定义组件

### 2.1 基本结构：@Component + @Builder

```ts
@Component
struct MyComponent {
  // 1. 成员变量（状态装饰器声明）
  @State count: number = 0;
  // 普通变量
  private title: string = 'Hello';

  // 2. 生命周期
  aboutToAppear(): void {
    console.info('aboutToAppear');
  }
  aboutToDisappear(): void {
    console.info('aboutToDisappear');
  }

  // 3. build 方法（必须，UI 描述）
  @Builder
  build() {
    Column() {
      Text(this.title)
        .fontSize(24)
      Button('点击 +1')
        .onClick(() => {
          this.count++;
        })
      Text(`计数: ${this.count}`)
    }
    .width('100%')
    .height('100%')
  }
}
```

**自定义组件的 5 个组成部分**：
1. `@Component` 装饰器（**struct** 只能配合 `@Component`）
2. 成员变量（状态、普通变量、方法）
3. 生命周期回调
4. `@Builder` 装饰的 build 方法
5. 私有状态由 `@State` 等装饰器声明

### 2.2 @Component vs @Preview

```ts
// @Preview 可以在 DevEco 预览器里单独渲染该组件
@Preview
@Component
struct MyComponent {
  build() { Text('preview') }
}
```

`@Preview` 支持参数化预览：

```ts
@Preview({ title: 'Phone', width: 360, height: 780 })
@Component
struct PhonePreview {
  build() { ... }
}
```

### 2.3 组件参数传递

**普通属性（单向，值传递）**

```ts
@Component
struct Child {
  // 普通变量：父传子，单向
  label: string = '';
  count: number = 0;

  build() {
    Text(`${this.label}-${this.count}`)
  }
}

// 使用
@Entry
@Component
struct Parent {
  build() {
    Column() {
      Child({ label: 'hi', count: 5 })   // ← 对象字面量传参
    }
  }
}
```

**注意**：普通属性是**值传递**，父组件状态变化会重新传入并触发子组件 update。

**状态属性（双向或单向同步）**

```ts
@Component
struct Child {
  @Link count: number = 0;          // 双向
  @Prop title: string = '';         // 单向
  @Link user: User = new User();    // 双向（对象整体）

  build() { Text(`${this.count}-${this.title}`) }
}

// 使用
@Entry
@Component
struct Parent {
  @State count: number = 0;
  @State title: string = 'hello';

  build() {
    Child({ count: this.count, title: this.title })  // ← $ 引用？
  }
}
```

> **关键规则**：当父组件把 `@State` 变量传给子组件的 `@Link` 时，**不需要写 `$`**。而传给 `@Prop` 时也直接传。`$` 的用法见教程 04。

### 2.4 生命周期回调（自定义组件）

| 回调 | 时机 | 典型用途 |
|---|---|---|
| `aboutToAppear()` | 组件创建、**build 之前** | 初始化、订阅数据 |
| `onAppear()` | 组件挂载到渲染树后 | 操作 DOM 尺寸、动画启动 |
| `aboutToDisappear()` | 组件销毁前 | 取消订阅、清理资源 |
| `onDisappear()` | 组件移除后 | 释放资源 |

> **面试区分点**：`aboutToAppear` 在 build 之前，此时组件还未渲染，不能获取组件尺寸；`onAppear` 时组件已渲染，可以用 `getUIContext()` 或 `onAreaChange` 获取真实尺寸。

## 三、布局体系（三大布局）

### 3.1 Column（垂直）/ Row（水平）

```ts
Column() {
  Text('第一行')
  Text('第二行')
}
.width('100%')
.height('100%')
.justifyContent(FlexAlign.Center)   // 主轴对齐
.alignItems(HorizontalAlign.Center)  // 交叉轴对齐
```

**常用对齐枚举**：
- `FlexAlign.Start / Center / End / SpaceBetween / SpaceAround / SpaceEvenly`
- `HorizontalAlign.Start / Center / End / JUSTIFY`
- `VerticalAlign.Top / Center / Bottom`

**自适应尺寸（重要）**：
```ts
.width('100%')       // 父容器宽度的百分比
.height('100%')
.layoutWeight(1)     // 剩余空间按权重分配 ★
.constraintSize({ minWidth: 50, maxWidth: 200 })
```

**`layoutWeight` 是面试常考点**：在 Row/Column 中，设置了 `layoutWeight` 的子组件会按权重瓜分**剩余空间**（父容器尺寸 - 其他子组件占用）。

```ts
Row() {
  Text('左').layoutWeight(1)
  Text('右').layoutWeight(2)     // 右占 2/3
}.width('100%')
```

### 3.2 Stack（层叠）

```ts
Stack({ alignContent: Alignment.TopEnd }) {
  Image($r('app.media.bg'))
  Text('叠加层')
    .backgroundColor(Color.White)
}
```

- 子组件**后添加的在上层**。
- `zIndex` 可显式设置层级。

### 3.3 栅格 Grid

```ts
Grid() {
  ForEach(this.items, (item: string) => {
    GridItem() {
      Text(item)
    }
  }, (item: string) => item)
}
.columnsTemplate('1fr 1fr 1fr')   // 三列
.rowsTemplate('1fr 1fr')
.height(300)
```

- `1fr` 表示等分一份。
- `2fr 1fr` 表示 2:1。
- `GridItem` 只能作为 `Grid` 的直接子组件。

### 3.4 自定义布局（onMeasure / onPlace）

```ts
@Component
struct MyLayout {
  onMeasure(widthMeasureSpec: MeasureSpec, heightMeasureSpec: MeasureSpec): void {
    // 决定自身尺寸
    this.measureSize.setMeasuredDimension(
      MeasureSpec.getSize(widthMeasureSpec),
      MeasureSpec.getSize(heightMeasureSpec)
    );
  }

  onPlace(widthMeasureSpec: MeasureSpec, heightMeasureSpec: MeasureSpec): void {
    // 决定子组件位置
    this.layoutChildren(MeasuredSize.measureChild(this, ...), ...);
  }

  build() {
    Column() { }
  }
}
```

### 3.5 尺寸单位（高频易错点）

| 单位 | 含义 | 使用场景 |
|---|---|---|
| `vp` (vp) | 虚拟像素，**随屏幕密度缩放** | ★ 长度、间距、字体（推荐） |
| `px` | 物理像素 | 几乎不用 |
| `lpx` | 逻辑像素，不随密度缩放 | 极少用 |
| `%` | 父容器百分比 | 宽度/高度自适应 |
| `fp` | 字体像素，随字体大小缩放 | 字体（`fontSize('16fp')`） |

> **面试话术**："鸿蒙用 vp（虚拟像素）做长度单位，在不同密度屏幕上物理尺寸一致，保证跨设备视觉统一；字体用 fp，跟随系统字体缩放设置变化。"

**路由页面可用的装饰器**：`@Entry` 标记入口组件，`@Entry` 组件**必须是页面的根组件**，一个文件中只能有一个。

## 九、常见坑与调试

| 现象 | 原因 | 解决 |
|---|---|---|
| UI 不刷新 | 状态没用装饰器 / 改了普通变量 | 用 `@State`/`@Link`，或 V2 的 `@Local`/`@Trace` |
| 列表滚动卡顿 | 未开 `lazyForEach` | 开懒加载 + 减小 item 复杂度 |
| 圆角不生效 | 缺 `clip(true)` | 加 `.clip(true)` |
| 顶部被状态栏遮挡 | 安全区默认避让 | `expandSafeArea` 或用 `WindowSize` 感知 |
| 文本超长不换行 | 缺 `maxLines`/宽度约束 | 设 `.maxLines()` + `.textOverflow()` |
| 弹窗后键盘遮挡 | 页面未开启键盘避让 | 设置 `this.getUIContext().setKeyboardAvoidMode(KeyboardAvoidMode.RESIZE)` |
| 预览器报错 | 预览器不支持部分系统 API | 改用真机/模拟器验证 |

## 十一、参考答案要点

1. 命令式是"一步步操作控件"，声明式是"描述 UI 应该是什么样子"，UI = f(state)，状态变了框架自动 diff 更新。
2. 首帧执行 build() 生成节点树；后续状态变更走 update 阶段做局部更新。build() 若有耗时/副作用，会拖慢首屏并可能在每次重建时重复触发副作用。
3. aboutToAppear 在 build 之前（组件还没渲染，拿不到尺寸）；onAppear 在挂载到渲染树之后。
4. 分配剩余空间（父容器尺寸减去其他子组件的固定占用），按权重比例瓜分。
5. 一次性创建全部节点会耗内存、耗时长；懒加载只渲染可视区域附近的项。
6. 让 ForEach 复用节点时保留该组件的状态（如列表项的勾选、展开状态）。
7. 用 `GridRow` + `GridCol` 配合 `breakpoints` 和 `span` 断点规则，配合 `BreakpointsReference.WindowSize`。
8. animateTo 用于状态变更引起的属性渐变动画；transition 用于条件渲染时组件的进入/退出动画。
9. px 是物理像素，不同屏幕密度下物理大小不同；vp 是虚拟像素，按密度缩放，保证视觉一致。
10. 需要 `.clip(true)` 让子组件被圆角裁剪。
