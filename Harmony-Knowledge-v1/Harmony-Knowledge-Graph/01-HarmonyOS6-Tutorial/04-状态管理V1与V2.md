# 教程 04：状态管理 V1 与 V2（HarmonyOS 6 重点）

> **目标**：这是 HarmonyOS 面试中**最高频、最能区分档次**的知识点。要掌握 V1 的六种装饰器、V2 的新体系、`@Observed` vs `@ObservedV2` 的区别、以及 AppStorage/PersistentStorage/LocalStorage/首选项的完整存储体系。
>
> **预计阅读**：75 分钟
>
> **版本说明**：V2 状态管理从 API 12 开始引入，HarmonyOS 6（API 20）已全面推荐使用 V2。

---

## 一、为什么需要状态管理

```
UI = f(state)
```

状态管理的三大任务：
1. **定义状态的归属**（组件内 / 父子间 / 全局）
2. **声明状态的观察者**（哪些组件依赖它）
3. **触发更新**（状态变更 → 通知依赖者 → 局部 diff 重渲染）

## 二、V1 状态管理：六大装饰器

### 2.1 速查表（先记这张表）

| 装饰器 | 类型 | 能否与父组件同步 | 能否修改父传值 | 底层机制 |
|---|---|---|---|---|
| `@State` | 组件内部状态 | ❌ | — | 本地 + Proxy 拦截 |
| `@Link` | 父子双向 | ✅ 双向 | ✅ | 引用传递（父的变量） |
| `@Prop` | 父子单向 | ✅ 单向（父→子） | ❌ | 值传递 + 拷贝 |
| `@Provide` | 祖先供给 | ✅ | ✅ | 树形订阅 |
| `@Consume` | 后代消费 | ✅ | ✅ | 树形订阅 |
| `@Observed` | 类对象可观察 | — | — | 与 `@ObjectLink` 配合 |
| `@ObjectLink` | 观察类对象 | ❌（不能替换父对象） | — | 引用 + Proxy 拦截 |
| `@Watch` | 状态变化回调 | — | — | 监听器 |
| `@StorageLink` | 全局双向 | ✅ | ✅ | AppStorage |
| `@StorageProp` | 全局单向 | ✅ | ❌ | AppStorage |

### 2.2 @State：组件内部状态

```ts
@Component
struct Counter {
  @State count: number = 0;          // 本地状态
  @State list: string[] = [];        // 数组/对象类型也支持
  @State obj: User = { name: 'a' };  // ★ 对象属性变化能触发刷新（V1 支持一层深度）

  build() {
    Column() {
      Text(`${this.count}`)
      Button('+1').onClick(() => { this.count++ })
    }
  }
}
```

**@State 的规则**：
- 必须是**成员变量**，且**有初始值**或**在构造函数中赋值**。
- 支持类型：`number`、`string`、`boolean`、`enum`、对象、数组、`class` 实例、`null`/`undefined`。
- **修改对象内部属性**也能触发刷新（V1 通过 Proxy 拦截一层的 set）。

```ts
@State user: User = { name: 'Tom', age: 18 };

// ✅ 修改属性 → 触发刷新
this.user.name = 'Jerry';

// ❌ 整体替换需要重新赋值（否则不刷新）
this.user = { name: 'Tom', age: 19 };   // 这个是 OK 的，赋值会触发
```

### 2.3 @Link：父子双向绑定

```ts
@Component
struct Child {
  @Link value: number = 0;      // ★ 必须有初始值（虽然父会覆盖）

  build() {
    Column() {
      Text(`子组件看到: ${this.value}`)
      Button('子组件+1').onClick(() => { this.value++ })   // ★ 直接改父的状态
    }
  }
}

@Entry
@Component
struct Parent {
  @State value: number = 0;

  build() {
    Column() {
      Child({ value: this.value })    // ★ 直接传，不用 $
      Button('父组件+1').onClick(() => { this.value++ })
    }
  }
}
```

> **易错点**：`@Link` 传参**直接传 `this.xxx`，不要写 `$this.xxx`**。写了 `$` 会报错。

### 2.4 @Prop：父子单向同步

```ts
@Component
struct Child {
  @Prop value: number = 0;        // 单向：父改子跟着改，子改不影响父

  build() {
    Column() {
      Text(`子组件看到: ${this.value}`)
      Button('尝试修改').onClick(() => {
        // this.value = 100;   ← 编译报错！@Prop 不允许修改
        // 但可以读取并基于它计算
      })
    }
  }
}
```

**@Prop vs @Link 核心区别**：
- `@Prop`：**值传递**，父传子时传的是**副本**；父组件重渲染会重新传递。
- `@Link`：**引用传递**，父子共用同一个变量。

```ts
// @Prop 的副本特性演示
@State arr: number[] = [1, 2, 3];
Child({ list: this.arr });   // @Prop list

// 父里 this.arr.push(4) 后，子里的 list 需要等父重渲染才更新（因为是副本）
```

> **注意**：对象/数组类型的 `@Prop` **只会同步一层**，嵌套对象的内部属性变化不会同步。这是 V1 最大的痛点，也正是 V2 诞生的原因。

### 2.5 @Provide / @Consume：跨层级通信

```ts
@Entry
@Component
struct GrandParent {
  @Provide('themeColor') theme: string = '#FF0000';    // 祖先提供

  build() { Column() { Middle() } }
}

@Component
struct Middle {
  build() { Column() { Child() } }     // 中间层无需任何声明
}

@Component
struct Child {
  @Consume('themeColor') theme: string;   // ★ 后代消费
  // 注意：@Consume 不需要初始值，父级必须存在同名 @Provide

  build() { Text(`颜色: ${this.theme}`) }
}
```

**要点**：
- `@Provide` 与 `@Consume` **必须使用相同的 key（别名）**。
- `@Consume` 变量**不需要初始值**（但如果找不到匹配的 `@Provide`，运行时崩溃）。
- `@Provide` 可以被后代 `@Consume` **直接修改**（双向）。
- 支持多层嵌套匹配（就近原则）。
- `@Provide` 的值本身若由 `@State` 持有，更新时依然生效。

### 2.6 @Observed + @ObjectLink：观察类对象（V1 的深度观察）

**问题**：`@Prop` 只同步一层，`@State` 的对象属性修改能刷新，但传给子组件时用 `@Prop` 就断了。

```ts
// 被观察的类
@Observed
class User {
  name: string = '';
  age: number = 0;
  address: Address = new Address();   // 嵌套对象

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
  }
}

@Observed
class Address {
  city: string = '';
}

@Entry
@Component
struct Parent {
  @State user: User = new User('Tom', 18);   // ★ 父持有

  build() {
    Column() {
      Child({ user: this.user })     // 传对象
    }
  }
}

@Component
struct Child {
  @ObjectLink user: User;            // ★ 观察对象内部属性变化

  build() {
    Column() {
      Text(this.user.name)
      Button('改年龄').onClick(() => {
        this.user.age = 20;         // ★ 触发刷新（父和子都会更新）
      })
    }
  }
}
```

**@ObjectLink 的规则**：
- **不能给初始值**（必须由父组件传入）。
- **不能整体替换**父传的对象（`this.user = new User(...)` 会报错），只能改其属性。
- 能感知 **任意深度**的嵌套属性变化（因为每个 `@Observed` 类都被 Proxy 包装）。

**@Observed vs @ObservedV2（面试必对比）**：

| 维度 | V1 `@Observed` | V2 `@ObservedV2` |
|---|---|---|
| 搭配 | `@ObjectLink` | `@Trace` |
| 装饰器位置 | 装饰**类** | 装饰**类**（同） |
| 属性级装饰 | ❌ 不需要 | ✓ `@Trace` 标注需要观察的属性 |
| 深度观察 | ✅ 全属性自动观察 | ✅ 但需 `@Trace` 标注（或类级全量） |
| 装饰器总数 | 2 个（@Observed + @ObjectLink） | 2 个（@ObservedV2 + @Trace） |
| 与 V1 混用 | ❌ 不可以 | ❌ 不可以 |
| 精细控制 | 粗（类内所有属性） | 细（可只观察部分属性） |

### 2.7 @Watch：监听状态变化

```ts
@Component
struct Comp {
  @State @Watch('onCountChange') count: number = 0;

  onCountChange(propName: string, oldValue: number, newValue: number): void {
    console.info(`${propName}: ${oldValue} -> ${newValue}`);
    // ⚠️ 不要在这里改状态，容易死循环
  }

  build() { Text(`${this.count}`) }
}
```

> `@Watch` 只在**当前组件内**生效，**不能传递给子组件**（`@Watch` 不能与 `@Link` 一起用）。

## 三、V2 状态管理（HarmonyOS 6 推荐）

### 3.1 V2 解决了什么问题

V1 的痛点：
1. `@Prop` 只同步一层 → 嵌套对象不更新（**最常见的 bug**）
2. 装饰器种类多、语义复杂，父子/跨层关系难记
3. V1 与 V2 装饰器**不能混用**在同一属性链上，容易踩坑

**V2 的核心改进**：
- **观察粒度从"对象"细化到"属性"**（`@Trace` 标在属性上）
- **一套装饰器覆盖所有场景**，减少心智负担
- 支持 **装饰器 + 深度观察**，无 `@Prop` 的一层限制

### 3.2 V2 装饰器速查表

| 装饰器 | 对应 V1 | 用途 |
|---|---|---|
| `@Local` | `@State` | 组件内部状态 |
| `@Param` | `@Prop` | 父 → 子，单向；**不可在组件内修改** |
| `@ParamOnce` | — | 父 → 子，单向，**仅初始化一次**，后续父变更不同步 |
| `@Event` | — | 子 → 父，**事件回调**（替代 `@Link` 的写场景） |
| `@ProvideV2` | `@Provide` | 祖先 → 后代供给 |
| `@ConsumeV2` | `@Consume` | 后代消费祖先数据 |
| `@ObservedV2` | `@Observed` | 类被观察（属性级） |
| `@Trace` | — | 类内**被观察的属性** |
| `@Monitor` | — | 监听状态变化（可多个、可分组） |
| `@Computed` | — | 计算属性（依赖变化自动重算） |
| `@Require` | — | 强制父组件传入（外部传入的对象属性必须有初值） |
| `@Builder` | `@Builder` | UI 构建函数（V2 中支持带参数和返回值） |

### 3.3 @Local：组件内部状态

```ts
@Component
struct Comp {
  @Local count: number = 0;          // 对应 @State

  build() {
    Text(`${this.count}`)
  }
}
```

### 3.4 @Param + @Event：单向数据 + 事件回调（V2 推荐模式）

**这是 V2 最重要的范式转变**：从"双向绑定"转向"单向数据流 + 事件"。

```ts
@Component
struct Child {
  @Param title: string = '';                 // 父 → 子，单向
  @Param count: number = 0;
  @Event onIncrement: () => void = () => {}; // 子 → 父，回调
  @Event onChange: (value: string) => void = (v: string) => {};

  build() {
    Column() {
      Text(`${this.title}: ${this.count}`)
      Button('+1').onClick(() => {
        // ★ 不能直接改 @Param
        // this.count++;   ← 报错
        this.onIncrement();       // 通知父组件去改
      })
      TextInput({ text: '' })
        .onChange((v: string) => { this.onChange(v); })
    }
  }
}

@Entry
@Component
struct Parent {
  @Local count: number = 0;
  @Local title: string = '计数器';

  build() {
    Column() {
      Child({
        title: this.title,
        count: this.count,
        onIncrement: () => { this.count++ },             // 父改状态
        onChange: (v: string) => { this.title = v }
      })
    }
  }
}
```

**V2 范式的优势**：
- 数据流清晰：父是唯一数据源，子通过事件上报。
- 可预测：不会出现"谁改了谁"的混乱。
- 更容易测试和追踪。

### 3.5 @ParamOnce

```ts
@Component
struct Child {
  @ParamOnce initialValue: string = '';   // 只在初始化时取一次父的值
  build() { Text(this.initialValue) }
}
```

适用：Tab 初始化时的默认选中项、对话框初始内容等——父后续变化不应影响子。

### 3.6 @ObservedV2 + @Trace：属性级深度观察

```ts
@ObservedV2
class User {
  name: string = '';             // 未标注 @Trace → 不被观察
  @Trace age: number = 0;         // ★ 只有标了 @Trace 的属性被观察
  @Trace address: Address = new Address();   // 嵌套也能深层观察
}

@ObservedV2
class Address {
  @Trace city: string = '';
}
```

使用：
```ts
@Entry
@Component
struct Parent {
  @Local user: User = new User();     // ★ V2 中用 @Local 持有被观察对象

  build() {
    Column() {
      Child({ user: this.user })
      Button('改名').onClick(() => {
        this.user.name = 'Tom';      // ❌ 无 @Trace，不触发刷新
        this.user.age = 20;          // ✅ 有 @Trace，触发刷新
      })
    }
  }
}

@Component
struct Child {
  @Param user: User = new User();    // ★ V2 中传对象用 @Param（配合 @ObservedV2）

  build() {
    Text(`${this.user.name} ${this.user.age}`)
  }
}
```

**V2 传对象的关键变化**：V1 是 `@ObjectLink`（引用 + 观察），V2 是 **`@Param` + `@ObservedV2` + `@Trace`**（`@Param` 本身会观察被观察对象的 `@Trace` 属性）。

### 3.7 @ProvideV2 / @ConsumeV2

```ts
@Entry
@Component
struct GrandParent {
  @ProvideV2('theme') theme: string = '#FF0000';

  build() { Column() { Middle() } }
}

@Component
struct Middle {
  build() { Column() { Child() } }
}

@Component
struct Child {
  @ConsumeV2('theme') theme: string;

  build() { Text(this.theme) }
}
```

**V2 变化**：支持**对象类型**的跨层供给（V1 的 `@Provide` 传对象会有同步问题）。

```ts
@ObservedV2
class Theme {
  @Trace color: string = '#FF0000';
}

@Entry
@Component
struct Parent {
  @ProvideV2('themeObj') theme: Theme = new Theme();   // ★ 对象
}
```

### 3.8 @Monitor：精细监听（V2 新增）

```ts
@Component
struct Comp {
  @Local @Monitor('a', 'b') count: number = 0;      // 监听多个属性
  @Local @Monitor('onNameChange') name: string = '';

  a: number = 0;    // 内部变量，配合 @Monitor 收集
  b: number = 0;

  aboutToAppear(): void {
    // 手动触发
    this.a = 1;
  }

  onCountChange(propName: string, oldValue: number, newValue: number): void {
    console.info(`count: ${oldValue} -> ${newValue}`);
  }

  onNameChange(propName: string, oldValue: string, newValue: string): void {
    console.info(`name: ${oldValue} -> ${newValue}`);
  }

  build() { Text(`${this.count}-${this.name}`) }
}
```

**@Monitor 的优势**：
- 一个状态可监听**多个属性变化**。
- 可监听**对象属性的变化**（V1 的 `@Watch` 做不到）。
- 支持**分组回调**（同一回调处理多个属性）。

### 3.9 @Computed：计算属性

```ts
@Component
struct Comp {
  @Local firstName: string = 'A';
  @Local lastName: string = 'B';

  @Computed
  get fullName(): string {
    return `${this.firstName} ${this.lastName}`;   // 依赖变化自动重算
  }

  build() { Text(this.fullName) }
}
```

### 3.10 @Require：强制父组件传入

```ts
@Component
struct Child {
  @Require @Param user: User;      // ★ 父组件必须传 user，否则编译报错
  build() { Text(this.user.name) }
}
```

> **记忆点**：V2 中 `@Param` 的对象类型如果没有初始值，父组件必须传；加 `@Require` 让编译器强制检查，避免运行时 undefined。

### 3.11 V1 与 V2 混用规则（重要，踩坑重灾区）

**规则**：
1. **同一个属性上**不能同时用 V1 和 V2 装饰器。
2. **同一条数据链路**上（如父的 `@State` → 子的 `@Link`）不能混用 V1 和 V2 装饰器。
3. `@Provide`/`@Consume`（V1）与 `@ProvideV2`/`@ConsumeV2`（V2）**不能同时存在于同一链路**。
4. `@Observed` 类**不能**传给 `@Param`（V2），反之 `@ObservedV2` 类不能传给 `@ObjectLink`（V1）。

**最佳实践**：**新项目全用 V2，老项目保持 V1，不要混**。如果必须迁移，把 V1 的 `@State`→`@Local`、`@Link`→`@Param`+`@Event`、`@Observed`→`@ObservedV2`+`@Trace`、`@Provide`→`@ProvideV2`。

## 四、存储体系全景

```
┌─────────────────────────────────────────────────────┐
│  AppStorage    应用内存级，全局，页面级可用           │
│  ↓ 持久化                                        │
│  PersistentStorage  持久化到磁盘（首选项格式）        │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  LocalStorage  组件内部，与 @State 绑定的本地存储     │
│  @LocalStorageLink / @LocalStorageProp              │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  首选项 Preferences  键值对持久化（轻量）             │
│  @ohos.data.preferences / @kit.ArkData              │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  关系型数据库 RDB  SQLite-like，结构化数据            │
│  @ohos.data.relationalStore / @kit.ArkData          │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  分布式数据  跨设备同步（KVStore）                    │
│  @ohos.data.distributedKVStore                      │
└─────────────────────────────────────────────────────┘
```

### 4.1 AppStorage（应用全局内存状态）

```ts
// 1. 在 UIAbility 中初始化（推荐，全局唯一）
export class AppStorageSetup {
  static init(): void {
    AppStorage.setOrCreate<string>('userToken', '');
    AppStorage.setOrCreate<number>('cartCount', 0);
  }
}
```

```ts
// 2. 在组件中使用
@Entry
@Component
struct Index {
  // 双向：改 AppStorage 会同步到所有使用处
  @StorageLink('userToken') token: string = '';
  // 单向：只读 AppStorage，不允许反向写入
  @StorageProp('cartCount') count: number = 0;

  build() {
    Column() {
      Text(this.token)
      Button('登录').onClick(() => { this.token = 'abc'; })
    }
  }
}
```

### 4.2 PersistentStorage（持久化全局状态）

```ts
// AppStorage 初始化时同步到磁盘，重启后自动恢复
PersistentStorage.persistProp('userToken', '');
PersistentStorage.persistProp('cartCount', 0);

// 之后 AppStorage 的变化会自动持久化
AppStorage.set('userToken', 'xyz');
```

**限制**：
- 只能持久化**简单类型**（number、string、boolean、enum、对象/数组但必须是可序列化的简单结构）。
- **API 12 起被废弃**，推荐用 **V2 的 `@StorageLinkV2` + `AppStorageV2`** 或 `PersistentStorageV2`。

### 4.3 AppStorageV2 / PersistentStorageV2（V2 推荐）

```ts
// 初始化
PersistentStorageV2.persistProp('token', '', 'Token');

@Entry
@Component
struct Index {
  @StorageLinkV2('token') token: string = '';   // 双向
  @StoragePropV2('token') t2: string = '';      // 单向
}
```

### 4.4 LocalStorage（组件内部存储）

```ts
@Component
struct Comp {
  @Local count: number = 0;
  // 初始值来自 LocalStorage
  @LocalStorageLink('count') localCount: number = 0;   // 双向
  @LocalStorageProp('count') lpCount: number = 0;      // 单向

  build() { Text(`${this.count}-${this.localCount}`) }
}
```

> 与 `@State` 的区别：`@State` 的初值是硬编码的，`@LocalStorageLink` 的初值来自 LocalStorage，且两处共享同一份数据。

## 五、MVVM 架构实践（面试项目必备）

### 5.1 分层

```
View (UI 层)          Index.ets —— 只负责渲染与事件上报
   ↕ 数据绑定
ViewModel             TodoViewModel.ets —— 状态、逻辑、派生数据
   ↕ 数据访问
Model / Repository     TodoRepository.ets —— 数据源（网络/数据库/缓存）
```

### 5.2 完整示例

**Model**
```ts
export interface TodoItem {
  id: number;
  title: string;
  done: boolean;
}

export class TodoRepository {
  private cache: TodoItem[] = [];

  async fetch(): Promise<TodoItem[]> {
    // 实际项目：网络请求 + 数据库缓存
    return this.cache;
  }

  async save(item: TodoItem): Promise<void> {
    const idx = this.cache.findIndex(t => t.id === item.id);
    if (idx >= 0) {
      this.cache[idx] = item;
    } else {
      this.cache.push(item);
    }
  }
}
```

**ViewModel（V2 状态管理）**
```ts
import { TodoItem, TodoRepository } from './TodoRepository';

@ObservedV2
export class TodoViewModel {
  @Trace list: TodoItem[] = [];
  @Trace loading: boolean = false;
  @Trace keyword: string = '';

  private repo: TodoRepository = new TodoRepository();

  @Computed
  get filteredList(): TodoItem[] {
    if (!this.keyword) return this.list;
    return this.list.filter(i => i.title.includes(this.keyword));
  }

  async load(): Promise<void> {
    this.loading = true;
    try {
      this.list = await this.repo.fetch();
    } finally {
      this.loading = false;
    }
  }

  toggle(id: number): void {
    const item = this.list.find(i => i.id === id);
    if (item) {
      item.done = !item.done;
    }
  }
}
```

**View**
```ts
import { TodoViewModel, TodoItem } from './TodoViewModel';

@Entry
@Component
struct Index {
  @Local vm: TodoViewModel = new TodoViewModel();

  aboutToAppear(): void {
    this.vm.load();
  }

  build() {
    Column() {
      TextInput({ placeholder: '搜索' })
        .onChange((v: string) => { this.vm.keyword = v })

      if (this.vm.loading) {
        LoadingProgress()
      } else {
        List() {
          ForEach(this.vm.filteredList, (item: TodoItem) => {
            ListItem() {
              Row() {
                Checkbox()
                  .select(item.done)
                  .onChange((v: boolean) => {
                    this.vm.toggle(item.id);
                  })
                Text(item.title).decoration(
                  item.done ? { type: TextDecorationType.LineThrough } : {}
                )
              }
            }
          }, (item: TodoItem) => item.id)
        }
        .layoutWeight(1)
      }
    }
  }
}
```

> **架构要点**：ViewModel 用 `@ObservedV2` + `@Trace`，View 用 `@Local` 持有它 —— 这就是 V2 的"深度观察 + 派生计算"能力带来的好处，改 `vm.list` 内部任意属性，UI 都会更新。

## 六、状态管理常见坑（面试实操题）

| 坑 | 现象 | 原因 | 解决 |
|---|---|---|---|
| `@Prop` 传对象 | 嵌套属性不更新 | @Prop 只同步一层 | 改用 `@Observed`+`@ObjectLink`（V1）或 `@Param`+`@ObservedV2`+`@Trace`（V2） |
| `@Link` 写 `$` | 编译报错 | @Link 直接传变量 | 传 `this.xxx` |
| `@Consume` 找不到 Provide | 运行时崩溃 | key 不匹配 | 检查 key 一致、祖先链路完整 |
| V1/V2 混用 | 编译报错或状态不同步 | 同一链路混用 | 统一到一套 |
| @State 改普通变量 | UI 不刷新 | 普通变量无观察 | 用 @State/@Local |
| 数组 `push` 不刷新 | 部分场景 | 需确认是 @State 且未被 @Prop 复制 | 重新赋值 `this.list = [...]` |
| `@Monitor` 触发死循环 | 栈溢出 | 回调里改被监控状态 | 回调里不要改同名状态 |
| AppStorage 未初始化 | 取值 undefined | 未 setOrCreate | 在 Ability 的 onCreate 初始化 |

## 七、状态管理速记口诀

```
内部状态 → @State(V1) / @Local(V2)
父给子   → @Prop(V1) / @Param(V2)      子给父 → @Link(V1) / @Event(V2)
跨层     → @Provide+@Consume(V1) / @ProvideV2+@ConsumeV2(V2)
对象观察 → @Observed+@ObjectLink(V1) / @ObservedV2+@Trace(V2)
全局     → @StorageLink/@StorageProp(V1) / @StorageLinkV2(V2)
监听     → @Watch(V1) / @Monitor(V2)
计算     → getter(V1手写) / @Computed(V2)
```

## 九、参考答案要点

1. @State 组件内部状态；@Link 父子双向引用绑定；@Prop 父子单向值传递（只同步一层）；@Provide 祖先向下供给；@Consume 后代消费祖先数据；@ObjectLink 观察被 @Observed 标注的类实例的深层属性。
2. 不能。`@Link` 是引用传递，直接传 `this.value`；`$` 用于给"值传递的变量创建引用"（如 @Prop/普通变量传给 @Link 时才需要 `$`）。传 @Link 时父传的是 @State 本身，写 $ 会导致类型不匹配。
3. 不会。@Prop 传的是副本，且只同步一层。嵌套属性变化既不改副本，也不触发父重渲染，所以子看不到。需要 @Observed + @ObjectLink（V1）或 @Param + @ObservedV2 + @Trace（V2）。
4. 观察粒度不同：V1 是类级粗粒度（@Observed 类内所有属性自动可观察），V2 是属性级细粒度（只有标 @Trace 的属性被观察）；传递方式不同：V1 用 @ObjectLink（不能整体替换），V2 用 @Param（配合 @ObservedV2 实现深度观察）。
5. @Param 设计为单向，防止子组件破坏父的数据源。V2 用 @Event 事件回调让子通知父，由父修改状态（单向数据流）。
6. AppStorage 是应用内存级全局状态；PersistentStorage 是它的磁盘持久化版；LocalStorage 是组件内部、与 @State 关联的局部存储；Preferences 是轻量键值对持久化；RDB 是结构化关系型数据库。
7. 可监听多个属性、可监听对象属性的变化、支持分组回调（同一回调处理多个属性）。
8. 不能混用。同一属性上、同一数据链路上、@Provide 与 @ProvideV2 体系不能并存于同一链路。建议整项目统一到 V2。
9. 解决派生数据的手动同步问题——依赖的 @Trace 属性变化时自动重算，避免在多处重复写计算逻辑导致不一致。
10. V2 中 @Param 只允许父→子，@Event 负责子→父，数据源唯一在父组件；优势是数据流可预测、可追踪、易测试，避免双向绑定的隐式更新带来的调试困难。
