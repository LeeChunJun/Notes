## 2. `boot::Context` + `BaseManager` 机制

### 2.1 BaseManager

`mars/boot/base_manager.h:16-21`：

```cpp
class BaseManager {
 public:
    virtual ~BaseManager() {}
    virtual std::string GetName() = 0;   // 唯一约束：返回稳定唯一名
};
```

三个实现者都返回 `typeid(X).name()`：
- `mars::app::AppManager`（`app_manager.cc:33`）
- `mars::stn::StnManager`（`stn_manager.cc:60`）
- `mars::sdt::SdtManager`

### 2.2 Context

`mars/boot/context.h:22-99`。它是一个 **按名字索引的 Manager 注册表 + 全局 Context 池**。

```cpp
// 添加：key = mgr->GetName()
template <class T>
void AddManager(T* mgr);

// 取用：key = typeid(T).name()
template <class T>
T* GetManager();
```

> ⚠️ **坑**：`AddManager` 用 `GetName()` 做 key，`GetManager` 用 `typeid(T).name()` 做 key。
> 所以 `GetName()` 必须返回 `typeid(T).name()`，否则取不到。三大 Manager 都遵守了。

线程安全：`S_SCOPED_LOCK()` = `std::unique_lock<std::recursive_mutex>`（`context.h:17`）。

**全局惯例**：所有跨层 API 都走 `"default"` 这个 Context：

```cpp
AppManager* app_manager = Context::CreateContext("default")->GetManager<AppManager>();
```

出现在 `app_logic.cc`、`sdt_logic.cc`、`stn_logic.cc` 共 20+ 处。`CreateContext` 幂等（同名返回同一实例），零成本。

### 2.3 JNI 桥

`mars/boot/jni/context_wrapper.cc`：`JniCreateContext` / `JniAddManager` / `JniGetManager`（返回 `jlong` 裸指针 handle），注册到 `com/tencent/mars/app/Context`。

## 3. 信号总线（`baseevent`）

声明：`mars/baseevent/baseprjevent.h:25-36`
实现：`mars/baseevent/src/baseprjevent.cc:22-69`（每个函数返回函数内 `static boost::signals2::signal<...>`）

| 信号 | 签名 | 位置 |
|---|---|---|
| `GetSignalOnCreate()` | `signal<void()>` | `.h:25` |
| `GetSignalOnInitBeforeOnCreate()` | `signal<void(int encoder_version)>` | `.h:26` |
| `GetSignalOnInitBeforeOnCreateV2()` | `signal<void(int, std::string)>` | `.h:27` |
| `GetSignalOnDestroy()` | `signal<void()>` | `.h:29` |
| `GetSignalOnSingalCrash()` | `signal<void(int sig)>` | `.h:30` |
| `GetSignalOnExceptionCrash()` | `signal<void()>` | `.h:31` |
| `GetSignalOnForeground()` | `signal<void(bool isForeground)>` | `.h:32` |
| `GetSignalOnNetworkChange()` | `signal<void()>` | `.h:33` |
| `GetSignalOnNetworkDataChange()` | `signal<void(const char* tag, int64_t send, int64_t recv)>` | `.h:35` |
| `GetSignalOnAlarm()` | `signal<void(int64_t id)>` | `.h:36` |

**发射端**：`mars/baseevent/src/baseprj.cc`
- `OnCreate()` → `GetSignalOnCreate()()` (`:33`)
- `OnDestroy()` → `GetSignalOnDestroy()()` (`:45`)
- `OnForeground(bool)` → `GetSignalOnForeground()(_isforeground)` (`:57`)
- `OnNetworkChange()` (`:60-66`)
- `OnNetworkDataChange(tag, send, recv)` (`:68`)
- `OnAlarm(id)`（Android 专用，`:73`）

**订阅端与优先级**（boost::signals2 `connect(priority, slot)`，**数字越小越先执行**）：

| 订阅点 | 信号 | 优先级 | 位置 |
|---|---|---|---|
| `stn_logic.cc:222-236` | 全部 STN 信号 | OnDestroy=**1**（最低，最后跑）；OnNetworkChange=**5** | |
| `sdt_logic.cc:76-77` | OnCreate / OnDestroy | 默认 / **3** | |
| `baseevent/src/active_logic.cc:40` | OnForeground | 默认 | → `ActiveLogic::OnForeground` |
| `net_core.cc:1160-1243` | OnNetworkDataChange | 运行时 connect/disconnect | 流量统计 |

> **STN 的 OnDestroy 用优先级 1 是刻意设计**：保证 STN 的清理（断链、停线程）在 xlog/sdt 之后，避免日志线程先死导致日志丢失。

## 8. 一张图记住"谁调用谁"

```
Java  App
  │  StnLogic.startTask(task)
  ▼
JNI  Java2C
  │  → mars::stn::StartTask(task)  [stn_logic.cc:241]
  ▼
StnManager::StartTask  [stn_manager.cc:475]
  │  → net_core_->StartTask(task)
  ▼
NetCore::StartTask  [net_core.cc:326]           ← STN 线程
  ├─ __ValidAndInitDefault      参数校验/默认值填充
  ├─ __ChooseChannel            选通道 (long/short/minorlong)
  ├─ longlink_task_manager_->StartTask(task, kChannelLong)
  └─ shortlink_task_manager_->StartTask(task, kChannelShort)
        │
        ▼
LongLinkTaskManager::__RunLoop  [longlink_task_manager.cc:271]  ← 1s tick
  ├─ __RunOnTimeout             首包/包间/读写/总超时
  └─ __RunOnStartTask
        ├─ MakesureAuthed(host, user_id)        ← 鉴权门控
        ├─ Req2Buf(...)                          ← 业务编码（上层实现）
        ├─ AntiAvalanche::Check                 ← 雪崩防护
        ├─ longlink->Send(body, ext, task)       ← 打包 + 入发送队列
        └─ 发送队列 → LongLink 线程 writev
```

回程：

```
LongLink 线程 recv
  → longlink_unpack → cmdid, taskid(=seq), body
  → LongLinkTaskManager::__OnResponse
      ├─ longlink_ispush(taskid==0) ? → fun_on_push_ → Callback::OnPush
      └─ else → __Locate(taskid) → Buf2Resp → OnTaskEnd
```
