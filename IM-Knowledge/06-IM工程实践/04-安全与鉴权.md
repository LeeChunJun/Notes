# 04 · 安全与鉴权

---

## 1. 安全层次

```
┌───────────────────────────────────────────────────────┐
│ ⑤ 端到端加密（E2EE）                                   │
│    消息内容只有收发双方能解密（Signal/WhatsApp 模式）    │
│    ★ Mars 开源版不提供，需业务层实现                     │
├───────────────────────────────────────────────────────┤
│ ④ 业务层加密                                           │
│    在 Req2Buf/Buf2Resp 里加解密                          │
├───────────────────────────────────────────────────────┤
│ ③ 传输层加密（TLS）                                    │
│    LonglinkConfig::need_tls（默认 true）                │
│    ⚠️ 开源版 TLS 实现不完整，微信内部版才有完整实现       │
├───────────────────────────────────────────────────────┤
│ ② 协议层加密                                           │
│    ⚠️ 开源版没有（LongLinkEncoder 是扩展点）             │
├───────────────────────────────────────────────────────┤
│ ① 鉴权                                                 │
│    CMD_ID_AUTH 握手 + session_id + MakesureAuthed        │
└───────────────────────────────────────────────────────┘
```

## 2. 鉴权流程

### 2.1 握手

```
┌─────────┐                                    ┌─────────┐
│ Client  │                                    │ Server  │
└────┬────┘                                    └────┬────┘
     │ ① TCP/TLS 连接建立                            │
     │──────────────────────────────────────────────>│
     │                                                │
     │ ② CMD_ID_AUTH                                   │
     │   { token, device_id, device_type,              │
     │     client_version, app_version, push_token }   │
     │──────────────────────────────────────────────>│
     │                                                │ ③ 校验 token
     │                                                │    → 查 session / 校验签名
     │                                                │ ④ 建会话 session_id ↔ 连接 ↔ user
     │ ⑤ { session_id, server_time, push_token,       │
     │      config, err_code }                         │
     │<──────────────────────────────────────────────│
     │                                                │
     │ ⑥ 后续业务包都带 session_id                     │
     │──────────────────────────────────────────────>│
```

### 2.2 `MakesureAuthed` —— 本地门控

```cpp
// mars/stn/stn.h:469
virtual bool MakesureAuthed(const std::string& _host, const std::string& _user_id) = 0;
```

```cpp
// mars/stn/src/longlink_task_manager.cc:471-483
if (first->task.need_authed) {
    bool ismakesureauthsuccess = ...MakesureAuthed(host, first->task.user_id);
    if (!ismakesureauthsuccess) {
        first = next;   // ★ 留在队列，下一轮再来
        continue;
    }
}
```

**语义**：
- 返回 `true` → 任务可以发
- 返回 `false` → **任务留在队列，每秒轮询一次**（不会丢，也不会发）

> ★ **这是 Mars 提供的"鉴权同步点"**：
> 登录完成后调 `StnLogic.touchTasks()` 可以立即唤醒挂起的任务。

### 2.3 注意事项

| 事项 | 说明 |
|---|---|
| **Java 默认 `needAuthed = true`** | C++ 默认是 false，Java 默认是 true —— **从 Java 接入必须注意** |
| **`need_authed` 与 CMD_ID_AUTH 的关系** | `need_authed` 是**本地门控**（不发网络包）；`CMD_ID_AUTH` 是**真实的鉴权请求**（发网络包）。两者是不同层次 |
| **返回 false 不算错误** | 任务不会被判失败，不会触发 `OnTaskEnd` |

### 2.4 会话失效的处理

服务端返回"登录态失效"的错误码 → `Buf2Resp` 返回 `RESP_FAIL_HANDLE_SESSION_TIMEOUT(-13)`：

```cpp
// longlink_task_manager.cc:829-906
if (kTaskFailHandleSessionTimeout == _fail_handle || kTaskFailHandleRetryAllTasks == _fail_handle) {
    __Disconnect(_name, LongLinkErrCode::kDecodeErr);    // ★ 断链
    MessageQueue::CancelMessage(asyncreg_.Get(), longlink_id_[_name]);
    retry_interval_ = 0;                                  // ★ 立即允许重试
}
```

> **效果**：立即断链 → 重新连接 → 重新鉴权 → 重发任务。

## 3. Token 管理

### 3.1 Token 类型

| 类型 | 说明 | 安全性 |
|---|---|---|
| **长期 token**（refresh token） | 用户登录后下发，持久化 | 高（要加密存储） |
| **短期 token**（access token） | 有效期短（如 2 小时），用于握手 | 中 |
| **session_id** | 长连建立后由服务端下发 | 高（连接级） |

### 3.2 Android 存储

| 存储 | 加密 | 适用 |
|---|---|---|
| `SharedPreferences` | ✗ | 不敏感配置 |
| `EncryptedSharedPreferences` | ✓ | **token 推荐** |
| `KeyStore` | ✓ | 密钥本身 |
| 文件 + 自定义加密 | 视实现 | 谨慎 |

> **Android 9+ 禁止应用访问用户截图/剪贴板**，敏感信息不要放剪贴板。
> **不要用 `Log.d` 打 token。**

### 3.3 客户端实现

```java
@Override public boolean makesureAuthed(String host) {
    if (sessionManager.isValid()) return true;
    // 触发登录流程
    loginManager.startLogin();
    return false;
}
```

## 4. 传输安全

### 4.1 TLS

```cpp
// mars/stn/stn.h:210
bool need_tls;   // LonglinkConfig，默认 true
```

```cpp
// mars/stn/stn.h:226
std::string tls_group;   // ShortlinkConfig
```

> **开源版的 TLS 支持是不完整的** —— `need_tls` / `tls_group` 只是接口占位，
> 完整实现（证书校验、ALPN、pinning）在微信内部版。
>
> **如果你要做生产 IM，建议自己在 `LongLink` 里接 TLS**，
> 或者用 `LongLinkEncoder` 之外的方式（如自建 socket 层）。

### 4.2 证书校验

**必须做**：
- 校验证书链
- 校验域名（SAN）
- 建议做 **证书 pinning**（防中间人）

```java
// OkHttp 风格的 pinning 思路
Set<String> pinnedHashes = Set.of("sha256/AAAA...");
```

### 4.3 明文流量

> **开源版的 Mars 帧格式是明文的**（只有 20 字节头 + body，没有加密位）。
> **如果没有 TLS，消息内容在链路上是裸的。**
>
> **必须用 TLS，或者在业务层加密。**

## 5. 协议层扩展：加加密

`LongLinkEncoder`（`mars/stn/proto/longlink_packer.h:53-115`）是官方给的扩展点。

### 5.1 自定义帧格式

```cpp
struct SecureHeader {
    uint32_t magic;          // 0x4D415253 ("MARS")
    uint32_t version;        // 协议版本
    uint32_t flags;          // bit0: 加密; bit1: 压缩
    uint32_t cmdid;
    uint32_t seq;
    uint32_t body_length;
    uint8_t  iv[16];         // AES-CBC IV
};
```

### 5.2 挂载自定义编码器

```cpp
// 1. 复制默认编码器
LongLinkEncoder my_encoder = gDefaultLongLinkEncoder;

// 2. 替换 pack / unpack
my_encoder.longlink_pack = [](uint32_t cmdid, uint32_t seq,
                               const AutoBuffer& body, const AutoBuffer& ext,
                               AutoBuffer& packed, longlink_tracker* tracker) {
    // 自定义组帧 + 加密
};

// 3. 挂到长连配置
LonglinkConfig config("secure-longlink");
config.longlink_encoder = &my_encoder;
config.packer_encoder_version = PackerEncoderVersion::kNew;
CreateLonglink_ext(config);
```

> ⚠️ **注意**：改了帧格式，**服务端必须同步改**。
> **必须做灰度**：老客户端和新客户端的帧格式不同 → 服务端要同时支持两种。

### 5.3 加密实现建议

| 方案 | 说明 |
|---|---|
| **AES-256-GCM** | 推荐。带认证标签，防篡改 |
| **AES-256-CBC + HMAC** | 需注意 padding oracle |
| **ChaCha20-Poly1305** | 移动端性能好 |
| **会话密钥协商** | 用 ECDH 协商会话密钥，之后用对称加密 |

> **性能注意**：加密会显著消耗 CPU。
> 小消息（< 1KB）加密开销可接受；大消息应该走短连 + 业务层加密。

## 6. 端到端加密（E2EE）

**Mars 完全不提供**，必须业务层实现。

### 6.1 基本架构

```
发送方：明文消息 → 用会话密钥加密 → 放进 Envelope.payload → 走 STN
接收方：从 Envelope.payload 解密 → 明文消息
```

### 6.2 密钥管理

| 环节 | 方案 |
|---|---|
| 身份密钥 | 客户端生成，私钥存 KeyStore |
| 会话密钥 | ECDH 协商（每会话一组） |
| 密钥轮换 | 定期更换 / 成员变化时重新协商 |
| 密钥验证 | 指纹比对（扫码） |
| 群聊 | 发送者密钥 + 每个成员密钥（sender key 模式） |

### 6.3 关键约束

| 约束 | 原因 |
|---|---|
| **服务端不能看到明文** | E2EE 的定义 |
| **服务端无法做内容安全审核** | 需要额外的端侧举报机制 |
| **推送通知不带明文** | 只能推"你有新消息" |
| **多端同步需要密文透传** | 或每个端独立加密 |
| **密钥丢失 = 消息不可恢复** | 必须有密钥备份方案 |

> **面试话术**：
> "E2EE 的核心权衡是**安全性 vs 服务端能力**：
> 服务端失去了内容审核、搜索、优先级调度的能力。
> Signal 用'发送者密钥'模式解决了群聊的密钥分发，
> 但仍然需要客户端本地做举报和封禁同步。
> 我们的方案是**混合模式**：控制面消息（比如撤回、系统通知）走服务端明文，
> 用户内容走 E2EE。"

## 7. 其他安全措施

### 7.1 防重放

| 场景 | 对策 |
|---|---|
| 攻击者重放旧的鉴权包 | `session_id` + 时间戳 + nonce |
| 重放旧的业务包 | `msg_id` 去重（服务端）+ `client_seq` 递增 |
| 重放 ACK | ACK 里带 `server_seq` |

### 7.2 防篡改

- TLS 提供传输层完整性
- 业务层：AES-GCM 的认证标签，或在 body 里加 HMAC

### 7.3 防伪造（客户端身份）

| 手段 | 说明 |
|---|---|
| **设备指纹** | Android ID + 机型 + 系统版本 + 安装来源 |
| **长连身份校验（IdentifyChecker）** | ★ Mars 内建！`kCheckNow/kCheckNext/kCheckNever` |
| **token 绑定设备** | token 与 device_id 绑定 |

#### IdentifyChecker 详解

`mars/stn/src/longlink_identify_checker.cc`。

```
1. 客户端在上层生成"校验 buffer" + "hash buffer"，cmdid 由上层给定
2. 客户端发 cmdid=上层cmdid, seq=0xFFFFFFFE 的帧，body = 校验 buffer
3. 服务端回包 seq 必须回显 0xFFFFFFFE
   （longlink_identify_isresp 判 _sent_seq == _recv_seq && 0 != _sent_seq）
4. 客户端把回包 body 交给 OnLonglinkIdentifyResponse() 校验
```

| 模式 | 行为 |
|---|---|
| `kCheckNow` | 立刻校验 |
| `kCheckNext` | 下次心跳校验 |
| `kCheckNever` | 不校验（sample Android 的默认，`MarsServiceStub.java:188-193`） |

> ★ **校验包复用心跳通道，不多花 RTT** —— 这是 Mars 协议设计的一个亮点。

### 7.4 日志脱敏

| 字段 | 处理 |
|---|---|
| **消息内容** | ★ 绝对不能打进日志 |
| **token / password** | 掩码 |
| **手机号 / 用户 ID** | 部分掩码 |
| **push token** | 掩码 |
| **证书内容** | 不打 |

> sample 的 `NanoMarsTaskWrapper.java:47` 打了完整报文的 hex dump —— **生产必须移除**。

### 7.5 越权检查（服务端）

| 检查 | 说明 |
|---|---|
| **会话归属** | 收到的消息必须属于当前登录用户 |
| **群成员校验** | 发消息前校验是否还在群里 |
| **发送频率** | 单用户发送频率限制（防刷屏） |
| **内容大小** | 消息大小上限 |
| **设备数** | 同账号登录设备数上限 |
