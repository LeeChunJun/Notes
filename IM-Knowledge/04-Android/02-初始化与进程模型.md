## 1. Sample 的进程模型

`samples/android/marsSampleChat/wrapper/src/main/AndroidManifest.xml:9-17`：

```xml
<application>
    <service
        android:name=".service.MarsServiceNative"
        android:process=":marsservice" />
    <receiver
        android:name="com.tencent.mars.BaseEvent$ConnectionReceiver"
        android:process=":marsservice" />
</application>
```

> ★ **Mars 网络栈跑在 `:marsservice` 独立进程**，UI 进程通过 **AIDL** 通信。

### 1.1 为什么建议独立进程

| 优势 | 说明 |
|---|---|
| **UI 崩溃不影响长连接** | App UI 卡死/ANR 时，长连接还在，消息照样能收 |
| **UI 进程被杀不影响长连接** | 用户切后台被系统回收 UI 进程，长连接仍在（微信就是这么做的） |
| **降低内存压力** | 网络栈的 native 内存（openssl/boost/zstd）不占 UI 进程 |
| **避免主线程被 native 阻塞** | 长连接 I/O 完全在独立进程 |

### 1.2 代价

| 代价 | 说明 |
|---|---|
| **AIDL 序列化开销** | 每次请求要跨进程 marshal（Bundle + byte[]） |
| **进程间通信延迟** | ~几百微秒 |
| **复杂度** | 需要处理 Service 绑定/解绑/重连 |
| **日志要分文件** | 每个进程一份 xlog（sample 里按进程名区分） |

> **sample 的缺陷**：`MarsServiceProxy.onServiceDisconnected` **不重连**（`MarsServiceProxy.java:145-157` 有 TODO）。
> 真实实现必须处理 Service 被杀后的重绑定。

```java
    StnLogic.setShortlinkSvrAddr(profile.shortLinkPort());                         // :107 8080
    StnLogic.setClientVersion(profile.productID());                               // :108 200

    // ④ 启动

    StnLogic.makesureLongLinkConnected();  // :111  主动拉起长连

```

### 2.4 ★ 顺序为什么不能变

| 顺序 | 原因 |
|---|---|
| ① 回调注册 **在** `Mars.init()` 之前 | `Mars.init` 内部会触发平台初始化，可能立刻回调 |
| ② `Mars.init()` **在** `Mars.onCreate()` 之前 | `Mars.java:45-57` 明确抛 `IllegalStateException` |
| ③ 地址配置 **在** `Mars.onCreate()` 之前 | `BaseEvent.onCreate()` 会触发 STN 的 `OnCreate` → 创建 `NetCore` → 读配置 |
| ④ `makesureLongLinkConnected()` **在** `onCreate` 之后 | 此时 NetCore 已就绪 |

> **这是 Android 接入 Mars 最容易出错的地方**。
> 顺序错了要么崩溃，要么长连地址没生效（表现为"一直连不上"）。

## 3. 前后台切换

`samples/android/marsSampleChat/app/src/main/java/com/tencent/mars/sample/chat/ChatActivity.java:155-164`：

```java
@Override protected void onResume() {
    super.onResume();
    MarsServiceProxy.inst.setForeground(true);     // :156-159
}

@Override protected void onPause() {
    super.onPause();
    MarsServiceProxy.inst.setForeground(false);
}
```

`MarsServiceProxy.setForeground` 最终会调用 `BaseEvent.onForeground(isForeground)`
（native），触发 `ActiveLogic::OnForeground` → `LongLinkConnectMonitor::__OnSignalForeground`。

> **影响**：
> - 前台 1 分钟内 → 自动重连间隔 **30 秒**
> - 前台 > 10 分钟 → **300 秒**
> - 后台不活跃 → 阶梯退避，最长 **600 秒**
> - 后台 + 无账号 → **7 天**

**不调用 `onForeground` 的后果**：Mars 一直认为 App 不活跃 → 重连极慢（10 分钟起步）→ 用户感觉"消息收不到"。

## 4. 网络变化

`BaseEvent.ConnectionReceiver`（`BaseEvent.java:28-118`）注册在 `:marsservice` 进程：

```xml
<receiver
    android:name="com.tencent.mars.BaseEvent$ConnectionReceiver"
    android:process=":marsservice" />
```

它监听 `CONNECTIVITY_ACTION`，做 **Wi-Fi BSSID/SSID 级别**的"是否真的换网"判定：

```
收到 CONNECTIVITY_ACTION
  → 比对 Wi-Fi BSSID/SSID
     ├─ 相同 → 只是信号波动，不触发 onNetworkChange（避免假换网）
     └─ 不同 → 真正的换网 → BaseEvent.onNetworkChange()
```

`onNetworkChange` → `StnManager::OnNetworkChange` → `NetCore::OnNetworkChange`
→ 断链 + 立即重连 + 任务重排队。

> **IM 价值**：避免"Wi-Fi 信号抖动 → 误判换网 → 长连重建 → 消息延迟"的恶性循环。
> 这是真实线上问题打磨出来的逻辑。

## 5. AIDL 接口

`samples/android/marsSampleChat/wrapper/src/main/aidl/com/tencent/mars/sample/wrapper/remote/`：

### `MarsService.aidl`
```java
interface MarsService {
    void send(in MarsTaskWrapper taskWrapper, in Bundle properties);
    void cancel(in int taskID);
    void registerPushHandler(in MarsPushMessageFilter filter);
    void unregisterPushHandler(in MarsPushMessageFilter filter);
    void setAccountInfo(in String uin, in String userName);
}
```

### `MarsTaskWrapper.aidl`
```java
interface MarsTaskWrapper {
    Bundle getProperties();
    byte[] req2buf();
    int buf2resp(in byte[] buf);
    void onTaskEnd(in int errType, in int errCode);
}
```

### `MarsPushMessageFilter.aidl`
```java
interface MarsPushMessageFilter {
    void onRecv(in int cmdId, in byte[] data);
}
```

> **AIDL 的对象传递**：Binder 传的是**同一个对象的引用**（同进程内），
> 跨进程时才会真正序列化。所以 `MarsTaskWrapper` 的 `req2buf()`/`buf2resp()`
> 实际上是在**接收进程**（`:marsservice`）里执行的 —— 这是正确的，
> 因为 STN 在那个进程里。

## 9. Android 接入检查清单

### 9.1 初始化

- [ ] `System.loadLibrary("c++_shared")` → `"marsxlog"` → `"marsstn"`
- [ ] 多进程日志用**不同文件名**
- [ ] `AppLogic.setCallBack` / `StnLogic.setCallBack` / `SdtLogic.setCallBack` **在 `Mars.init()` 之前**
- [ ] `Mars.init(context, mainLooperHandler)` **在 `Mars.onCreate()` 之前**

- [ ] `Mars.onCreate(true)` 最后
- [ ] `StnLogic.makesureLongLinkConnected()` 在最后

### 9.2 生命周期

- [ ] `Activity.onResume/onPause` → `BaseEvent.onForeground(bool)`
- [ ] `BaseEvent.ConnectionReceiver` 已在 manifest 注册
- [ ] 退出登录时清理长连（`clearTask()` + `reset()`）

### 9.3 回调

- [ ] `makesureAuthed` 返回**真实的**登录态（Java 默认 `needAuthed = true`）
- [ ] `isLogoned()` 与 `getAccountInfo()` 一致
- [ ] `getClientVersion()` 与服务端一致
- [ ] `getAppFilePath()` 返回可写目录
- [ ] `req2Buf`/`buf2Resp` 不阻塞

- [ ] 网络栈放独立进程（推荐）
- [ ] `onServiceDisconnected` **要重连**（sample 没做）

## 10. 常见 Android 问题速查

| 症状 | 原因 | 处理 |
|---|---|---|
| `IllegalStateException: function MarsCore.init must be executed before Mars.onCreate` | 顺序错了 | `init` 在前 |
| 长连一直连不上 | `setClientVersion` 与服务端不一致 | 三端对齐 |
| 长连连上就断 | `client_version` 不匹配 → 解包失败断链 | 同上 |
| 消息一直发不出去 | `makesureAuthed` 返回 false（Java 默认 `needAuthed=true`） | 返回真实登录态 |
| 后台收不到消息 | 没调 `onForeground(false)` | 补上 |
| 重连特别慢（10 分钟） | `getAccountInfo().username` 为空 + 不活跃 → 7 天 | 补上账号信息 |
| 智能心跳不生效 | `getAppFilePath()` 不可写 | 返回可写目录 |
| 日志丢失/错乱 | 多进程写同一文件 | 按进程名区分 |
| Service 死了不恢复 | `onServiceDisconnected` 没重连 | 补上 |
| `task no found` 日志多 | 正常现象（响应迟到） | 频繁出现才需查首包超时 |
