# 06 · 线程模型与消息队列

## 1. 为什么需要 MessageQueue

Mars 的网络层要面对的核心矛盾：

> **回调可能来自任意线程**（网络 IO 线程、信号线程、系统回调），但 **STN 的内部状态是单线程串行访问的**。

`MessageQueue` 就是 Mars 的答案：
**一个"把函数投递到指定线程执行"的通用异步原语**。

它承担三种职责：
1. **线程切换**：把回调搬到目标线程
2. **定时执行**：`kAfter` / `kPeriod`
3. **去重/合并**：`SingletonMessage` / `FasterMessage`

## 3. `RunLoop::Run()` —— 消息泵

`mars/comm/messagequeue/message_queue.cc:910-1033`：

```cpp
void RunLoop::Run() {
    MessageQueue_t id = CurrentThreadMessageQueue();
    while (true) {
        // ① 清空"正在执行"状态，唤醒所有 WaitForRunningLockEnd 等待者
        content.lst_runloop_info.back().runing_message_id = KNullPost;
        content.lst_runloop_info.back().runing_message = NULL;
        content.lst_runloop_info.back().runing_cond->notifyAll(lock);

        // ② duty_func_：每次循环的可选钩子
        if (duty_func_) duty_func_();

        // ③ 退出条件
        if (content.breakflag || (breaker_func_ && breaker_func_())) { pop; break; }

        // ④ 扫描消息列表，找一条"到期"的消息
        wait_time = 10 * 60 * 1000;   // 最长等 10 分钟
        for (it : lst_message) {
            if (kImmediately)              { take; break; }
            else if (kAfter)   { if (after <= elapsed) { take; break; }
                                  else wait_time = min(wait_time, after - elapsed); }
            else if (kPeriod)  { /* kAfter ↔ kPeriod 状态机切换 */ }
        }

        // ⑤ 无到期消息 → 条件变量等待
        if (NULL == messagewrapper) { content.breaker->Wait(lock, wait_time); continue; }

        // ⑥ 匹配 handler（精确匹配 or broadcast）
        for (h : lst_handler)
            if (postid.reg == h->reg || (h->recvbroadcast && postid.reg.isbroadcast()))
                fit_handler.push_back(*h);

        // ⑦ ★ 解锁执行 —— 执行期间不持锁
        lock.unlock();
        messagewrapper->message.execute_time = gettickcount();
        for (h : fit_handler) {
            SCOPE_ANR_AUTO((int)anr_timeout, kMQCallANRId, &h.reg);   // ANR 监控
            uint64_t t0 = clock_app_monotonic();
            h.handler(messagewrapper->message.postid, messagewrapper->message);
            uint64_t t1 = clock_app_monotonic();
            ASSERT2(0 >= anr_timeout || anr_timeout >= (int64_t)(t1 - t0), ...);  // ANR 断言
        }
        if (delmessage) delete messagewrapper;
    }
}
```

### 关键设计点

| 点 | 说明 |
|---|---|
| **执行时不持锁** | `lock.unlock()` 在 handler 执行前 —— 避免 handler 里再投递消息时死锁 |
| **支持嵌套 runloop** | `lst_runloop_info` 是一个栈；同队列内 `WaitMessage` 会嵌套执行 RunLoop（`.cc:591-599`） |
| **ANR 监控** | `SCOPE_ANR_AUTO` + `anr_timeout`（默认 10 分钟），Android 上接 `comm/anr.cc` |
| **MAX_MQ_SIZE = 5000** | 超限触发 `_MQMaxSizeCallback`（`.cc:374-389`）：dump 50 条消息 + `ASSERT2` + 可选外部回调 `g_mq_max_size_callback`（`.cc:50`） |

### 5.1 `AsyncResult<R>`

`message_queue.h:430-694`：把"异步执行 + 取结果"包装成一个可调用对象，
支持 `R`、`void`、`R&`、`const R&` 四种特化。

```cpp
AsyncResult<int> ar(func, handler);
int r = ar.WaitInvoke();      // :696-742
```

**语义**（`.cc:591-599`）：
- 同队列时**直接执行**（不 post，避免死锁）
- 跨队列时 post + `WaitMessage` 阻塞等待

> **IM 用途**：业务线程想知道"某个 STN 操作的最终结果"时用它。
> 但**不要在 STN 线程里用 `WaitInvoke` 调用会回到 STN 线程的函数**（会嵌套 runloop，风险高）。

## 8. `FasterMessage` 的去重算法详解

`message_queue.cc:502-534`：

```
FasterMessage(handler, msg, timing):
  1. 计算新消息的 wait_time = __ComputerWaitTime(msg)
  2. 在队列里找同 handler + 同 message 的已有消息
  3. 如果找到：
       比较两者的 wait_time
       保留 wait_time 更小的（"更快到期"的），删掉另一个
  4. 否则：正常入队
```

`__ComputerWaitTime`（`.cc:481-500`）计算每条消息的"还需等待多久"。

> **STN 的用法**：`__RunLoop` 是 1 秒节拍。
> 多个地方（网络变化、任务下发、前后台切换）都可能触发一次调度，
> `FasterMessage` 保证队列里**只有一个**待执行的 `__RunLoop`，
> 且下次执行时间取所有触发源中最早的那个。
>
> **效果**：**天然去重 + 天然"就近执行"**，避免 1 秒节拍被拖成多秒。

## 10. IM 实践要点

### 10.1 绝对不要在 `Req2Buf`/`Buf2Resp` 里阻塞

因为它们跑在 **[3] STN 线程**。阻塞 = 所有 IM 消息卡住。

```java
// ❌ 错误示范
@Override public byte[] req2buf() {
    Bitmap bmp = loadBitmapFromDisk();   // 磁盘 IO！
    return compress(bmp);                // CPU 密集！
}

// ✅ 正确示范
// 1. 在业务线程提前准备好字节数组
// 2. req2buf 只是返回引用
@Override public byte[] req2buf() {
    return preEncodedBytes;              // 纯内存操作
}
```

### 10.2 UI 更新必须切回主线程

sample 的做法（`samples/android/marsSampleChat/app/.../chat/TextMessageTask.java:76-82`）：

```java
@Override public void onTaskEnd(int errType, int errCode) {
    if (callback == null) callback = onError;
    uiHandler.post(callback);        // uiHandler = new Handler(Looper.getMainLooper())
}
```

> ⚠️ **sample 里的一个真实 bug**：`callback` 字段在 `onPostDecode`（STN 线程）和
> `onTaskEnd`（STN 线程）之间共享，**没有 volatile**。
> 虽然两个回调都在 STN 线程，所以实际不会跨线程问题 ——
> 但如果业务把 `onPostDecode` 挪到别的线程，就会有可见性问题。

### 10.3 用 `ScopeRegister` 思想管理订阅

Java 侧对应的是"注册/反注册配对"。sample 里 `MarsServiceProxy` 有
`onServiceConnected` / `onServiceDisconnected` 配对，但**断连后不重连**
（`MarsServiceProxy.java:145-157` 有 TODO）。这是 sample 的缺陷，不是 Mars 的。

### 10.4 消息队列积压的监控

`MAX_MQ_SIZE = 5000`。超过会 dump 消息 + ASSERT。
在 IM 里，如果 STN 队列积压，通常意味着：
- `Req2Buf` 太慢
- 短连阻塞在 STN 线程（不应该）
- 单个 handler 消息太多

**监控指标建议**：STN 队列长度、`__RunLoop` 实际执行间隔 vs 预期 1000ms。
