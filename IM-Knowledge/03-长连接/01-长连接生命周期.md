## 1. 状态机

`mars/stn/src/longlink.h:77-83`：

```cpp
enum TLongLinkStatus {
    kConnectIdle = 0,      // 空闲，尚未启动
    kConnecting = 1,       // 正在建连（DNS + TCP handshake）
    kConnected,            // 已连接
    kDisConnected,         // 连接建立后断开（读写错误/远端关闭）
    kConnectFailed,        // 建连失败
};
```

状态迁移全部通过 `LongLink::__ConnectStatus()`（`longlink.cc:457-466`）：

```cpp
void LongLink::__ConnectStatus(TLongLinkStatus _status) {
    if (_status == connectstatus_)
        return;
    xinfo2(TSF "connect status from:%0 to:%1, nettype:%_", connectstatus_, _status, ::getNetInfo());
    connectstatus_ = _status;
    __NotifySmartHeartbeatConnectStatus(connectstatus_);          // → SmartHeartbeat
    if (kConnected == connectstatus_ && fun_network_report_)
        fun_network_report_(__LINE__, kEctOK, 0, conn_profile_.ip, conn_profile_.port);
    STATIC_RETURN_SYNC2ASYNC_FUNC(boost::bind(boost::ref(SignalConnection), connectstatus_, config_.name));
}
```

**状态图**：

```
    kConnectIdle (0)
         │  MakeSureConnected()
         ▼
    kConnecting (1) ──────────────┐
         │  connect 成功            │ connect 失败
         ▼                         ▼
    kConnected (2)            kConnectFailed (4)
         │  读写错误/远端关闭       │
         ▼                         │
    kDisConnected (3) ────────────┘
         │  重连决策
         └────→ (再次 MakeSureConnected)
```

> ⚠️ **注意**：`__ConnectStatus` 内使用了 `RETURN_SYNC2ASYNC_FUNC`，
> 即**状态变更信号是异步投递到 STN 线程的**，而 `connectstatus_` 本身是同步改写的。
> 这保证了监听者（`LongLinkConnectMonitor`、`LongLinkTaskManager`）不会在 I/O 线程上被同步阻塞。

## 3. 完整生命周期

### 3.1 `MakeSureConnected()` —— 启动长连

`longlink.cc:277-313`：

```cpp
bool LongLink::MakeSureConnected(bool* _newone) {
    if (IsSvrTrigOff()) { xwarn2(TSF "make connected but svr trig off"); svr_trig_off_ = false; }
    if (_newone) *_newone = false;
    ScopedLock lock(mutex_);

    if (kConnected == ConnectStatus())
        return true;
    if (LongLinkErrCode::kObjectDestruct == disconnectinternalcode_) {
        xwarn2(TSF "object has been released");
        return false;
    }

    bool newone = false;
    thread_.start(&newone);          // ★ spawn "::lonklink" 线程

    if (newone) { // ★ 新建线程时做一次状态复位
        connectstatus_ = kConnectIdle;
        conn_profile_.Reset();
        conn_profile_.link_type = config_.link_type;
        identifychecker_.Reset();
        disconnectinternalcode_ = LongLinkErrCode::kNone;
        readwritebreak_.Clear();
        connectbreak_.Clear();
        lstsenddata_.clear();
    }
    if (_newone) *_newone = newone;
    return false;
}
```

**`thread_.start(&newone)` 的语义**（`mars/comm/unix/thread/thread.h:179-208`）：
- 线程已在运行 → 直接返回，`*_newone = false`
- 否则 `pthread_create`，`*_newone = true`

> **这保证了"同一条长连接同时只有一个连接线程"** —— 幂等的启动。

### 3.2 `__Run()` —— I/O 线程主体

`longlink.cc:495-576`：

```cpp
void LongLink::__Run() {
    { ScopedLock lock(mutex_); tracker_.reset(longlink_tracker::Create()); }   // 协议层 tracker
    uint64_t cur_time = gettickcount();
    ...
    ConnectProfile conn_profile;
    conn_profile.start_time = cur_time;
    conn_profile.conn_reason = conn_profile_.disconn_errcode;   // 上次断开的原因
    getCurrNetLabel(conn_profile.net_type);
    conn_profile.tid = xlogger_tid();
    __UpdateProfile(conn_profile);

    SOCKET sock = __RunConnect(conn_profile);       // ① 建连
    if (INVALID_SOCKET == sock) {
        conn_profile.disconn_time = ::gettickcount();
        conn_profile.disconn_signal = ::getSignal(::getNetInfo() == kWifi);
        __UpdateProfile(conn_profile);
        ScopedLock lock(mutex_);
        tracker_.reset();
        return;                                     // ← 这里不会再设 kDisConnected
    }

    ErrCmdType errtype = kEctOK;
    int errcode = 0;
    __RunReadWrite(sock, errtype, errcode, conn_profile);   // ② 读写循环
    socket_close(sock);

    conn_profile.disconn_time = ::gettickcount();
    conn_profile.disconn_errtype = errtype;
    conn_profile.disconn_errcode = errcode;
    conn_profile.disconn_signal = ::getSignal(::getNetInfo() == kWifi);

    ScopedLock lock(mutex_);
    __ConnectStatus(kDisConnected);                 // ③ 断开
    __UpdateProfile(conn_profile);

    if (kEctOK != errtype)
        __RunResponseError(errtype, errcode, conn_profile);   // ④ 通知上层
}
```

> **关键**：`__Run()` **跑完就退出，线程不常驻**。
> 重连完全由 `LongLinkConnectMonitor` 的 alarm 驱动，再次调用 `MakeSureConnected()` 重新拉起线程。
>
> **这是 Mars 长连接的一个重要架构特点**：
> **一条长连接 = 一个"连接 + 读写 + 断开"的完整生命周期事件，而不是一个常驻对象。**
> 好处：状态干净、无残留、易于重连；坏处：重连有线程创建开销。

### 3.5 TCP_NODELAY

`longlink.cc:753-757`：

```cpp

```

实现（`mars/comm/socket/unix_socket.cc:354-356`）：

```cpp
int socket_disable_nagle(int sock, int nagle) {
    return setsockopt(sock, IPPROTO_TCP, TCP_NODELAY, (char*)&nagle, sizeof(nagle));
}
```

> **IM 价值**：禁用 Nagle 算法 → 小消息**立即发出去**，不等待攒够 MSS。

## 4. `Disconnect()` —— 主动断开

`longlink.cc:315-342`：

```cpp
void LongLink::Disconnect(LongLinkErrCode::TDisconnectInternalCode _scene) {
    xinfo2(TSF "_scene:%_", _scene);
    ScopedLock lock(mutex_);
    if (!thread_.isruning()) return;

    disconnectinternalcode_ = _scene;

    bool recreate = false;
    if (!readwritebreak_.Break() || !connectbreak_.Break()) {
        xassert2(false, "breaker fail");
        connectbreak_.Close();
        readwritebreak_.Close();
        recreate = true;
    }
    lock.unlock();

    dns_util_.Cancel();     // 取消进行中的 DNS 查询
    thread_.join();         // 等 I/O 线程退出

    if (recreate) {
        connectbreak_.ReCreate();
        readwritebreak_.ReCreate();
    }
}
```

**两个 `SocketBreaker`**：
- `connectbreak_`：打断正在进行的 connect
- `readwritebreak_`：打断正在进行的 select

`SocketBreaker`（`mars/comm/unix/socket/socketbreaker.h:28-58`）基于 **pipe**：
`Break()` 往 pipe 写一个字节，`SocketSelect` 把 pipe 读端加入 fdset，
`select` 立即返回且 `IsBreak() == true`。

> **这是 Mars 打断阻塞 I/O 的标准手法**，也是 C++ 里"打断阻塞系统调用"的经典实现。

## 6. `svr_trig_off_` —— 服务端关闭后不自动重建

`longlink.h:172-178`：

```cpp
void SvrTrigOff() { svr_trig_off_ = false; }
bool IsSvrTrigOff() {
    return false;  // 暂时不用这个功能
                   //        return config_.link_type == Task::kChannelMinorLong && svr_trig_off_;
}
```

**该特性在当前版本被硬编码关闭**（`return false`）。

后果：
- `svr_trig_off_` 仍会在 `recv == 0` 时置 true（`longlink.cc:1005`）
- 但 `IsSvrTrigOff()` 恒为 false
- `LongLinkConnectMonitor` 的 5 处 `if (longlink_.IsSvrTrigOff()) return;`
  （`longlink_connect_monitor.cc:230, 268, 375, 408, 424`）**永远不会生效**
- **结论：当前版本服务端关闭后一定会走自动重连流程**

`SvrTrigOff()` 会在两处被调用以清除标记：
- `LongLinkTaskManager::__RunOnStartTask`（`longlink_task_manager.cc:534`）
- `RedoTasks`（`longlink_task_manager.cc:203`）

> **设计意图理解**：
> 副长连（MinorLong）是"某租户专属"的连接。
> 服务端主动关闭它，意味着"这个租户被踢了/连接已迁移"，
> 不应该自动重连（否则会和服务端的关闭意图打架），而应等服务端再触发。
> 开源版把这个逻辑注释掉了，说明**开源场景不需要**这个区分。

```cpp
    conn_profile_.start_read_packet_time = 0;
    conn_profile_.start_connect_time = 0;
    readwritebreak_.Break();      // ★ 唤醒 select，立刻去写
    return true;
}
```

- `lstsenddata_` 是 `std::list<std::pair<Task, move_wrapper<AutoBuffer>>>`（`longlink.h:232`）
  —— 元素是 (Task, 打包后的字节流)
- `readwritebreak_.Break()` 打断 select，使写事件立刻被处理 → **发送延迟极低**

### 7.2 `SendWhenNoData`

`longlink.cc:232-255`：要求 `lstsenddata_` 为空才发，且 `task.send_only = true`。
用于心跳包、TCP 路径信令包。

### 7.3 `Stop`

`longlink.cc:264-275`：只删除**尚未开始写**（`Pos() == 0`）的任务。

## 8. `ConnectProfile` —— 连接画像

记录在 `conn_profile_` 里，随连接上报：

| 字段 | 含义 |
|---|---|
| `start_time` | 开始 |
| `dns_time` | DNS 查询时间（**重连间隔计算用它**：`posttime = gettickcount() - dns_time`） |
| `conn_time` | 连接成功时间 |
| `conn_rtt` | 建连 RTT |
| `conn_cost` | 建连总耗时 |
| `conn_errcode` | 建连错误码 |
| `tryip_count` | 试了几个 IP |
| `ip_index` | 命中的 IP 在列表中的下标（**>0 说明首选 IP 不通 → 弱网信号**） |
| `host` / `ip` / `port` | 目标 |
| `ip_type` | IP 来源（Debug/DNS/NewDNS/Proxy/Backup） |
| `local_ip` / `local_port` | 本地地址 |
| `disconn_time` / `disconn_errtype` / `disconn_errcode` / `disconn_signal` | 断开信息 |
| `net_type` | 网络类型 |
| `link_type` | 通道类型 |

> **IM 价值**：`ip_index > 0` 是**判定弱网的重要信号**——
> 说明首选 IP（通常是上次连成功的那个）这次连不通了。
> `WeakNetworkLogic` 就用这个。

## 9. 长连接相关的关键结论

| 问题 | 答案 |
|---|---|
| 长连接线程常驻吗？ | **不常驻**。`__Run()` 跑完就退出，重连时重新创建 |
| 一次连接的生命周期有多长？ | 从 `MakeSureConnected` 到 `__Run` 返回 |
| 断开后谁来重连？ | `LongLinkConnectMonitor`（STN 线程）通过 alarm 驱动 |
| 在途任务会丢吗？ | **不会**，批量失败后按 `retry_count` 重试 |
| 服务端主动关闭会怎样？ | `recv==0` → `kEctSocketShutdown(-10090)` → 批量失败 → 退避重连 |
| 心跳超时会怎样？ | **直接断链**（`kEctSocketRecvErr(-10091)`）→ 走重连流程 |
| 长连支持多路复用吗？ | **不支持**。一个 cmdid 一个响应，靠 taskid 区分 |
| 副长连是什么？ | 为特定 host 单独建立的长连接，`link_type = kChannelMinorLong` |
