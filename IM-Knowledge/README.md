## 一、这个知识库解决什么问题

Mars 的 STN（Short Task Network）就是微信团队打磨多年的 **IM 长连接网络框架**。
它不是一个"示例项目"，而是一套生产级的信令通道中间件：

- 微信的**长连接（信令通道）**、**短连接（HTTP CGI）**、**消息推送**、**心跳保活**、**弱网容灾** 全部构建在它之上。
- `samples/android/marsSampleChat` 是官方给出的 Android IM Demo，完整实现了"发消息 → 上行 → 服务端广播 → 下行 push → UI 更新"。

本知识库把 100% 开源代码拆成 **9 个可独立检索的知识域**，每个文档都标注了 `file:line`，可以直接跳回源码验证。

## 四、10 个必须记住的数字

| 数字 | 含义 | 出处 |
|---|---|---|
| **20 字节** | Mars 长连帧固定头 `__STNetMsgXpHeader`（5 × uint32，network byte order） | `mars/stn/proto/longlink_packer.cc:36-44` |
| **20** | `client_version`，客户端与服务端必须一致，否则直接解包失败断链 | `longlink_packer.cc:76-80` / `samples/Server/.../NetMsgHeader.java:39` |
| **6** | `NOOP_CMDID`，长连接心跳 ping/pong 的 cmdid | `longlink_packer.cc:96` |
| **243** | `SIGNALKEEP_CMDID`，UDP 信令保活 cmdid | `longlink_packer.cc:97` |
| **0** | `PUSH_DATA_TASKID`，服务端主动 push 的 seq 约定 | `longlink_packer.cc:98,175-177` |
| **3.5 min** | `MinHeartInterval` 最小心跳间隔（210s） | `mars/stn/config.h:34` |
| **10 min** | `MaxHeartInterval` 最大心跳间隔（600s） | `mars/stn/config.h:35` |
| **10s / 2.5s / 3** | 长连建连：单次超时 / IP 间隔 / 最大并发连接数 | `mars/stn/config.h:102-104` |

| **1 MiB** | 单帧最大长度，超过即协议错误断链 | `longlink_packer.cc:86-88` |

## 五、必须知道的 5 个"坑"

1. **开源版 ≠ 微信内部版**。开源 Mars 没有 magic 头、没有加密位、没有压缩协商，也没有 `cmdInnerPing/cmdAuth` 那一套 cmdid。
   这些是微信内网 STNetMsgXp 的东西。详见 `附录/03-术语中英对照.md` 与 `07-面试准备/03-源码追问与勘误.md`。
2. **线上 `seq` 就是 Mars 的 `taskid`**。回包靠 taskid 在任务表里 `find_if` 精确匹配，**不要求顺序**；匹配不上就 warn 后静默丢弃。
3. **短连接没有 Mars 私有头**，就是标准 HTTP/1.1 POST；**响应与 task 的绑定靠 TCP 连接对象本身**，线上没有关联键。
4. **心跳超时 = 断链**。noop ping 8 秒（active 5 秒）不回就判定链路已死，直接 `goto End` 关闭长连。
5. **`Task::need_authed` 是本地门控，不产生网络包**。`Callback::MakesureAuthed()` 返回 false 时任务留在队列里等，不会发出去。
